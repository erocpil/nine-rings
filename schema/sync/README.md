# 同步协议契约与候选向量

更新于 2026-10-15，涵盖 I1a～I1d 编码、往返、固定修订预检与发布恢复基础。这些是未来同步封装的实现基础，**不是已经开启的新备份格式**。顶层备份 version 1/2、应用版本、数据库版本、未来 header.format 和 header.codec 互相独立。

## 当前客户端能力

Web/Tauri/Flutter 继续读写原有无 header 导出。当前发布路径不生成新 header；CURRENT_SYNC_CAPABILITIES 的 formats/codecs 为空、read/write 为 0，不能因编解码器已存在就宣称存储往返无损。任何保留字段 header（包括 null 或未知形状）均在应用数据前拒绝。TS 的本地导出 Push 检查也在首个写请求之前执行；Flutter 同样拒绝带头的本地导出和远端 Pull，Rust 原生 import_data 在固定模型反序列化及数据库/配置操作之前检查。

该拒绝机制不等于完整切换控制：当前旧协议 Push 仍以已知 latest 版本预检，不保证每次都读取同版本远端快照；显式协议预检现已提供控制文件、固定修订父链和设备开启事实检查，但尚未强制替换每次旧格式同步的所有读取步骤。旧二进制更不会获得新检查。全部参与设备升级、空间控制状态、固定修订预检与正式启用仍是后续门禁，不能据本批开启新协议。

| 读取/往返能力 | Web/PWA | Tauri（各桌面共用入口） | Flutter |
| --- | --- | --- | --- |
| 原有无头备份 | version 1/2 | version 1/2 | 原有 version 1；加密新版拒绝 |
| 有头新封装应用 | 拒绝 | TS 与原生 IPC 都拒绝 | Pull 与本机导入拒绝 |
| 带头本机导出 Push | 首次远端写入前拒绝 | 共用 TS 拒绝 | 首次远端写入前拒绝 |
| 任意未知元数据存储往返 | 文档/模板样本保留，顶层样本丢失，不认证全量无损 | 正文扩展保留，记录/模板/顶层样本丢失 | 固定模型丢弃记录扩展；SQLite 模型往返测试已在 CI/本机通过，仍不认证全量扩展 |
| 候选 codec 1 | TS 实现、冻结向量通过 | 共用 TS，不另引入 Rust 编码器 | 候选 Dart 同向量测试已在 CI 和本机通过；不等于存储认证 |

正文扩展与顶层/记录元数据是不同边界，不能因 content 保留 JSON 就认定全量往返无损；也不把上述实现层检查等同于 Windows/Linux 真机验证。

## 候选封装

| header 字段 | 契约 |
| --- | --- |
| kind | nine-rings.sync-snapshot |
| format / codec | 正安全整数；须分别被客户端支持 |
| id | 1～128 个 ASCII 字符，首字符为字母/数字，其余允许字母/数字/点/下划线/连字符，禁止路径分隔符；远端读取须与 latest 相等 |
| requires.read / write | 独立的正安全整数；写入还必须满足读取能力 |
| requires.readFeatures / writeFeatures | 独立的非空特性名数组，不重复；未知必需特性不能忽略 |
| parent | null 或包含相同规则的 id 与 64 位小写十六进制 sha256 的对象；形状正确不代表已核验父链 |
| createdAt | 带时区的 ISO 日期时间，秒必填，小数秒可为 1～9 位，校验实际日历与小时范围；不是规范化正文的依据 |
| writtenBy | 非空 app/platform/deviceId，作为诊断信息，不作为可信签名 |

评估器不删未知字段、不降低远端要求，也不解密内容。requireHeader 为真时禁止缺头降级；默认接受无头仅为兼容导入，不能用来证明远端尚未切换。格式、codec、等级和必需特性都要匹配，identity 不匹配先拒绝。不涉及正文摘要校验、发布或本机基线确认。

## 候选 codec 1

`src/lib/sync/canonical-codec.ts` 接受已经解析的 JSON 值，生成紧凑 JSON 文本：

- 对象键按原始 UTF-16 code unit 顺序排序，包括数字形状键，不能用 localeCompare；实现手动写对象，避免 JSON.stringify 对整数键重排。
- 数组保持原顺序，字符串保持 Unicode、NFC/NFD、换行与密文字节表达；不提取/解密资源。孤立 UTF-16 代理项由 JSON.stringify 写为反斜线 u 转义，之后编码 UTF-8，不变成替换字符。
- 数字采用有限 IEEE-754 值的 ECMAScript JSON 最短表示；负零为 0，整数必须处于 JS 安全范围。精度定义为已解析的 IEEE-754 值，不保证任意精度十进制原始 token 的还原。非 JS 实现必须通过相同向量，不直接假定其默认浮点格式等价。
- 拒绝 NaN/Infinity、不安全整数、undefined、BigInt、稀疏/附加属性数组、循环、访问器、符号及非普通 JSON 对象；嵌套最多 100 层。
- 摘要为上述文本 UTF-8 的 SHA-256、小写十六进制。未知字段和时间戳仍参与摘要；不对整个动态导出做“每次必相同”的承诺。它不是最终实体语义投影，也不是现有 Git Blob SHA-1，更不是由对象推导出的原始快照文件字节摘要。

本批不替换现有合并算法中的兼容字段规范化，也不改变正文、源代码或密文。未来实体投影需要显式处理 snake/camel 别名、字符串 JSON 字段、导出元信息、派生搜索文本、模板/设置与保护域，不能直接哈希不同端导出的对象就宣称语义相同。

`strict-json.ts` 与候选 Dart 解析器在新协议原始输入层拒绝重复键（含转义后相同的键）、非有限数字、不安全整数、非法 JSON 空白/语法和超过 100 层嵌套。分数定义仍为解析后的 IEEE-754 值，不宣称保留任意精度原始十进制 token；孤立代理项保留后转义。严格解析器用于显式远端协议预检，尚未替换旧导入解析器，不改变旧格式普通导入的兼容行为。

`envelope-candidate-v1.schema.json` 固定必需字段、类型、等级范围、身份与摘要表达，并允许未知扩展字段原样保留；未知必需特性仍由能力评估器拒绝。Schema 不代替运行时的日历、UTF-16 长度和身份匹配检查，也不表示未知字段已经能存储。这里不使用会删除属性的 validator 选项。

## 共享样本与验收

- fixtures/canonical-v1.json：冻结输入、规范文本及 SHA-256，包含键序、数字形状键、Unicode、换行、数组、未知数据、密文、小数与孤立代理项；新增 139 个有限浮点值（含固定伪随机位模式、次正规数及指数阈值）。TS 实现已通过；Dart 采用显式 UTF-16 键序/字符串转义及数字表示布局，运行测试已在 CI 与本机通过。不能仅凭格式化通过就认证跨端哈希。
- fixtures/legacy-gates.json：当前客户端的无头允许/有头拒绝样本，TS、Rust 和 Flutter 测试共用。Flutter 运行由 CI 完成，本机不为此安装 Flutter。
- fixtures/strict-json-v1.json：TS/Dart 共用的原始输入接受/拒绝样本；TS/Dart 在共享样本中均已通过。
- fixtures/storage-roundtrip.json：实际 IDB 和 Rust SQLite 导入、改名、再导出；Flutter 同时覆盖对象/字符串正文、camel/snake 字段和 SQLite 行映射，CI 与本机均通过。正文未知属性、标题/路径/概念/关联、记录/模板/顶层扩展的保留情况分开断言，不把预期丢失断言当成新协议合格证。

Flutter `Note.fromJson` 已补对象/列表正文到 JSON 字符串，以及 storagePath/docType/linkedDocIds 的别名读取；此前 Web 对象正文会发生类型错误、camelCase 管理字段会丢失。它仍不保留未知记录元数据、模板或顶层扩展，不是新版全量备份支持。

Dart SHA-256 使用 [Dart 官方 crypto 包](https://pub.dev/packages/crypto)，并将 [Dart 浮点字符串表示](https://api.dart.dev/dart-core/double/toString.html)的十进制/指数布局统一到候选约定；最终仍以共享向量及运行测试为门禁。

## 未知数据与后续切换决策

采用“无损保留或明确拒绝”，不为了通过测试在规范化时删除未知字段。本批保留新协议写能力为 0：Web 的顶层扩展、SQLite/Flutter 的固定记录边界和编辑器未知块往返都尚未满足全量保留条件。未来首个可写能力只覆盖已经验证的实体字段/正文特性，超出范围必须在应用/发布前拒绝；需要通用未知扩展往返时再增加存储，不能让 schema 的 additionalProperties 代替这项能力。

本轮未修改数据库 schema、未给现有备份加头，也未操作远端。往返样本不等于加密、资源、设置跨存储或所有编辑变换都已验收。

设置边界已补实际修复：备份内 nr:github-sync 只允许 owner/repo/path，导出和恢复都不承载他端的已接受版本、远端 SHA、凭据模式或协议事实；原有独立本机凭据/事实不被替换。恢复连接时不沿用输入中的基线，失败则精确回滚本机旧配置。该实现覆盖 Web/Tauri 前端设置边界，不表示设置的全部未知字段或跨存储事务已获得新协议认证。

I1 剩余门禁：Dart 向量运行已确认，继续完成可写实体的实际编辑往返、设置/保护边界认证；将真实固定修订预检强制接入新发布计划，以及“可验证完整备份/全部参与端升级”的显式切换流程。正式发布还要与后续基线/attempt 恢复机制衔接。没有通过前不分配正式新协议写能力，也不填写虚构的最低发布版本。


## I1c：候选写入拒绝规则与切换预检（2026-10-15）

`candidate-write-policy.ts` 仅对候选输入做无副作用审查：严格解析，检查元数据白名单，拒绝重复 snake/camel 别名、非规范布尔/排序/路径及未知正文。首个测试范围只包含字符串 Delta insert 和 header/bold/italic/strike/code 属性；ProseMirror、嵌入资源与其它属性仍拒绝，不代表当前产品不支持它们，也不代表此范围已经通过实际编辑往返认证。

设置使用注入的独立内存执行恢复→收集并逐值比较，拒绝丢失、敏感字段、本机基线和重复模板来源；不访问用户 localStorage。AppConfig 尚未认证，非空配置明确拒绝。加密正文保持不透明，检查保护路径/历史与所属正文的 protectionId、salt、iterations 一致，拒绝孤立历史及残留搜索文本；校验不是解密认证，密文可通过格式检查也不代表密码或认证标签正确。错误报告只包含固定代码、数量和所需特性，不包含路径、标题、字段名或密文。

`assertCandidateWrite` 另外要求合法封装、latest 身份、客户端能力及完整的读/写特性声明；当前生产能力仍为 0，候选 eligible 不授予写入许可。Flutter 对模板、设置、加密和版本 2 保持未认证。

`protocol-switch.ts` 提供纯首次切换预检和注入存储的已开启事实记录：

- 同步空间按 owner/repo（忽略大小写）、branch/path（保留大小写）隔离；只保存空间摘要、首次观察提交及格式/codec，前端设置备份不携带或覆盖它。
- 输入证据的控制文件与快照必须来自同一固定提交；未知/混合状态、已观察开启后控制消失、未证明从未开启的历史均拒绝。正常已开启空间要求走加入流程，不走首次切换。
- 首次事实只增不删，读取损坏、写入失败或读回不一致均拒绝；它不能防止旧程序写入或用户清空本机数据，也不能代替远端完整性检查。
- 备份必须绑定当前本地修订及摘要，浏览器仅开始下载不算确认；要求参与端确认、候选实体合格、能力足够及发布恢复机制就绪。

I1c 纯接口之后，I1d 已补真实固定提交下载/历史核验、按域存储往返和候选 attempt 恢复基础。完整备份收据生成、参与端确认 UI 及正式生产发布接入仍未完成。调用方传入的 verified 不是接口自行核验的证明；纯预检 ready 也不是可以直接发布的令牌。未启用任何协议切换、远端写入或自动同步。


## I1d：真实预检与实体往返（2026-10-15）

「协议预检」已接入设置和真实认证 HTTP，固定 Git 提交并验证树、Blob 及快照父链，详见[固定提交预检](../../docs/sync-fixed-revision-preflight.md)。看到控制信息即记录保守拒写标记，完整开启事实另行核实；旧格式入口不能绕过已观察标记。该过程不改变文档、发布指针或同步基线。

`entity-projection.ts` 只接受已通过候选审查的输入。语义投影明确统一 snake/camel、JSON 字符串数组、空概念/关联及可选路径 null/缺省，合并具有相同属性的相邻字符串操作；仅排除派生 search_text、空 tombstone、导出时间/来源元信息。密文不解密、不合并或重加密。数组顺序、正文 Unicode、有效格式、标题、时间与保护关系仍参与实体摘要；缺席实体不表示授权删除。

实际编辑往返发现并收紧：拒绝 CR、缺少结束换行、false 格式属性、带格式换行或将 header 放在非独立换行上的输入；存在格式时，换行必须独立。Tauri 固定模型还拒绝字符串形式的正文/数组、缺失派生搜索字段和越出 i32 的文档排序值。它们可以是现有产品能兼容的旧数据，但尚未获得候选协议写入认证，不通过静默规范化掩盖差异。

共享 candidate-entities-v1 样本覆盖真实 IndexedDB、模板本地存储、Rust SQLite、真实 TipTap 和转换器，以及加密文档/路径验证器/保护历史。存储后可解密同一密文；真实保存更新 updated_at 是实际修改，不从实体摘要中剔除。AppConfig 默认扩展、重复模板设置来源、未知元数据和其它正文特性继续拒绝，因此**正常完整导出尚不能普遍切换**；按域测试不等于整份备份已认证。

Dart 的共享编码、严格输入和 Note SQLite 模型测试已在远端 9aade54 运行通过；本机升级后的 Flutter 3.47.7 / Dart 3.13.5 已运行完整 51 项测试。修复旧测试初始化/列表写 SQL、退役随笔断言，以及实际 NoteVersion 的 sort_order 和标签 JSON 映射。版本 2、加密、模板与设置的新协议 Flutter 写入仍未认证，不因编码通过而开放。

候选[发布恢复基础](../../docs/sync-publication-recovery.md)已加入独立本机记录库、冻结计划、发布前持久化及 GET-only 恢复。只覆盖能力认证后的空命名空间候选；生产能力保持 0，不替换现有 Push 协议。非空远端接受计划、完整 AppConfig/正文覆盖、备份/升级确认 UI 和正式对象准备流程仍为开启前门禁。

## Web AppConfig 候选特性（2026-10-15）

最新范围新增 `web-app-config-v1`，仅允许完整且通过实际 Web 读写规范化的 AppConfig，以 `settings/app-config` 单独投影及组装；不静默填充缺省配置或丢弃未知字段。字段变更必须显式审查。Tauri/Flutter 继续拒绝，原生字段缺失及 null 合并问题仍待修复。实际存储、恢复和候选冲突回归见 [实体计划](../../docs/sync-entity-plan.md#web-appconfig-认证2026-10-15)。此段更新前述历史批次的 AppConfig 未认证范围，不改变生产协议能力或旧备份入口。
