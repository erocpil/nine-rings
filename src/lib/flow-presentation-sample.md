# 流程展示：从想法到可执行方案

一份阶段式说明，将**做什么、为什么、怎样做、交付什么**放在同一条阅读路径上。阶段编号由展示方式生成，正文保持普通 Markdown。

## 捕捉想法，明确要解决的问题

*目的：把模糊的灵感转换为可以讨论的问题。*

**输入**：一次观察、一条反馈，或一项临时待办。

- **记录现象**：描述发生了什么，保留具体例子。
- **明确对象**：谁会遇到这个问题？影响发生在哪里？
- **写出目标**：用一句话描述改进后应该出现的行为。

> 例子：打开长文档后，读者难以快速找到下一步操作。

**输出**：一个问题描述，以及一个能够观察的改进目标。

## 拆解步骤，区分主线与条件分支

*目的：让读者知道从哪里开始，以及不同情况怎样继续。*

**输入**：上一阶段的问题描述。

- **列出主线**：先定位问题，再尝试方案，最后检查结果。
- **标出条件**：遇到异常时，说明返回哪个阶段。
- **控制颗粒度**：每个阶段只承担一个主要动作。

### 条件分支

- 信息充分：进入方案验证。
- 信息不足：返回第一阶段，补充案例与约束。

**输出**：有明确起点、分支和终点的步骤清单。

## 验证方案，检查结果是否满足目标

*目的：用可以观察的结果结束讨论。*

**输入**：步骤清单与一个最小的可执行方案。

| 检查项 | 完成标准 |
| :--- | :--- |
| 主线 | 能从起点走到终点 |
| 分支 | 条件与后续动作清晰 |
| 结果 | 能判断目标是否达到 |

- [ ] 按主线执行一次
- [ ] 验证异常分支
- [ ] 记录结果与下一步

**输出**：验证记录；未满足目标时，返回相应阶段修改。

# 如何使用这种表达方式

在文档属性的「文档展示」中选择「流程展示」，默认以 H2 标题作为阶段，也可选择其它标题级别。普通段落、列表、引用和表格仍可正常编辑，标题折叠也保留原有行为。

建议每个阶段使用「动作标题 → 目的 → 输入 → 操作与分支 → 输出」的结构。更高层级的标题结束当前流程；脚注仍单独显示在文档末尾。

关闭流程展示后，正文恢复普通文档的呈现。导出的 Markdown 不包含额外的阶段编号；展示设置随工作区文档数据保存。
