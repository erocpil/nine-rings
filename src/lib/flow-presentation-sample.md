# 流程展示：从想法到可执行方案

流程块将**做什么、为什么、怎样做、交付什么**放在同一条阅读路径上，可以直接嵌入普通文档。下面的编号自动生成，左侧虚线连接各个阶段。

```flow
### 捕捉想法，明确要解决的问题

*目的：把模糊的灵感转换为可以讨论的问题。*

**输入**：一次观察、一条反馈，或一项临时待办。

- **记录现象**：描述发生了什么，保留具体例子。
- **明确对象**：谁会遇到这个问题？影响发生在哪里？
- **写出目标**：用一句话描述改进后应该出现的行为。

> 例子：打开长文档后，读者难以快速找到下一步操作。

**输出**：一个问题描述，以及一个能够观察的改进目标。

### 拆解步骤，区分主线与条件分支

*目的：让读者知道从哪里开始，以及不同情况怎样继续。*

**输入**：上一阶段的问题描述。

- **列出主线**：先定位问题，再尝试方案，最后检查结果。
- **标出条件**：遇到异常时，说明返回哪个阶段。
- **控制颗粒度**：每个阶段只承担一个主要动作。

#### 条件分支

- 信息充分：进入方案验证。
- 信息不足：返回第一阶段，补充案例与约束。

**输出**：有明确起点、分支和终点的步骤清单。

### 验证方案，检查结果是否满足目标

*目的：用可以观察的结果结束讨论。*

**输入**：步骤清单与一个最小的可执行方案。

| 检查项 | 完成标准 |
| :--- | :--- |
| 主线 | 能从起点走到终点 |
| 分支 | 条件与后续动作清晰 |
| 结果 | 能判断目标是否达到 |

- [ ] 按主线执行一次
- [ ] 验证异常分支
- [ ] 记录结果与下一步

**输出**：验证记录；未满足目标时，返回相应阶段修改。
```

## 使用方法

在正文工具栏的「更多」菜单选择「插入流程块」（窄屏也可使用「块 → 流程块」），或者粘贴一个以 `flow` 为语言的围栏块。

- **阅读与源码**：点击流程块右上角「源码」按钮，直接修改内部 Markdown；点击「流程」恢复呈现。
- **块模式**：点击放大按钮，在「阅读 / 编辑」之间切换；编辑沿用原文档保存与撤销。
- **折叠与复制**：折叠整个流程，或复制内部 Markdown 源码。
- **阶段与分支**：示例用 H3 标题作为阶段、H4 作为分支。也可以统一用 H4/H5 等标题表示阶段；没有 H2 时使用最浅层的标题，含 H2 时仍优先用 H2。
- **多个流程**：一份文档可以插入多个流程块，分别编号和折叠。

推荐结构是「动作标题 → 目的 → 输入 → 操作与分支 → 输出」。内部需要代码块时，用四个或更多反引号包围外层 flow 块，避免内外围栏冲突。

导出 Markdown 时保留 flow 围栏和源文；其它 Markdown 软件可将它作为普通代码块显示。已有文档属性中的流程展示保留兼容，新内容推荐使用独立流程块。
