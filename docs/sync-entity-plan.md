# 非空远端逐实体候选计划

2026-10-15。`src/lib/sync/entity-plan.ts` 是只读规划基础，不是生产 Push/Pull 入口，不提升当前格式读写能力。当前 UI 尚未接入这些选择。

## 固定输入

`previewRemoteEntityPlan` 接受完整远端预检结果，核对空间身份与固定 commit，从该 commit 的 Git 树/Blob 重新读取 latest 和快照，验证 Git 对象摘要与快照身份。不会读取移动分支上的 Contents，也不把报告中的布尔值当作实体内容。快照须通过现有候选正文/元数据认证；未认证 AppConfig、正文或未知元数据继续拒绝。

本机输入、选择和接受基线在第一个异步操作前复制。候选含固定远端 commit、快照 ID/原始字节摘要、本机实体修订和原始两侧快照，显式 `writable:false`。空间变化拒绝复用基线；实体键按 kind/ID 元组编码，重复身份、错误摘要、过期或计划外选择均拒绝。规划不访问正文数据库、接受账本或网络写接口。

## 内容来源与确认分开

| 情况 | 候选内容 | 接受确认 |
| --- | --- | --- |
| 明确选择本机修改 | 冻结本机实体 | 后续发布成功后确认 |
| 明确选择远端 | 固定提交中的远端实体 | 后续本机实际应用成功后确认，不能由 Push 代办 |
| 双方相同且未忽略 | 远端等价实体 | 返回相等证据，调用方仍需核对修订及恢复代次后确认 |
| 忽略或未解决冲突 | 保留远端；远端缺席则保持缺席 | 不推进基线，不丢弃本机草稿 |
| 无基线但双方不同 | 冲突，保留远端 | 不猜测哪一方较新 |
| 有 present 基线但任一方缺席 | pending-delete，保留远端现状 | 不删除、不自动复活、不确认 absent |

`publicationNeeded` 只比较候选实体与远端实体，不能显示成“已经同步”：它可能仍有未接受远端、忽略、冲突或待删除。无变化不应仅为推进时间戳而发布。正文、模板、前端设置、保护路径和保护历史均参与按实体规划。

## 后续门禁

输出仅是语义实体计划，尚非可上传的封装。后续必须把选定来源组合为完整候选，重新验证跨实体保护关系、历史依赖、模板引用及完整设置，连接恢复代次、保存屏障及版本能力，并将选择绑定最终计划摘要。接受账本读取的持久化格式适配、选择 UI、跨存储 Pull 应用日志和对象上传仍待接入。现有空命名空间 preparePublication 不因此放开非空远端发布。

没有新增删除授权、自动同步、旧格式远端改写或真实备份仓库写入。

验证：新增 13 项规划测试；连同候选策略、真实 IDB/SQLite/编辑器实体往返及发布恢复共 49 项通过。覆盖五类实体选择、远端单独变化、双边冲突、显式添加、忽略相同项、三种缺席、错误空间/摘要/重复身份/过期选择，以及模拟 Git 对象接口的固定提交读取。

## 候选组装（2026-10-15）

`assembleEntityCandidate` 从冻结的两侧原始快照重新投影、核验选择，再按实体来源提取原始记录；不接受调用方修改过的 outgoing 列表。组合后重新执行完整候选校验与实体摘要比较，防止独立合法的正文、保护目录和保护历史组合后失配。两侧输入和输出分别受 64 MiB 预算限制。

新候选不继承旧 header、导出时间或设备来源信息：这些属于后续发布阶段。返回的计划摘要绑定空间、两侧语义快照摘要、逐实体决定与候选摘要，因此“忽略相同项”和“接受相同项”即使产生相同内容，也不是同一确认计划。这里的语义摘要不替代固定 Git commit 与原始字节摘要；实际上传仍须由后续发布层同时绑定它们及保存/恢复代次。

本批仍只覆盖此前已认证的数据范围；AppConfig、更多正文特性、正式发布封装、持久接受账本和 Pull 应用日志未开放。模板链接遵循现有校验，不新增不存在的引用完整性承诺。`writable:false` 保持不变。

共享样本 `candidate-reference-anchors-v1.json` 与真实锚点插件覆盖初始化、编辑映射、撤销恢复、IDB 导出/清空/导入和 SQLite 新库恢复。浏览器回归在合并表格中真正创建引用并自动保存：表格正文及完整锚点元数据均通过候选认证，额外未知元数据仍拒绝；刷新后表格内容保留。此前表格批次对 referenceAnchors 的暂拒结论由本批替代。

## 独立图片块正文认证（2026-10-16）

增加候选能力 `block-image-v1`，覆盖 Delta 的独立 `image` 对象及已认证列表、引用中的图片。保留 `imageAlt`、`imageTitle`、正整数／正整数 px 宽度及手动缩进；图片地址、尺寸和描述均原样进入实体摘要，变更任何一项都会改变摘要。不新增图片存储格式，也不改动旧备份导入规则。

认证对象是可移植图片表示：HTTP(S) 绝对地址，以及使用规范 Base64 的 PNG/JPEG/GIF/WebP data URI。相对路径、file/blob/nr-image 地址、含凭据地址、SVG/其它 data URI、非规范尺寸及未知属性均拒绝；不自动清除或改写以通过门禁。此边界证明字节与编辑语义往返，不证明远端链接可访问、图片可解码或离线可用；外部 HTTP(S) 图片仍依赖原站。

本机 `nr-image://` 必须先经现有资源导出器解析成 data URI，再交给候选审查。单元回归验证有资源时正确内嵌、资源缺失时明确失败；没有引入外置附件上传或替换生产 Push。

共享 `candidate-image-v1.json` 覆盖内嵌／远端图片、数值／px 宽度、替代文本与标题、列表／引用嵌套。验证真实 schema 的图片属性编辑与撤销、IDB 更新／导出／清空恢复、原生 SQLite 更新／新库恢复、摘要变化及显式冲突来源组装；Chromium/WebKit 各覆盖桌面及手机宽度的触摸缩放、实际自动保存、完整候选认证和刷新保留。

本批不认证 `inlineImage`、表格内图片、图片链接 mark、百分比宽度及其它未验证表示。后续先补行内／表格图片，再继续脚注、受限 HTML、特殊渲染块和其它元数据。Flutter 仍拒绝，生产 `CURRENT_SYNC_CAPABILITIES.read/write` 保持 0；原生 GUI 和真实远端上传未执行。

## 行内图片及表格图片认证（2026-10-16）

新增候选能力 `inline-image-v1`，覆盖 `inlineImage` 对象及其在段落、简单／复杂列表、引用和表格单元格中的精确位置。图片地址继续复用独立图片的可移植边界；替代文本、可空标题、尺寸、已支持的文字外观和 HTTP(S) 图片链接（含链接标题/显式标记）原样保留。普通文字链接及其它协议链接仍不在本批认证范围，不能从图片链接推导一般链接能力。

行内图片不要求后面单独跟块结束符，不会被投影成独立图片块；其字段与 marks 参与实体摘要。表格允许图片与文本混排，保留表头、列宽、对齐、合并和多段正文。`content` 与 `paragraphs` 必须符合真实编辑器的双重表达，或被拒绝；不通过规范化删除冗余字段来掩盖不一致。引用锚点大小计算补齐 `markdownImage` 原子节点，验证完整锚点范围。

共享 `candidate-inline-image-v1.json` 包含图片链接、外观标记、空替代文本/标题、复杂列表/引用及多段合并单元格。测试覆盖真实 schema 的属性修改与撤销、Markdown 行内/表格图片导入、IDB 编辑/导出/新库恢复、SQLite 更新/新库恢复、摘要变化和选择整实体组装。真实本机图片同时出现在行内及表格 `content`/`paragraphs` 时，现有资源解析器在认证前内嵌全部引用；未解析引用仍拒绝。

浏览器回归在桌面/手机宽度的合并表格中建立真实引用锚点、触摸调整图片宽度、等待自动保存并认证完整正文；刷新后尺寸、位置、链接和多段单元格保留。生产读写能力保持 0，Flutter 继续拒绝；未执行全量 E2E、原生 GUI 或真实远端上传。后续转向脚注、受限 HTML 和特殊渲染块及剩余元数据认证。

## 脚注正文认证（2026-10-16）

增加候选能力 `footnotes-v1`：脚注引用是带稳定 ID、显示编号和本 ID 引用序号的文字 mark；定义保存 ID、可空编号、引用次数及递归正文。允许 Unicode ID、重复引用、多段定义和已认证的列表/引用/代码/表格/图片正文；保留未引用定义（number:null、references:0）及编辑中尚未补定义的引用。定义区必须是唯一的文末区块，定义 ID 不重复，编号/引用次数和字段类型有界且严格校验；未知字段、空或不可编码 ID、过期编号与计数、嵌套定义区块均拒绝。

脚注编号属于整份文档的语义。递归先验证各正文形状，再统一执行一次完整 Delta → ProseMirror → Delta 的语义比较；不能把表格/引用/定义内的引用单独从 1 编号，也不能删除派生字段来掩盖原始数据不一致。普通结构块依然经过同一根级语义核对，递归深度预算不变。

脚注区之前的分隔线以实际编辑器保存的 `hr:true` 对象参与摘要，并单独声明 `horizontal-rule-v1`（同时认证相同表示的普通分隔线）。旧版或刚解析的 Markdown 可能尚未含显式分隔线/计数，若载入时会补写则候选拒绝；正常编辑器保存后的表示可以认证。认证不回写用户正文、不改变旧 Markdown 导入兼容行为。正文引用位置、全部定义（含未引用项）、计数、分隔线和文字外观均参与实体摘要；完整引用锚点的节点大小覆盖 footnotes/footnoteDefinition。

共享 `candidate-footnotes-v1.json` 覆盖重复/中文/带数字后缀的 ID、无定义引用、未引用定义、跨表格/列表/引用的全局编号、定义内引用、多段结构正文、两位数编号及普通分隔线。真实 schema/编号插件的编辑、删除首次引用及撤销，IDB/SQLite 更新/导出/新库恢复，实体摘要与整实体选择组装均有验证。浏览器覆盖脚注编辑、真实自动保存及完整候选认证、重复引用的指定返回、刷新与普通/虚拟只读跳转。

仅扩大 Web/Tauri 候选范围，生产读写能力保持 0，Flutter 继续拒绝。原始 Markdown/来源等未认证元数据仍拒绝，不能由脚注正文认证推导完整导入文档已可切换。后续受限 HTML、特殊渲染块及剩余元数据；未执行全量浏览器 E2E、原生 GUI 或真实远端上传。

## 受限 HTML 正文认证（2026-10-16）

候选能力 `restricted-html-v1` 覆盖 details 的文本 summary、open 状态与递归正文、sub/sup/ins mark 和命名锚点；mark 高亮沿用 `inline-appearance-v1`，硬换行独立声明 `hard-break-v1`。嵌套列表、引用、表格和脚注采用完整文档语义往返，不在局部重新编号。引用锚点模型大小补齐 details 容器及原始 HTML / 命名锚点原子。

`inert-html-v1` 仅保存未知 HTML 的原始字符串：编辑器、普通只读和虚拟只读以转义文本呈现，完整注释隐藏，不生成 script、iframe 或事件处理器。结构化 details 不接受额外 HTML 属性，summary 为纯文本；原始字符串拒绝不可跨 Rust JSON 往返的孤立代理字符。未知字段、丢失的 mark、非法锚点及超深递归均拒绝，不能删除字段或转义源内容使认证通过。导出 Markdown 会保留 HTML 源码，本认证不保证其它 Markdown 软件如何执行这些源码。

共享 `candidate-html-v1.json` 覆盖上下标/高亮/换行、嵌套 details、跨列表/引用/表格的脚注、惰性块/行内 HTML、注释和中文锚点。真实 schema 编辑/撤销、summary/open 修改、IDB 与 SQLite 导出及新库恢复、实体摘要和完整实体选择均纳入回归。浏览器验证折叠工作区编辑、普通/虚拟只读的惰性呈现及保存刷新。

生产 `CURRENT_SYNC_CAPABILITIES.read/write` 保持 0，Flutter 继续拒绝未认证能力；并未开放正式增量备份、Pull 应用或远端上传。下一批为 Mermaid/flow/toc/公式等特殊渲染块及剩余元数据。
