# 非空远端逐实体候选计划

2026-10-15。`src/lib/sync/entity-plan.ts` 是只读规划基础，不是生产 Push/Pull 入口，不提升当前格式读写能力。当前设置页已提供只读差异审查与本机选择草稿；尚未接入正式发布或应用。

## 固定输入

`previewRemoteEntityPlan` 接受完整远端预检结果，核对空间身份与固定 commit，从该 commit 的 Git 树/Blob 重新读取 latest 和快照，验证 Git 对象摘要与快照身份。不会读取移动分支上的 Contents，也不把报告中的布尔值当作实体内容。快照须通过现有候选正文/元数据认证；未认证 AppConfig、正文或未知元数据继续拒绝。

本机输入、选择和接受基线在第一个异步操作前复制。候选含固定远端 commit、快照 ID/原始字节摘要、本机实体修订和原始两侧快照，显式 `writable:false`。空间变化拒绝复用基线；实体键按 kind/ID 元组编码，重复身份、错误摘要、过期或计划外选择均拒绝。规划不访问正文数据库、接受账本或网络写接口。

## 内容来源与确认分开

| 情况 | 候选内容 | 接受确认 |
| --- | --- | --- |
| 明确选择本机修改 | 冻结本机实体 | 后续发布成功后确认 |
| 明确选择远端 | 固定提交中的远端实体 | 后续本机实际应用成功后确认，不能由 Push 代办 |
| 双方相同且未忽略 | 远端等价实体 | 返回相等证据，调用方仍需核对修订及恢复代次后确认 |
| 忽略或未解决冲突 | 保留远端；远端缺席则保持缺席 | 不推进基线，不丢弃本机草稿 |
| 无基线但双方不同 | 冲突，保留远端 | 不猜测哪一方较新 |
| 有 present 基线但任一方缺席 | pending-delete，保留远端现状 | 不删除、不自动复活、不确认 absent |

`publicationNeeded` 只比较候选实体与远端实体，不能显示成“已经同步”：它可能仍有未接受远端、忽略、冲突或待删除。无变化不应仅为推进时间戳而发布。正文、模板、前端设置、保护路径和保护历史均参与按实体规划。

## 后续门禁

输出仅是语义实体计划，尚非可上传的封装。后续必须把选定来源组合为完整候选，重新验证跨实体保护关系、历史依赖、模板引用及完整设置，连接恢复代次、保存屏障及版本能力，并将选择绑定最终计划摘要。接受账本读取的持久化格式适配、选择 UI、跨存储 Pull 应用日志和对象上传仍待接入。现有空命名空间 preparePublication 不因此放开非空远端发布。

没有新增删除授权、自动同步、旧格式远端改写或真实备份仓库写入。

验证：新增 13 项规划测试；连同候选策略、真实 IDB/SQLite/编辑器实体往返及发布恢复共 49 项通过。覆盖五类实体选择、远端单独变化、双边冲突、显式添加、忽略相同项、三种缺席、错误空间/摘要/重复身份/过期选择，以及模拟 Git 对象接口的固定提交读取。

## 候选组装（2026-10-15）

`assembleEntityCandidate` 从冻结的两侧原始快照重新投影、核验选择，再按实体来源提取原始记录；不接受调用方修改过的 outgoing 列表。组合后重新执行完整候选校验与实体摘要比较，防止独立合法的正文、保护目录和保护历史组合后失配。两侧输入和输出分别受 64 MiB 预算限制。

新候选不继承旧 header、导出时间或设备来源信息：这些属于后续发布阶段。返回的计划摘要绑定空间、两侧语义快照摘要、逐实体决定与候选摘要，因此“忽略相同项”和“接受相同项”即使产生相同内容，也不是同一确认计划。这里的语义摘要不替代固定 Git commit 与原始字节摘要；实际上传仍须由后续发布层同时绑定它们及保存/恢复代次。

本批仍只覆盖此前已认证的数据范围；AppConfig、更多正文特性、正式发布封装、持久接受账本和 Pull 应用日志未开放。模板链接遵循现有校验，不新增不存在的引用完整性承诺。`writable:false` 保持不变。

逐实体选择已可经 `prepareReviewedPublication` 生成仅限服务层的持久发布意图，冻结原本机修订与独立候选修订，并只把 `afterPublication` 作为发布后的接受子集。远端选取、忽略、相等及缺席均不代办接受或删除；无内容变化不生成空提交。旧格式首次切换创建 control、协议 parent 为 null；已启用空间保留 control 原字节并链接原快照 ID/字节摘要。两侧快照、基线、选择和组装证据参与重启核验，原快照与控制文件还从固定 Git 父提交回读验证，详见 [发布恢复](sync-publication-recovery.md)。

本批保持生产读写为 0，无正式按钮或真实上传；Pull 本机应用与接受日志、相等证据确认、显式宿主传输/启用流程仍未完成。整个冻结计划含原始来源及证据，继续受 128 MiB 本机日志预算限制。

## 操作内正文认证复用（2026-10-17）

`CandidateEvaluationScope` 是仅供宿主内部使用的不透明临时上下文，不进入插件 SDK、备份、草稿或恢复日志。宿主及预检、发布、Pull、恢复操作入口默认创建上下文，通过显式参数借给子步骤；持有者在成功、失败或取消后的 `finally` 中释放。重启后重新读取冻结记录会创建新上下文并认证，序列化或伪造的上下文不能复用。

缓存只保存正文认证的诊断计数与所需特性，键包含运行时及完整正文/元数据的 JSON 表示。字符串正文仍先严格解析，重复键不能借缓存放行。上限为 512 项、64 MiB（UTF-16 键与诊断 JSON 的计量预算，不是 JS 堆/RSS 硬限制），采用 LRU；超预算照常认证，结果不留存。私有缓存没有公开写入口；读取诊断不会暴露或修改缓存。抛出异常的计算不缓存，部分诊断仍按原规则合并。

只有内容认证可以复用。协议能力与特性声明、根/文档元数据、设置、模板镜像、保护归属、原始来源绑定、实体摘要、文档库代次、保存修订、HEAD、接受基线和应用后目标仍按原边界复核。不缓存这些可变证据，不改变实体编码、摘要、原始来源、绑定规则或接受时机；生产读写能力继续为 0。

大 Git Blob 的 Base64 解码直接填入已核对长度的 Uint8Array，避免字符串迭代器形成大临时数组；64 MiB 文件和 128 MiB 累计读取预算、Base64 形状、UTF-8 严格解码、长度及 Git SHA 复核均保留。多字节大正文与非法 UTF-8 均有回归。完整备份的分阶段耗时、日志预算和测量限制见[真实备份审计](sync-real-backup-audit.md)。


审查预览及 `EntityReview` 只保留原始本机/远端来源、行摘要、空间/修订/代次/选择与接受基线，不再夹带 `outgoing`、`equal`、`afterPublication`、`afterLocalApply` 的整份派生正文数组。组装时重新投影、验摘要和选择；真正的接受实体仍完整保存在 `accepted`/基线中，不能省略。旧日志带有这些派生字段仍可恢复，但不得信任或使用这些数组替代原始绑定来源。

`snapshotEntityReview` 同步深拷贝可变元数据，原始来源必须为不可变字符串，直接保留字符串值，避免每层 `structuredClone` 再次序列化/复制大字符串。规划器和组装器只冻结声明的输入字段，避免传播整份审查的无关派生状态。调用方随后修改来源属性、空间或选择不影响已冻结快照；实际本机/远端变化仍由原有保存、绑定和 HEAD 复核拒绝。日志因此减小，但协议快照和实体摘要不变。
