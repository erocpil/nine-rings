# 非空远端逐实体候选计划

2026-10-15。`src/lib/sync/entity-plan.ts` 是只读规划基础，不是生产 Push/Pull 入口，不提升当前格式读写能力。当前 UI 尚未接入这些选择。

## 固定输入

`previewRemoteEntityPlan` 接受完整远端预检结果，核对空间身份与固定 commit，从该 commit 的 Git 树/Blob 重新读取 latest 和快照，验证 Git 对象摘要与快照身份。不会读取移动分支上的 Contents，也不把报告中的布尔值当作实体内容。快照须通过现有候选正文/元数据认证；未认证 AppConfig、正文或未知元数据继续拒绝。

本机输入、选择和接受基线在第一个异步操作前复制。候选含固定远端 commit、快照 ID/原始字节摘要、本机实体修订和原始两侧快照，显式 `writable:false`。空间变化拒绝复用基线；实体键按 kind/ID 元组编码，重复身份、错误摘要、过期或计划外选择均拒绝。规划不访问正文数据库、接受账本或网络写接口。

## 内容来源与确认分开

| 情况 | 候选内容 | 接受确认 |
| --- | --- | --- |
| 明确选择本机修改 | 冻结本机实体 | 后续发布成功后确认 |
| 明确选择远端 | 固定提交中的远端实体 | 后续本机实际应用成功后确认，不能由 Push 代办 |
| 双方相同且未忽略 | 远端等价实体 | 返回相等证据，调用方仍需核对修订及恢复代次后确认 |
| 忽略或未解决冲突 | 保留远端；远端缺席则保持缺席 | 不推进基线，不丢弃本机草稿 |
| 无基线但双方不同 | 冲突，保留远端 | 不猜测哪一方较新 |
| 有 present 基线但任一方缺席 | pending-delete，保留远端现状 | 不删除、不自动复活、不确认 absent |

`publicationNeeded` 只比较候选实体与远端实体，不能显示成“已经同步”：它可能仍有未接受远端、忽略、冲突或待删除。无变化不应仅为推进时间戳而发布。正文、模板、前端设置、保护路径和保护历史均参与按实体规划。

## 后续门禁

输出仅是语义实体计划，尚非可上传的封装。后续必须把选定来源组合为完整候选，重新验证跨实体保护关系、历史依赖、模板引用及完整设置，连接恢复代次、保存屏障及版本能力，并将选择绑定最终计划摘要。接受账本读取的持久化格式适配、选择 UI、跨存储 Pull 应用日志和对象上传仍待接入。现有空命名空间 preparePublication 不因此放开非空远端发布。

没有新增删除授权、自动同步、旧格式远端改写或真实备份仓库写入。

验证：新增 13 项规划测试；连同候选策略、真实 IDB/SQLite/编辑器实体往返及发布恢复共 49 项通过。覆盖五类实体选择、远端单独变化、双边冲突、显式添加、忽略相同项、三种缺席、错误空间/摘要/重复身份/过期选择，以及模拟 Git 对象接口的固定提交读取。

## 候选组装（2026-10-15）

`assembleEntityCandidate` 从冻结的两侧原始快照重新投影、核验选择，再按实体来源提取原始记录；不接受调用方修改过的 outgoing 列表。组合后重新执行完整候选校验与实体摘要比较，防止独立合法的正文、保护目录和保护历史组合后失配。两侧输入和输出分别受 64 MiB 预算限制。

新候选不继承旧 header、导出时间或设备来源信息：这些属于后续发布阶段。返回的计划摘要绑定空间、两侧语义快照摘要、逐实体决定与候选摘要，因此“忽略相同项”和“接受相同项”即使产生相同内容，也不是同一确认计划。这里的语义摘要不替代固定 Git commit 与原始字节摘要；实际上传仍须由后续发布层同时绑定它们及保存/恢复代次。

本批仍只覆盖此前已认证的数据范围；AppConfig、更多正文特性、正式发布封装、持久接受账本和 Pull 应用日志未开放。模板链接遵循现有校验，不新增不存在的引用完整性承诺。`writable:false` 保持不变。

验证：5 项新增组装测试，相关 6 文件共 54 项通过；覆盖来源选择、跨实体保护失配、完整保护组合、决定摘要、过期选择、未认证设置拒绝和实际 IndexedDB 导入/导出。结构校验不会解密或证明密码有效；保护参数变更样本仅验证关系约束。类型检查与 lint 通过，未执行原生 Tauri/Flutter 组装往返或真实远端写入。

## 行内外观认证（2026-10-15）

候选策略增加 `inline-appearance-v1` 必需特性，覆盖 Web/Tauri 的文字颜色、命名字号及行内高亮；格式声明仍须经读写能力门禁核对。生产 `CURRENT_SYNC_CAPABILITIES` 仍为 0，Flutter 对这些格式仍拒绝认证。

- 颜色仅认证规范化后不变的小写六位十六进制值；短十六进制、RGB 文本、CSS 变量、命名色等暂不认证，避免候选摘要与恢复后的内容不同。
- 字号仅认证现有 Delta 的 `small/normal/large/huge`。不把任意 px 值认定为无损；本批未改变产品既有字号序列化映射。
- 背景色必须伴随 `highlight:true`。行内代码与其它格式混用、行末换行携带行内格式仍拒绝，避免不合法的 ProseMirror mark 集合。
- 测试发现颜色和字号同时存在时生成两个 `textStyle` 标记；现改为同一标记承载两个属性。提取现有 FontSize 扩展供真实 schema 测试复用，命令及默认行为不变。

验证：新增 21 项格式认证测试，相关 7 文件共 75 项通过；共享候选 fixture 增加组合格式，实际 IDB 导入/编辑/导出、Rust SQLite 导入/编辑/导出/新库恢复通过。Chromium/WebKit 各 3 项相关 E2E 分别通过，覆盖格式重开、继续编辑和撤销；完整 npm test、typecheck、lint 通过。原生 Tauri 界面和 Flutter 往返未测试。

后续顺序：完整 AppConfig 认证、列表/结构块等更多正文类型、选择 UI 与持久接受账本适配、对象准备及 Pull 应用日志。当前仍不是生产同步上线结论。

## Web AppConfig 认证（2026-10-15）

`web-app-config-v1` 候选特性认证 Web 的完整 83 项 AppConfig：必须包含全部已审查字段，不能带未知键；类型、枚举、六层颜色、快捷键和实际读取规范化均检查。旧默认配色会在读取时迁移，因此原始旧配色候选拒绝，必须先由现有客户端读取并重新导出。认证不填充缺失默认值、不裁剪未知字段，也不访问真实 localStorage。字段清单冻结，未来新增字段须补充认证和用例。

完整 AppConfig 以 `settings/app-config` 独立实体参与摘要、冲突选择及组装，和 `settings/frontend` 分开，避免选取一类设置时覆盖另一类。实际导入会覆盖所有已知字段（包括 nullable 目录图标值），认证输入不依赖接收端的旧默认值。候选源/目标仍须通过整个快照门禁；不承诺把带未知本机配置的接收端直接纳入无损恢复。

本批只认证 Web：Tauri 固定 AppConfig 缺少 18 个 navigation 字体/颜色字段，配置合并及备份导入会忽略显式 null，Flutter 也没有同等模型。二者继续以 `runtime-unsupported` 拒绝含 AppConfig 的候选；不会静默删除这些设置。下一批先补齐原生模型和可空配置恢复及共享往返，再扩大运行端范围。设置认证证明当前数据在存取中的保留，不代替各设置控件的全部交互验收。

验证：新增 5 项测试，涵盖所有字段缺失的拒绝、未知/非法值、旧配色迁移、无真实存储副作用、实际 IDB 导入/配置编辑/导出及设置冲突组装；同步相关 14 文件共 206 项通过。生产协议写能力仍为 0，未接新 Push/Pull 或真实远端写入。
