# 编辑器后续优化：本轮范围与剩余验收

基线：`412bd02`。本轮不改存储格式，不启用可编辑正文虚拟化，不增加常驻 EditorView。

## 1. 回归基线与实际缺陷

基线 `block-workspace.spec.ts` 为 13 通过、10 失败。旧测试仍在 CodeMirror 编辑模式寻找 `pre code` / ProseMirror；只读全选预期仍是旧的两步选择；工具栏边距和弹层顶部间距断言未跟随已有设计更新。逐项更新入口和断言，保留正文内容、写入目标、保存失败、撤销和折叠状态验证，不跳过这些用例。

手机编号设置测试改走右下边缘设置手势，而不是不存在的桌面按钮。

折叠测试改用当前“新建文档”入口，标题定位显式忽略附加的折叠控件文字。块工作区初始化偶发的 `Execution context was destroyed` 经浏览器协议日志确认，底层是 `Promise was collected`，并非页面实际重载。仅保留任务引用不足以稳定长 CDP evaluate；后续改为页面内持有任务、测试端轮询普通结果，完成后释放，没有重做初始化或跳过断言。

校正入口后补充并修复实际边界：

- CodeMirror 必须接收原块当前内容，工具栏撤销/重做后不能继续显示初始或过期文本。
- 源模型同步到 CodeMirror 使用显式事务标记，避免回写形成第二笔编辑。
- Ctrl/Cmd+Z、Shift+Z、Y 在捕获阶段交给原文历史，避免 Vim 的 DOM 处理器先消费重做。
- 清空代码块不能构造 ProseMirror 的空 text 节点。
- 横竖屏切换时，弹层同时观察编辑器布局变化；仅监听 window resize 会读到响应式布局更新前的位置。

这不是全项目 E2E 已全部通过的声明。

## 2. 大文档性能

复现命令：

```sh
NR_EDITOR_BENCHMARK=1 NR_EDITOR_MOBILE=1 NR_EDITOR_PROFILE=1 npx playwright test e2e/editor-opening-benchmark.spec.ts --workers=1
```

环境：Linux Chromium、390px 手机宽度、Vite 开发模式，独立运行，每种规模三轮。不是手机真机数据，也不是生产包耗时。

| 1500 块，ms | 打开并布局（三轮） | 返回渲染（三轮） |
| --- | --- | --- |
| 修改前 | 4823 / 4605 / 4410 | 4450 / 4331 / 4448 |
| 稳定配置、初始化折叠插件后 | 5431 / 4264 / 4220 | 4587 / 4526 / 4399 |

仅稳定配置的中间实验没有明显提速。最终实验打开中位数略低，但波动较大，返回渲染没有明显改善，不能据此宣称整体显著加速。后续源码映射缓存和职责提取不包含在这组对比中。

本轮减少重复工作：扩展和 editorProps 按编辑会话稳定；折叠宿主插件在初始化阶段注册，不再由 gutter 在挂载/卸载期间反复重配；源码映射仅在当前文档内缓存一份，源码变更时重建，卸载时释放，不建立全局敏感正文缓存。

另修复滚动热点：块尺寸观察器首次观察新进入窗口的块时，不再把初始通知当作尺寸改变，只有实际尺寸变化才触发整窗重测。千块滚动用例原先读了 4872 次矩形，修复后 Chromium、WebKit 都通过原有的 `< 600` 断言；没有放宽阈值。这是滚动路径的改进，不能代替首次打开速度结论。

基准增加 CPU 调用链记录。剩余热点仍是完整 EditorView 挂载、NodeView 初始化和布局测量，开发模式 StrictMode 也会放大这些成本。后续应先补生产包/真机对照，再决定是否采用分阶段布局；不能为了数字隐藏正文、丢失选区或撤销历史。

## 3. 位置对应精度

长列表、引用和表格按内部文本段落索引，不再对整个容器高度插值。保留顶层块身份以兼容只读局部渲染；表格源码按行映射，跳过分隔行。重复文字仍按文档顺序对应，不做全文关键词搜索。

段内位置仍是近似映射：图片延迟加载、超长单段、代码折叠和复杂行内样式仍需更细的行级锚点与真机测试。本轮不承诺任意排版下逐像素一致。

## 4. 列表样式

正文和设置预览中的列表几何规则移入 `editor-lists.css`，导入位置保留原有后置覆盖关系。不混入新的列表样式设计；验证嵌套标记、编号列、字体缩放、可调间距及任务控件。

## 5. 职责拆分

提取 `useEditorScrollPersistence`，负责持久化滚动位置、状态栏位置显示和恢复取消；当前渲染器切换锚点优先级不变。编辑器主体不再承担这一组 effect，但仍持有会话和视图 ref。

App 工作区导航、SettingsPanel 分页和完整编辑器生命周期仍需后续独立批次，不把本轮局部拆分标记为全部模块化完成。

## 后续批次：首次打开与 App / 设置页拆分

### 首次打开

`DocumentEditorContent` 将 TipTap 挂载 DOM、设置编辑器选项、安装 NodeView 期间的中间布局合并：挂载阶段暂不参与布局，在同一 commit 的 layout effect 中恢复显示，早于绘制和父级的位置恢复。不使用定时器延迟正文、不减少块数、不关闭 StrictMode，也不改变文档、选区或撤销模型。

生产包复现：

```sh
npm run build
NR_EDITOR_BENCHMARK=1 npx playwright test --config playwright.editor-benchmark.config.ts
```

Linux Chromium，390px 宽度，1500 块已有可编辑文档，每轮新建页面。计时从页面导航到完整正文挂载并完成两帧布局；关闭 Service Worker，HTTP 缓存可热，不是网络全冷启动，也不是真机结果。对照组为相同代码，仅恢复原来的 EditorContent 挂载方式。

| 生产包 | 三轮耗时（ms） | 中位数（ms） |
| --- | --- | --- |
| 原挂载 | 685.9 / 714.2 / 654.7 | 685.9 |
| 合并中间布局 | 573.1 / 518.9 / 490.1 | 518.9 |

本组中位数降低约 24%。两组均挂载 1500 块、1551 个正文后代元素。基准另检查正文可见、可编辑和完整块数；不以只显示首屏冒充完整就绪。

开发模式的较长混排文档也有改善：1500 块打开中位数 2647ms → 1576.9ms，但三轮波动明显（优化后 1459–2249.4ms），且 StrictMode 会放大重复布局，不能与上述生产包绝对耗时直接比较。更大文档、图片/表格密集内容及真实设备仍需后续采样。

### 职责边界

- App 提取 `useWorkspaceSidebar`：各面板宽度、切换、拖拽冻结、尺寸持久化与取消/失焦清理。App 保留文档导航和保存边界；从 2287 行减到 2072 行。
- 设置页提取 `SettingsDataPage`、`SettingsUpdateStatus` 和 `useSettingsData`。导入任务状态仍归设置面板持有，切换分页或关闭重开不会丢弃任务；配置保存队列与排版草稿不变。SettingsPanel 从 1384 行减到 1066 行。
- 修正当前回归涉及的旧 UI 定位：桌面列表分区、独立目录按钮、图片建文档入口、文档树折叠状态；右键用例同时等待浏览器和编辑器模型选区。
