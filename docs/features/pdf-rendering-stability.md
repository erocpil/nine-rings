# PDF 快速滚动稳定性与分级渲染

## 已定位与处理

- 占位页变成待渲染 Canvas 时失去预估高度，默认 Canvas 高度改变了滚动几何位置；纵向页面现在始终保留宽高比，已渲染页面保留测得尺寸。
- 同一页面不同请求可能具有相同渲染签名。每批请求增加独立所有权，旧批次的完成/清理不能修改新批次状态。
- 失效批次在入口、逐页循环和异步结果提交前退出，取消正在进行的 Canvas/文本层任务。旧批次不能关闭新批次的加载提示。
- 手机最多挂载四个页面画布，每页最多 200 万像素；离屏高清结果进入 LRU 缓存，最多六页、总计 1200 万像素，淘汰时清零。临时画布在成功、失败、取消后均释放。挂载页、离屏缓存及一个串行临时画布的 RGBA 输出缓冲预算约 88 MB；这不是 PDF 解码、字体、图片和浏览器进程的总内存上限。
- 后续补齐离屏 PDF.js 页面解析缓存清理：等待该页渲染流水线结束，且页面没有重新进入挂载集合后才释放。加载任务未完成时关闭阅读器也会销毁 Worker。
- 缩放布局与渲染完成时序分离：缩放时同步更新全部占位页和已缓存页尺寸，避免屏幕外的旧大页面撑出横向滚动空间。当前页小于视口时保持居中并关闭横向手势，宽页面仍允许平移；缩放锚点恢复也遵守这一边界。

## 诊断

设置 → 高级 → 本地诊断 → 导出诊断报告，新增 `readerEvents`。

最近 40 条本地事件仅含事件类型和时间，不含 PDF 名称、ID、正文或错误原文：

- `boot`：应用模块重新启动。
- `open`：PDF 加载开始（开发环境 Strict Mode 可能重复）。
- `close-request`：明确调用返回入口。
- `render-error`：当前有效任务渲染异常。
- `pagehide`：浏览器通知页面离开。

`open` 后没有 `close-request` 而出现新的 `boot`，说明需要调查重载，但不能据此认定是内存崩溃。系统终止进程时不保证触发 `pagehide`；存储不可用时记录会安全跳过。

## 验收范围

新增 60 页纵向快速往返滚动测试，检查目标页文本与画布完成标记、最多四个可见画布、离屏缓存预算、缩略图保留、回滚高清缓存命中、主动关闭与重新启动记录。该测试首先复现目标页偏移，稳定占位尺寸后通过。

Chromium 增加 4 倍 CPU 降速及同页反复进入/离开，并以受控挂起的 PDF Worker 测试加载中关闭；这两项与普通 PDF 阅读回归均通过。

本轮 Chromium 5 项阅读/滚动/工具栏回归、104 项单元测试、零 warning lint、类型及项目格式检查通过。缓存单元测试覆盖 LRU 淘汰、像素预算、缩放签名失效和资源所有权转移。

仍需手机安装 PWA 使用原始问题 PDF 实测，特别是扫描版、混合页面尺寸及高倍率缩放。WebKit 本环境的真实文件导入停在 IndexedDB Blob 事务失败，不能计作阅读渲染验证通过。

## 分级显示策略

- 纵向滚动速度超过 0.8 CSS 像素/毫秒时使用预览任务；停止约 200 毫秒或回到慢滚时恢复高清任务。选择文本或使用批注工具时优先交互质量。
- 已挂载高清页面不降级，回到近期页面先显示缓存位图，再恢复文本层；缓存签名包含文档代次、视口和缩放策略，尺寸不匹配时重新渲染。
- 预览最长边限制在 192×256 框内，完成高清渲染也会顺带生成预览。最多保存 64 页 JPEG 数据 URL，字符串总量不超过 200 万字符。缩略图不参与选择、搜索和批注，原文本层与批注坐标保持独立。
- 可见页优先；邻近页面高清预取先等待前台空闲调度，再串行执行。不会打开文件便生成全书缩略图，切到系统后台也不承诺持续渲染。
- 缓存位图在文字层和画布共同提交前仅借用、不移出 LRU；中途滚动或切换预览质量导致任务取消时，仍保留原高清副本。成功复制到当前画布后才移出并释放，避免短距离往返重复栅格化。本次 CI 排查在双 worker、4 倍 CPU 降速、重复五轮中复现一次旧实现缓存丢失；修复后同样五轮全部通过，缓存预算未提高。
- 新页面首次到达且没有任何预览时仍需等待一次 PDF 解码；未知页面尺寸仍使用估计比例。扫描版解码峰值不等于输出画布预算，仍需真机压力验证。

异常重载后的会话恢复与磁盘预览缓存暂未开启，不自动恢复可能反复引发故障的文件。
