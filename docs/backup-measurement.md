# 备份测量（I0 第一批）

2026-10-14：先测量现有完整 JSON，不改变远端布局、Push/Pull 合并语义或数据库格式。

## 应用中的入口

设置 → 云端同步 → GitHub 备份 → **备份测量** → **分析本地快照**。无需先配置 Token。操作先保存待处理编辑，再调用正常的完整导出；分析优先在已有数据转换 Worker 中执行，不可用时兼容回退。大快照仍会占用导出和分析所需的内存，这不是流式导出实现。

报告按实际导出文本的 UTF-8 字节统计，包括缩进、转义、键名、标点与空白。类别互斥，合计必须等于整个文件大小：

| 类别 | 范围 |
| --- | --- |
| 正文 | notes 中的 content；扣除可识别的内嵌图片字符串值 |
| 内嵌图片 | 正文/模板已知图片槽位 insert.image 或 attrs.src 中的 data:image 值，包含 JSON 引号与转义开销 |
| 文档与保护元数据 | notes 的其他字段及 protected_paths；容器键名/标点归容器，不重复计入图片或搜索值 |
| 派生搜索文本 | 文档 search_text/searchText 的值 |
| 模板 | templates 以及 user_settings.values 中的 nine-rings:templates，扣除识别的图片值 |
| 保护历史 | 整个 protected_versions，保持密文边界，不提取其内图片 |
| 设置 | config 与其余可备份 user_settings |
| 其他 | 根封装、导出身份、未知顶层字段及其容器开销 |

这些是**导出表示的构成**，不是正文压缩后的大小或可直接节省的带宽。正文若以字符串封装 JSON，不二次展开，其中图片仍计入正文并提示；模板内类似字符串也不二次展开。结构化图片数量不包括加密、外链、普通文字中提及的 data URI 或上述字符串封装。模板计数是两处模板数组的条目数，不按 ID 去重。导出范围沿用当前协议，普通本地历史、回收站和 PDF/EPUB 原件不会因为本工具自动加入备份。

保存、完整导出、分析往返和总耗时单列；analysisMs 仅为分析函数时间。峰值内存没有跨端可靠实现，明确标为未测量；代理/VPN 状态为 unknown，需人工注明对照条件。不得将它们当成零开销或无代理的证据。

正常 Push 时，另记录 Contents 快照/指针及 Git 数据接口请求的实际 JSON 请求字节、通道、完整响应读取耗时、HTTP 状态或网络失败。请求体构造时间不在该网络耗时内，普通连接检查和 Pull 不在本批统计范围。记录仅保留当前会话最近 24 次请求，不保存地址、正文、令牌或错误原文。**复制测量报告**仅复制上述聚合结构；Esc 关闭测量弹层并保留设置页。

## 本地 JSON 分析

```sh
bash scripts/with-local-tools.sh npx tsx scripts/measure-backup-export.ts /path/to/export.json
```

只读本地文件、输出聚合 JSON，不打印标题、路径、ID 或正文；输入错误使用通用提示。

## 仓库元数据只读工具

离线样本不读令牌、不访问网络：

```sh
bash scripts/with-local-tools.sh node scripts/measure-backup-repo.mjs \
  --fixture tests/fixtures/backup-measurement/repo.json
```

真实仓库：先在终端以安全方式设置会话环境变量 GITHUB_TOKEN，再运行：

```sh
bash scripts/with-local-tools.sh node scripts/measure-backup-repo.mjs Owner/Repo \
  --pages 10 > .local-tools/backup-measurements/repo.json
```

重定向前自行建立输出目录；不要将令牌写在命令参数、报告或仓库文件中。工具固定访问 api.github.com，仅 GET 仓库、分支、Git commit/tree 与提交列表元数据，拒绝重定向，不调用 Contents 下载或任何写接口，不删除文件。默认分支来自仓库，支持 `--branch`；所有树与提交分页绑定本次读取的 HEAD。单请求 20 秒、整次网络预算 120 秒，不自动重试限流或其他错误。

默认报告隐藏仓库名、分支名及文件路径，用空间摘要匹配历史样本；显式 `--details` 才输出这些信息。版本化快照默认匹配 `-YYYYMMDDTHHMMSS[mmm].json`，可用 `--pattern` 自定义；匹配文件不一定已经被 latest 发布，提交数也不等于成功 Push 次数。报告不分析指针或孤立对象，不统计成功发布次数。

GitHub repo.size 以 KiB 为单位，是可能延迟更新的仓库汇总统计，**不是当前分支精确 pack 大小**。当前树文件原始字节合计是另一口径。树截断时标为下限；提交分页最多 1–100 页（默认 10），未读完时总数为 null，最近 90 天计数也标为不完整；无效/未来日期单独报告。

`--history samples.json` 接受既有报告数组；只有同一 scopeId、相隔至少一天且大小未下降的样本才给出粗略线性增长估计，明确列出假设。单次观察不能用“大小÷提交数”预测三年增长，估计也不授权清理或重写历史。
