# 固定提交协议预检

> 当前状态（2026-10-17）：Web/Tauri 0.3.0 已开放经过认证的手动同步，正式入口、限制与恢复规则见[同步指南](incremental-sync.md)。下文带日期的能力关闭及未接入记录保留为历史，不代表当前发布状态；Flutter 仍未开放。

2026-10-15。设置 → 云端同步 → GitHub 备份 →「协议预检」。Web/Tauri 共用认证 HTTP 入口；不应用文档、不更新同步基线、不向远端写入。首次开启事实与保守拒写标记是设备本地诊断，不进入便携设置备份。

## 读取与核验

1. 查询仓库默认分支，只读取一次分支引用，得到固定提交 H。
2. 从 H 的 Git commit/tree 逐层查找控制文件、文本 latest 和快照；不将 Contents 的 404 解释为文件缺席。非递归树必须完整、路径不重复，不接受符号链接或子模块代替备份文件。
3. Blob 验证声明大小、Base64、严格 UTF-8 和 Git SHA-1，再严格解析 JSON。后续父快照同样从 H 的树读取，不跟随移动中的分支。
4. 新封装 latest 身份、格式/codec、parent 原始文件 SHA-256 与控制文件的首快照锚点必须一致。父链不可达、损坏或超预算均停止，不当作旧格式。
5. 无控制文件时，在预算内遍历所有可达 Git 父提交，检查该控制路径是否曾出现，不只扫描第一父链。只有完整遍历成功才返回本模型下的 verified-never-enabled；权限、限流、缺失提交和截断不是“从未开启”。这不是对外部强推前的不可达历史或任意旧协议格式的证明。

读取使用 GitHub 的 [Git Trees API](https://docs.github.com/en/rest/git/trees#get-a-tree) 和固定 SHA 的 Git objects；[Contents API 的 ref 默认跟随分支](https://docs.github.com/en/rest/repos/contents#get-repository-content)，因此不能混用默认分支下载作为固定提交证据。

## 控制路径与预算

沿用当前备份基路径命名：例如 `nested/backup.json` 对应 `nested/backup-latest`、`nested/backup-<id>.json` 和预留控制路径 `nested/backup-protocol.json`。控制定义见 [候选 schema](../schema/sync/control-candidate-v1.schema.json)。它绑定首个封装快照的 ID 与**原始 UTF-8 文件字节** SHA-256；parent.sha256 使用相同口径，不能用 Git Blob SHA-1 或实体语义摘要代替。

默认最多 160 个请求、128 MiB Blob 解码总量、单 Blob 64 MiB、单树 10000 项、单提交 32 个父项；快照链默认 16 个（最多 32），Git 历史默认 16 个提交（最多 64）。目录路径最多 100 段。超预算会明确停止或返回历史未知，不提高预算来掩盖不完整核验。

预检一旦看到控制文件或无控制文件的封装头，就先保存保守的连接拒写标记；即使后续读取失败、不支持控制版本或完整性失败，也不能再通过旧格式 Push/Pull 绕过。完整核验成功后另保存空间首次开启事实。连接标记跨默认分支变化保守拒绝，空间事实仍按 owner/repo/branch/path 独立。存储不可用不伪报检查成功；凭据不进入 report.space、记录库或日志。

## 当前边界

生产读写能力仍为 0，已开启空间只能核验并停止旧格式同步。协议预检是显式操作，尚未替换旧协议每次 Push/Pull 的全部下载步骤；它不是正式切换入口，也不能让旧二进制获得这些检查。尚未观察到协议的旧格式连接继续保持兼容行为。

正式切换前仍需：非空远端的逐实体接受/冲突计划、完整设置与正文特性认证、备份收据和参与端升级确认，以及强制接入发布前的固定提交核验。新协议只读能力、父链检查点和历史压缩不能由一次预检自动授权。
