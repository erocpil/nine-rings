# 共享双栏核心与独立应用宿主

日期：2026-11-09。状态：用户已确认方向，分批实施。

## 背景与选择

双栏浏览已具备导航、比较、预览及安全操作能力，需要逐步成为独立软件。用户要求两款软件的核心功能出自同一套代码。当前插件仍直接依赖 Nine Rings 的主视图、最近文件、会话、授权及设置，不能通过复制组件获得可靠的独立产品。

选择同仓库共享核心、分别装配宿主。备选的长期复制分支会产生修复与安全规则分叉；把完整 Nine Rings 换一套外壳则继续带入数据库文档和同步生命周期。先抽离必要接口，再建立独立入口，避免先搬目录或重写已有行为。

## 第一批边界

- 共享模型、路径检查、目录提供者、操作执行器及串行队列。浏览器核心不直接访问主区域、插件全局实例或浏览器存储。
- 宿主提供授权断言、文件服务、打开文件、草稿检查、操作租约、移动/删除后的会话协调、变更通知及可选的结果记录。
- 授权、草稿检查和会话协调都是必需接口，不能以默认空函数绕过。可选 UI 持久化仍由原适配器处理，不得把已完成的磁盘操作误报为可直接重试。
- Nine Rings 旧入口保持签名与行为，通过适配器委托共享实现；现有调用方不需要一次迁移。纯比较/刷新模块和展示控件只依赖提供者契约。
- 第一批不新增安装包、目录授权、写权限或持久化格式。独立宿主、原生共享库及交付属于后续批次，不能将接口解耦称为独立软件已完成。

## 写入与生命周期约束

执行器在文件服务成功返回后，先记录写入已经确认，再协调宿主状态与发布变更。如果此后协调或通知失败，即使错误中含有 `TARGET_EXISTS`，也只能标记为需核对，不能进入重名重试循环。取消或撤回身份阻止后续工作，但已提交的磁盘操作仍须完成状态协调和租约释放。

打开文件与只读查询的结束条件不同：查询返回前重新核验身份与取消；打开操作由宿主在最后一次异步检查后接受，成功打开可能主动撤销原浏览视图，不能再将这次已接受的导航误报为取消。队列历史仅记录结果，不将持久化内容反序列化成可执行任务。

## 后续顺序

1. 完成上述共享核心及宿主契约，保留原插件回归，验证两个隔离宿主使用同一执行器。
2. 建立独立入口，复用浏览组件、文件服务和查看器；独立管理设置、授权、未保存内容及退出流程。
3. 整理共享原生文件服务与三平台打包，使用独立应用标识、数据目录、更新通道和产物。
4. 在两种宿主运行相同功能契约；核心缺陷只修复一次。随后按实际需求完善产品体验。

## 验证与监控

重点保持授权撤回后拒绝迟到结果、操作前与写入前重新检查草稿、租约释放、已发布但收尾不确定时暂停、队列不重放成功项、移动后打开文件身份一致。共享核心不得存在对 Nine Rings 主视图或插件单例的运行时依赖。

通过既有单元测试、可替换宿主契约测试、Chromium/WebKit 插件交互、类型/lint 和生产构建验证。记录新增核心覆盖率和原插件回归结果。独立启动耗时、内存及包体积在独立入口形成后测量，当前不承诺数值。

产品范围与取舍见[独立产品评估](../future-evolution/dual-pane-standalone.md)。

## 第二批：共享界面与独立 Web 原型

先将 `DualPaneFileBrowser` 保留为 Nine Rings 装配入口，提取唯一的 `FileBrowserWorkspace`。根授权、能力探测、目录提供者、队列、搜索、变更订阅及设备设置通过必需的宿主端口传入；列宽、常用目录和浏览状态使用可加命名空间的存储端口。各层不能回落到另一个应用的全局服务。

建立单独 Vite 入口作为 Web 原型，以独立开发端口和构建目录运行，不启动 Nine Rings App、数据库文档、同步或升级流程。复用现有文件服务的授权检查及相同浏览界面，文件打开先使用共享只读文本/图片预览。此原型明确禁用写入，不能以空草稿检查承诺编辑安全；原生安全操作、可编辑查看器、退出保存以及独立打包继续留在下一批。浏览器授权句柄为会话临时状态，重新启动需要授权，不声称已恢复系统权限。

## 第三批：共享源码工作区与安全保存

独立入口先接入既有 `DocumentSourceSurface` / `MarkdownSourceEditor`，不复制 CodeMirror、工具栏、选区菜单或折叠规则。完整富文本 Markdown 工作区仍带有数据库文档操作，不能为了复用而让独立原型引入数据库 API；本批优先实现完整源码查看、显式编辑、原文件修订核验保存及副本导出，富文本渲染后续再按能力接入。

保存提交与保存期间的后续编辑由共用协调函数处理，Nine Rings 本地文件入口与独立宿主都使用它。恢复草稿复用同一实现，以独立数据库名称隔离；目录快照不能写原文件。离开编辑区必须保存、确认草稿已持久化，或明确丢弃；失败保持编辑器与撤销历史。页面强制关闭仍只能尽力写草稿，对未落盘内容保留浏览器退出提示，不承诺异步事务在进程终止后必定完成。


独立恢复草稿采用“保留至手动处理”策略：不按时间过期，最多五份；满额时事务回滚并阻止以“已保留草稿”为由离开，不能静默淘汰已向用户确认保留的内容。下载和确认删除均在恢复入口提供；Nine Rings 默认保留策略兼容原有行为。保存期间又发生编辑、或者草稿收尾未确认时，保存器不返回“当前编辑已全部保存”的成功值。

## 第四批：共享 Rust 文件宿主与独立桌面入口

将既有 `local_files` 与跨卷传输实现原样迁入 `native/file-host`，包含现有回归测试；Nine Rings 通过模块重导出继续使用相同命令路径。共享状态在 `load(dir)` 时持有调用方提供的授权记录位置，取消对 Nine Rings `DataDir` 的直接依赖，保留记录文件名称/内容和主窗口调用限制。不会让独立宿主复用 Nine Rings 数据目录。

独立 Tauri 工程位于 `native/file-workbench/src-tauri`，使用单独的 Cargo workspace/lock、应用标识与标准系统标题栏。只装配共享文件服务和必要对话框；没有数据库、同步、托盘或全局快捷键。前端继续使用同一工作台和源码工作区。首次本地目标为 macOS ARM64 `.app`；Windows/Linux 编译交付和正式品牌/更新通道继续后续处理。

关闭窗口和系统退出统一经前端保存/草稿保护；源码宿主接受离开动作回调，成功保存或确认草稿后才执行退出。加载前尚无编辑时可直接关闭；前端接管后禁止原生入口绕过该确认。异常进程终止仍只能依赖已提交草稿，不能承诺最后一次异步事务必定完成。


## 共享文件右键菜单与系统打开

文件列表使用独立于随记菜单的 `FileBrowserContextMenu`，由同一双栏视图在两种产品中复用。按打开/预览、复制信息、文件操作和回收站分组，使用现有风格/主题颜色，提供悬停、键盘右进左退及越界避让。系统打开是可信宿主的可选能力；Web 不虚构此能力，系统打开能力不直接授予目录变更能力；独立宿主目录队列按下文单独装配。

打开方式先支持内置编辑器、系统默认应用及通过系统文件选择器选择其它应用。应用由原生端选择，不接受前端任意应用路径或命令；仅打开已授权根内的普通文件，选择前后复查路径与授权，拒绝符号链接及目录。macOS 使用 `/usr/bin/open` 的独立参数，Windows 默认使用 ShellExecute、其它应用使用明确选择的 exe，Linux 使用 xdg-open/gio 与用户选择的 desktop 文件。不开启 shell 插值，不修改默认关联。系统接手后的外部程序和已接受的打开请求不受插件停用控制；文件仍由既有外部修订校验保护，打开请求不伪装为保存。

目录修改时间按真实文件系统元数据展示，只表示该目录条目自身的修改时间；Web 无法提供时显示未知。目录大小默认不递归扫描、显示“—”及未统计提示；递归统计另行定义预算。`.` 不展示，`..` 由既有上级按钮、面包屑与快捷键替代，不作为可选中/复制/移动的伪文件，授权根不能向上越界。


## 独立界面的紧凑装配

通过可选 `BrowserWorkspaceHost.presentation` 调整同一共享界面的排列，不复制双栏组件。`toolbarExtras` 只接收可信宿主的工具内容，不把宿主草稿或配色状态放进文件服务/队列。地址栏继续共用原路径解析、授权验证、历史与收藏逻辑；显示与编辑互斥，输入取消须撤销在途请求。紧凑外观不决定目录写权限，由独立宿主按平台和队列能力明确提供。默认未声明模式的 Nine Rings 入口不改变。


## View 菜单的状态所有权

`BrowserWorkspaceHost.viewMenu` 是可选可信宿主端口，工作区发布当前活动目录栏的隐藏项状态并消费切换请求；每栏/标签仍由原 browser state 持有。独立应用提供原生菜单与 Web 等价菜单，初始化原生失败可回落。菜单失效/编辑器打开时禁用，原生状态更新排队防止迟到 IPC 重新启用旧面板；隐藏项不转换为文件写权限。新增 `type-desc` 同时检查 TS 排序/状态解析与 Rust serde enum，列宽兼容既有设备设置，不新增共享同步字段。


## 独立宿主的目录操作与配色（2026-11-10）

独立应用通过 `createWorkbenchOperations` 装配现有 `createBrowserOperationRunner` 与 `BrowserOperationQueueCore`，复用原生授权服务、同名不覆盖、目录递归预算、跨卷校验、冲突处理、停止语义及结果分类；不复制一套文件算法。入口与执行器均限制目录变更为 Tauri，Web 的已授权目录仍可保存正文，但目录队列即使被程序调用也会拒绝。

独立源码查看器没有后台缓存编辑会话；从编辑器返回浏览必须经过原离开确认与草稿事务。路径操作先检查独立草稿库，当前采用保守的“存在任何恢复草稿则拒绝”策略，覆盖后代路径、重叠授权和重启后身份变更；不会替用户删除或重新绑定草稿。目标写入也再次核验草稿并取得路径租约，异常后释放。后续若放宽为仅相关路径阻止，须先建立可核对的持久身份与草稿迁移协议。

任务执行、排队或等待冲突时，禁止进入独立编辑器以及确认退出；停止仍等待已提交的原生调用收尾，不能把停止按钮视为文件写入已取消。任务完成后再关闭窗口。Web 离开提示归界面生命周期所有，原生关闭握手仍由主窗口处理。确认后的变更通过原 mutation 通知更新两栏、标签与路径；没有后台编辑实例/草稿可迁移时，宿主协调钩子可为空，但不能绕过上述前置条件。当前队列不持久化或自动重放，强制退出仍需按实际磁盘状态核对。

菜单按对象与宿主能力筛选：目录不显示文件专属预览及打开方式；快照不显示变更或系统应用命令。临时忙碌、缺少目标栏等可恢复状态仍可禁用相应命令。重命名、新建、回收站只依赖当前栏，另一栏未选择不应阻止；复制/移动才要求可写目标栏。

配色只设置独立页面的颜色变量，提供柔和浅色、柔和深色及参考 Nine Rings 清雅/物哀的绿色/玫瑰色系，不启用 Nine Rings 的文档布局预设。`file-workbench:palette` 保存枚举值，首次兼容旧 `file-workbench:dark`，不写 Nine Rings 的主题设置。选择状态由宿主统一持有，浏览与编辑的工具入口共享，避免隐藏的浏览器工具保留旧色并在返回时覆盖新选择。

## 工具栏启动器、多目录区与连续预览（2026-11-10）

参考 [Total Commander 按钮栏](https://ghisler.ch/wiki/index.php?title=Button_bar)和 [Xfce Launcher](https://docs.xfce.org/xfce/xfce4-panel/launcher)，工具名称、程序、参数、图标和提示分开存储。配置仅在独立设备设置 `file-workbench:custom-tools-v1` 中保存，最多 32 项、总计 4 MiB，读写使用相同上限；单个导入图标不超过 128 KiB，保存为内嵌 PNG/JPEG/GIF/WebP，不依赖原路径持续授权。预置图标复用现有 ToolbarIcon 并分组，也支持 Unicode。宿主统一持有定义，浏览和编辑工具入口不各自缓存一份。

启动是主窗口明确点击触发的 `workbench_run_tool`，不在加载配置时执行，不作为第三方声明式插件的授权能力。参数每行一个，通过 Vec<String> 传递；`{path}`、`{file}`、`{name}`、`{target}`、`{files}` 在后端对授权根内节点核验后展开，替换结果不递归解析。`{files}` 必须独占一行；未知文字和 shell 字符仍是普通参数。无目录时可运行不依赖文件上下文的程序，若模板需要目录/选中项则明确报错。程序名或完整路径由用户配置；macOS 应用包通过系统 open 启动。默认“启动应用”方式显示启动 PID，外部程序自行运行、可在工作台退出后继续；该方式不捕获输出（命令行捕获方式见下文），不将程序冒充为已完成的文件队列操作。内置文件服务的根授权、路径校验和保存修订协议不因此改变。

每侧可显示 1～4 个纵向目录区。为保留现有单一来源/目标算法，state.groups 始终是两侧当前激活的组；extraGroups 保存其它组，activeRows 保存其插入位置，visibleRows 控制显示数量。激活仅交换组的归属，不复制标签实例；异步列表更新通过 updateBrowserRow 写回原目录区并保留用户的活动区。减少数量停放其它组，不丢弃路径/标签，增加后恢复。解析兼容旧版本 2 设置，限制每组 16 个标签、每侧 3 个附加组，并修复同列重复标签 ID。变更协调覆盖停放组，交换两侧也交换行数/活动行；复制/移动使用另一侧激活区，直接拖放使用实际落点。Nine Rings 默认仍只显示一组，入口和文件算法没有分叉。

全视图打开请求可附带当前已加载、排序/过滤后的 siblings 快照；共享提供者只透传可选字段，旧宿主不需要实现另一套导航。连续预览跨可预览文本和图片，跳过目录、已知二进制及超预算项，不绕回、不追加目录枚举。未知文本格式仍由实际 UTF-8 读取决定能否展示。空格/F3 的双栏快速预览保留上下键，全视图只读文本和图片使用左右键；可编辑文本保留原编辑键，按钮切换走 requestClose 的保存/草稿门禁。关闭仍恢复进入预览前的列表焦点和双轴位置。

标签排序从按下即捕获指针，以 6px 区分点击/拖动，拖动时只提示目标，释放后才改顺序，避免标签换位导致重复命中；键盘标签切换与移动继续保留。独立弹层只对背景使用 1px 模糊和很轻的暗色遮罩，兼容 WebKit 前缀，不改变弹层内容本身的清晰度。

### 工具执行与结果（2026-11-10）

工具定义继续使用独立宿主设置 custom-tools-v1，可选 kind=separator 表示竖线；execution 缺省 launch，保留旧配置启动应用语义，capture 表示等待命令行退出并捕获输出。已有工具和分隔符可右键修改，配置页左右移动决定工具栏顺序。目录标签关闭改为双击/右键；固定标签关闭前额外确认，批量关闭若包含固定项也先确认；最后一个固定标签确认关闭后保留空白占位页。

工具点击先解析授权路径并展示程序、逐项参数和工作目录，确认执行时重新核验并比较预览，路径变化必须重新预览。JSON 引号用于展示参数边界，不是 shell 命令；不会隐式调用 shell。{files} 独占参数行，每个选中文件或目录分别成为一个参数，其它占位符 {path}/{file}/{name}/{target} 保持非递归展开。空格、中文及 shell 元字符不改变参数边界。

执行面板由 Workbench 主组件统一持有，浏览器和编辑器工具栏共用；上下文在预览时冻结。关闭弹层不终止任务，查看执行结果按钮可恢复，查看本身不重复执行。capture 由主窗口独有的原生服务启动，后台读取两个管道、等待并回收进程；400ms 串行轮询，不使用虚假百分比，显示耗时和接收字节数。读取失败重试，不误报任务失败或已完成。每个输出通道只保留末尾 128KiB，最多8个未结束/未关闭输出的任务，最多32条内存记录。结果不持久化、不自动重放。详细输出可直接选择复制。

终止只针对被启动的当前进程，不保证终止其后代。主窗口关闭前阻止仍运行的捕获任务，用户可返回结果终止或等待；已退出但后代仍持有管道的情况显示“等待输出关闭”，不阻止应用退出。launch 独立应用仍可继续运行，不将 PID 当成任务成功退出。Web 可配置工具，但不执行本机命令。

### 独立授权目录管理与固定标签（2026-11-11）

工作台工具栏新增“管理授权目录”入口，宿主以可选 revokeRoot 能力暴露移除服务；Nine Rings 继续沿用本地文件树的原入口。撤销只按 rootId 处理，清理该身份在活动/停放/已关闭标签历史中的引用；父、子目录另行授权的两个身份不互相删除，也不增加磁盘路径拒绝规则。当前行没有其它历史时回退仍有效授权，全部移除后保留空目录页。操作队列忙时不可撤销，处理期间阻止关闭管理弹层，失败可重试；成功删除条目后焦点回到管理弹层以支持立即 Esc。恢复草稿保留，不删除磁盘内容，不更改系统隐私权限。

原生撤销先写授权记录，再从内存移除对应 ID；写入失败不先清空内存授权。共享文件服务 API 和 IPC 字段不变，父/子授权的独立读取与重启恢复有原生测试覆盖。固定标签的模型接口新增可选确认参数，原调用默认仍保护固定项；共享菜单在单个/批量关闭涉及固定项时显示确认。最后固定项关闭后生成空白标签保证栏结构有效；恢复仍生成新身份。右键取消默认文本选择，CSS 与 WebKit 前缀统一禁止目录标签文本被选中，已有编辑器正文选区不被清除。

File Workbench 的 PNG/ICO/ICNS 与网页 favicon 独立存放在 native/file-workbench/src-tauri/icons；源图为用户指定的 FKFl4.jpg。Nine Rings 的 src-tauri/icons 和其配置不变，避免共享图标路径引起联动替换。

### 列表缩减后的视口一致性（2026-11-11）

大量删除后刷新可能保留旧scrollTop，旧值超过新列表可滚动范围。浏览器把DOM滚动值夹紧至0时不一定发出scroll事件，而旧虚拟窗口用最大nodes.length-1兜底，只渲染最后一个条目。重新加载列表也必须按结果数量和真实容器高度夹紧请求位置，并在layout effect同步DOM与虚拟窗口，不能依赖下一帧或scroll事件纠正；保存的浏览位置同步更新。虚拟窗口的起点上限至少保留一屏条目，列表少于一屏时完整渲染。自动刷新仍按现有可见项身份锚定，手动刷新和操作后刷新不改变文件排序及分页语义。

### 固定标签锚点与可选限制（2026-11-11）

版本2状态新增可选anchor(rootId/node/label/missing)、restrictToAnchor与returnToAnchor；旧固定项按有效当前路径迁移。固定名不跟随浏览路径变化，默认自由导航；只在显式返回、或开启自动返回后从其它标签切入时回到锚点，再次点击活动标签不导航以保留双击关闭。限制子树为独立选项，中央updateBrowserTab校验身份与路径段边界，所有更新入口遵守同一限制；常规路径入口给出新建标签/关闭限制的提示。Alt+Home只在列表获得焦点时处理，不接管编辑器/输入框。

标签当前路径与锚点分开保存；新增/恢复未固定标签不继承锚点。移动/改名协调锚点路径，删除/撤销授权保留失效标记并禁用返回/限制配置，不静默改为新的授权身份。活动、停放与关闭记录沿用同一协调流程。菜单复用NotesContextMenu的可选checked字段，原菜单项角色及行为保持不变，新增选项使用menuitemcheckbox。
