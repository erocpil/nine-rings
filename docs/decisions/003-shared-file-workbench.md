# 共享双栏核心与独立应用宿主

日期：2026-11-09。状态：用户已确认方向，分批实施。

## 背景与选择

双栏浏览已具备导航、比较、预览及安全操作能力，需要逐步成为独立软件。用户要求两款软件的核心功能出自同一套代码。当前插件仍直接依赖 Nine Rings 的主视图、最近文件、会话、授权及设置，不能通过复制组件获得可靠的独立产品。

选择同仓库共享核心、分别装配宿主。备选的长期复制分支会产生修复与安全规则分叉；把完整 Nine Rings 换一套外壳则继续带入数据库文档和同步生命周期。先抽离必要接口，再建立独立入口，避免先搬目录或重写已有行为。

## 第一批边界

- 共享模型、路径检查、目录提供者、操作执行器及串行队列。浏览器核心不直接访问主区域、插件全局实例或浏览器存储。
- 宿主提供授权断言、文件服务、打开文件、草稿检查、操作租约、移动/删除后的会话协调、变更通知及可选的结果记录。
- 授权、草稿检查和会话协调都是必需接口，不能以默认空函数绕过。可选 UI 持久化仍由原适配器处理，不得把已完成的磁盘操作误报为可直接重试。
- Nine Rings 旧入口保持签名与行为，通过适配器委托共享实现；现有调用方不需要一次迁移。纯比较/刷新模块和展示控件只依赖提供者契约。
- 第一批不新增安装包、目录授权、写权限或持久化格式。独立宿主、原生共享库及交付属于后续批次，不能将接口解耦称为独立软件已完成。

## 后续顺序

1. 完成上述共享核心及宿主契约，保留原插件回归，验证两个隔离宿主使用同一执行器。
2. 建立独立入口，复用浏览组件、文件服务和查看器；独立管理设置、授权、未保存内容及退出流程。
3. 整理共享原生文件服务与三平台打包，使用独立应用标识、数据目录、更新通道和产物。
4. 在两种宿主运行相同功能契约；核心缺陷只修复一次。随后按实际需求完善产品体验。

## 验证与监控

重点保持授权撤回后拒绝迟到结果、操作前与写入前重新检查草稿、租约释放、已发布但收尾不确定时暂停、队列不重放成功项、移动后打开文件身份一致。共享核心不得存在对 Nine Rings 主视图或插件单例的运行时依赖。

通过既有单元测试、可替换宿主契约测试、Chromium/WebKit 插件交互、类型/lint 和生产构建验证。记录新增核心覆盖率和原插件回归结果。独立启动耗时、内存及包体积在独立入口形成后测量，当前不承诺数值。
