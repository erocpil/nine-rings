# 双栏文件浏览的宿主与插件边界

日期：2026-11-06。状态：已采纳，三批基础能力已实现；原生磁盘授权、大目录性能及跨平台 GUI 待现场验收。

现有文件树适合导航和编辑入口，但无法承载两个独立目录的对照浏览。备选方案为在 App 直接实现文件管理器、开放第三方任意视图、或扩展可信内置本地文件插件。采用第三种：复用授权文件服务与主区域保存门禁，宿主只增加受限 renderer 和可保留的浏览返回目标，左右栏逻辑留在插件视图中。

先交付浏览、导航、状态恢复与既有查看器接入，再扩展跨栏写入及效率工具。首批不改变文档存储或同步格式。验证关注旧请求丢弃、停用清理、保存失败仍保留原视图、只渲染可视条目及浏览往返不丢位置。完整计划见[双栏文件浏览](../plugins/plugin-dual-pane-browser.md)。

效率批次使用版本化设备标签状态，复用原授权读取/搜索与排他写入规则；快速预览、当前层元信息比较与批量命名计划均由受限宿主组件呈现。目录比较不代表递归正文认证，批量操作不代表整批原子事务，其它文件提供者待明确需求。

2026-11-07 补充：双栏浏览独立为可信内置插件，活动栏直接进入，不创建空分栏。相比继续嵌入本地文件或复制文件服务，采用独立贡献所有权加共享宿主资源持有计数；便于独立启停，又避免授权/会话被另一插件清理。原浏览设备状态不迁移，只有启用偏好一次性继承。需验证两种停用顺序、总开关撤回、浏览往返和独立打开文件。后续优化计划不因拆分而提前开放额外文件权限。
