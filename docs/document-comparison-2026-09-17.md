# 文档对比与 Pull 冲突处理

## 使用方式

- 桌面文档树右键文档 → **与另一文档比较…**，选择第二篇文档。可比较任意两篇文档，包括同步产生的冲突副本。
- 桌面/手机文档树进入批量选择，选中恰好两篇文档 → 工具栏 **比较所选文档（⇄）**。工具较多时横向滚动工具栏。
- Pull 预检中的 **双方冲突** 可逐篇查看本地/远端预览和逐行差异，再选择 **都保留 / 仅保留本地 / 仅保留远端**；点击安全合并后才生效。
- 默认都保留：远端使用原 UUID，本地另存为新的冲突副本。单边保留会二次确认；忽略远端的文档优先保留本地，不执行该篇冲突选项。全量覆盖仍是独立的危险操作，不使用这些选择。

## 对比与预览范围

- 正文按规范化 Markdown 逐行对比，另有完整正文结构和标题/路径/属性差异视图；Markdown 相同不代表排版、字体、书签或元数据相同。
- 静态预览保留标题、段落、列表及任务状态、引用、代码和表格；不挂载可编辑正文，不生成保存事务。
- 图片显示占位提示，不自动请求外部资源；链接仅显示，不在预览中执行。加密正文不自动解密、不显示为“相同”，只允许对比外部属性。
- 长文档预览和差异逐批展开，明确提示剩余数量。默认仅列变更行，可勾选显示相同行。逐行算法有计算预算；大范围变更退化为整段移除/新增，不省略正文。

## 安全与交互边界

- 每个显式冲突选择绑定预览时双方的规范化文档内容/属性；执行前不一致则中止，要求重新预检。下载结束后重新读取本地快照，避免以下载前的旧内容合并。
- 这不是普通编辑的跨窗口事务锁。恢复前仍应关闭其它编辑窗口，不能宣称能隔离导入期间的所有并发写入。
- 日常待办页面、模板及加密路径的既有安全合并规则不变。本轮选择作用于 notes 中的文档/随笔冲突。
- 菜单通过 Portal 放到 body，避免被分栏的 transform/overflow 裁剪；保留视觉视口避让，并在视口调整时关闭。桌面悬浮分栏识别菜单交互归属，不在操作菜单时消失。
- 手机抽屉把 Esc 交给前景菜单/对比弹窗处理；长按之后的新点击不再被前一次长按的兼容点击抑制误吞。
- 独立对比弹窗按需加载，展示打开时读取的快照；需要最新内容时重新打开。关闭弹窗不修改任何文档。

## 验证

- 单元测试：三种保留方式、默认安全副本、忽略优先、版本变化拒绝、基线变化时保持显式选择、格式化内容完整保留、加密预览隔离；逐行差异无损性及大规模降级。
- 浏览器测试：菜单越过分栏后仍可命中、独立/批量对比入口、格式化 Pull 预览、三种选择实际导入结果、过期选择不写入；复用分栏悬停及文档树移动/长按回归。
- iPhone PWA、macOS/Windows 原生窗口中的真实鼠标、触控和窗口缩放仍需真机验收。
