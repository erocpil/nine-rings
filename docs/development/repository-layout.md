# 仓库目录与维护约定

## 分类原则

按职责建立入口，不以文件数量决定架构拆分。移动只调整路径及引用，行为变更独立验证。文件名尽量保持稳定；保留历史文档和诊断脚本时明确其状态，避免把实验实现当成产品代码。

| 区域 | 归属 |
| --- | --- |
| `src/` | 运行时前端；组件、hooks、领域模块按实际职责逐步归组 |
| `src-tauri/`、`flutter_app/` | 原生宿主及另一客户端的独立构建边界 |
| `build-plugins/` | Vite 构建插件，与 `src/lib/plugin-system/` 的应用插件宿主分开 |
| `schema/` | 共享模型、生成器及声明式包规范 |
| `tests/` | 脚本测试、Vitest 单元测试及数据夹具 |
| `e2e/` | 按功能分组的浏览器测试，见[测试目录](../../e2e/README.md) |
| `scripts/` | 构建、验证、打包及维护入口；旧实验见 diagnostics/legacy |
| `docs/` | [文档导航](../README.md)，当前契约、计划、验证报告和归档分开 |
| `tools/`、`.local-tools/` | 用户工具与隔离环境，已忽略；不清理或提交用户内容 |

## 迁移检查

文档需更新链接、README、AGENTS 和脚本中的路径。验证报告保留原提交、执行环境及历史状态，不因目录迁移改写验证结论。

测试发现递归扫描 e2e，CI 使用唯一文件名匹配 `**/<name>.spec.ts`；同名文件会被拒绝。对迁移前后的 Playwright JSON 清单比较文件名与用例名，数量和语义必须一致；生产、诊断和 Reading 所有权不变。新路径的直接改动应进入 affected 集，共享 helper 和构建插件仍触发完整回归。

生产代码按依赖边界逐步归组。此次仅明确构建插件边界，保留编辑器、会话、存储等现有模块位置；后续搬动应逐模块检查静态导入、动态加载、Worker URL、mock、构建分包、CSP/PWA 和跨语言接口。

## 2026-11-06 整理与验证

依次分类 123 份原 docs 根目录文档、331 份浏览器测试，更新仓库内的文档链接、命令、CI 路径及相对导入。四份 Vite 插件迁至 build-plugins，四份早期手动脚本迁至 scripts/diagnostics/legacy；根目录构建配置和正式静态服务入口保留。已有有效相对文档链接核对 473 处，迁移未造成断链。

CI 测试选择器以唯一 basename 作为稳定身份，递归发现并拒绝重名；测试覆盖嵌套目录、重名拒绝、新路径的 changed-spec 选择和构建插件改动触发全量。所有默认用例清单由 Playwright JSON 核对，迁移前后均为 1581 项，文件名及用例名称集合一致。计数一致只证明发现范围，不证明所有运行行为。

运行验证：首次代表组 7 passed、3 failed，定位到插件夹具的目录 URL 在迁移时丢失末尾斜线；修复三处目录 URL 后，扩大代表组 Chromium/WebKit 各 17/17 passed。生产/PWA 门禁 20/20 passed，包含离线启动、更新、CSP/WASM 和工具栏；生产构建通过。最终完整 npm run check 通过，Vitest 220 文件、2465 项，IPC 契约通过，覆盖率门槛不变。未重新运行全部 1581 项默认 E2E，也未运行原生 GUI 验收。

影响结论：已验证路径发现、引用、代表运行及构建边界，没有发现迁移引入的剩余回归；全套浏览器执行和真实原生行为仍未由本批证明。后续生产模块归组应按职责独立推进，不把此次构建工具整理当作整个 src 的重构完成。
