# 跨端优化分批计划

## 第一批：全局搜索一致性

状态：实现及相关单测、Chromium/WebKit 搜索分页回归通过。

- 全局搜索使用共享 NoteSearchIndex；Tauri/Web/PWA 均优先 Worker，失败时分批在本地建立相同索引。
- 候选来自全部未删除随笔与文档，不再将两套搜索结果直接拼接。隐藏随笔时不在界面展示随笔结果。
- NFKC、非区域相关小写化、空白分词；全部词必须命中，允许分散在标题、正文、路径、标签、概念中。标点按普通字符处理，不解释 SQL/FTS 语法。
- 排序：完整标题、标题前缀、标题包含、其它命中；同档按置顶、更新时间倒序、ID 升序，最后一级不依赖系统区域或数据库读取顺序。
- 加密正文及其残留搜索文本永不参与索引；公开标题和路径可检索。
- 不截断候选；沿用结果面板每次 80 条的“显示更多”。这是显示分页，不是数据库分页。
- 首次搜索读取全量候选并建立 Worker 索引，后续普通编辑增量更新；移动、回收站恢复、批量删除、历史恢复等重置索引。Worker 失败时重新读取，避免缓存过期。
- 原生快捷记录事件及主窗口重新获得焦点时重置索引；文档列表内全局搜索按钮不再受旧的“仅移动端显示”样式限制。
- 保留旧适配器 FTS/LIKE 命令；本批统一的是全局搜索，不声称全部低层查询和文档列表筛选都已改用此规则。

验收：中文、多词、全半角、标题/路径/标签、稳定排序、超过 80 条、Worker 故障与缺失、加密正文、移动/删除/恢复。覆盖真实 Chromium/WebKit Worker；Tauri 运行时分支由自动化模拟，原生 WebView2 仍需真机验证。

## 第二批：回归矩阵和 Windows 验收

- 收敛普通/专注、编辑/只读、完整/局部渲染的核心测试入口。
- 改善桌面文档列表入口的可发现性：当前须先隐藏文档树，顶部才显示“文档视图”文件夹按钮；同时复核隐藏搜索框的键盘快捷键。
- Windows 安装包验证首次打开、点击跳动、只读粘贴、富文本剪贴板、文件对话框。
- 明确区分代码/浏览器测试与原生真机证据；环境不可用时保留待验收项。

## 第三批：长文档与搜索性能

- 记录首次打开、目录、高亮、切换文档、首次索引与热搜索的耗时和数据规模。
- 根据测量结果优化长任务；优先考虑分批读取精简搜索记录、索引更新合并、结果分页传输。
- 本批新增的全量候选加载在大资料库上的内存与 IPC 成本必须测量，不能仅凭桌面设备性能假设可忽略。

## 第四批：备份与图片恢复体验

- 汇总缺失图片、相关文档、来源设备和恢复建议。
- 完善导入预览、覆盖范围提示和失败重试。

## 第五批：界面细节收敛

- 统一弹层间距、按钮状态、空列表和错误提示，不重新调整主要布局。
- 截图反馈优先处理：文档列表筛选改为路径整行、类型/标签双列、排序/方向双列；显示字段默认折叠。鼠标端缩短顶部工具栏、筛选项和路径选择框，触屏保留原点击高度。

各批独立验证后交付；不能用某一批的完成代表所有跨端问题已解决。
