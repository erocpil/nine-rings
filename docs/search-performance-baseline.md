# 搜索与编辑器性能基线（2026-09-09）

## 测量范围

Linux 容器、Playwright Chromium、Vite 开发服务器、1280×800 初始视口；不是 Windows WebView2 或 iOS 真机数据。性能数字只供同环境比较，不设置固定毫秒数作为 CI 门槛。

搜索使用 5,000 篇合成文档，每篇基础正文 3,640 字符，另加唯一检索词。适配器从内存返回文档，**不包含 SQLite/IndexedDB 读取或原生 IPC 成本**。测量覆盖摘要准备、Worker 传输/构建及查询。每个版本连续运行三轮，每轮重建 Worker；第一轮含开发服务器 Worker 加载预热开销。热查询只命中一篇，大范围查询命中全部 5,000 篇。

主线程响应指标是建索引期间的最大 requestAnimationFrame 间隔，包含调度、布局、GC 等因素，不能直接视作某个函数的执行耗时。

## 搜索结果

| 轮次 | 优化前冷启动 ms | 分批后冷启动 ms | 优化前最大帧间隔 ms | 分批后最大帧间隔 ms |
| --- | ---: | ---: | ---: | ---: |
| 1 | 1124.5 | 820.3 | 215.7 | 36.1 |
| 2 | 570.4 | 499.2 | 76.4 | 18.6 |
| 3 | 494.1 | 505.1 | 59.6 | 19.1 |

冷启动中位数：570.4 → 505.1ms。单篇热查询优化前 14.0–20.6ms，分批后 14.4–20.2ms；全量命中查询优化前 103.8–131.9ms，分批后 90.1–127.9ms。查询算法没有改变，后两组差异不应归因于本次建索引优化。

另一次与单测并行的试跑出现明显耗时波动，未用于表中比较；以上比较运行时没有同时启动其它测试/构建。三轮样本仍很少，不据此承诺固定性能提升比例。

## 实现

- 将一次性摘要整理及 Worker 发送改为每批最多 250 篇；首批清空并重建，后续批次追加。
- 等待每一批的 Worker 回应，避免同时排队整个资料库的数据，给主线程处理输入和绘制的机会。
- 索引完全建立后才返回查询结果，不向用户显示半成品结果或截断结果。
- 构建携带代次标识：加密、导入或其它重置发生后，旧构建不能继续追加数据，也不能销毁新索引。
- 保留现有加密正文脱敏、排序、增量更新和无 Worker 降级语义。
- 回归中补齐搜索退出的任务取消：点击结果或关闭搜索时清除仍在防抖队列中的查询，避免结果页稍后再次出现；原有已发出请求的失效判断继续保留。

仍未解决：初次存储读取仍会取回完整文档；单篇超大正文仍可能形成长任务；大量匹配摘要仍一次性回传。后续优先测真实存储读取/IPC，再考虑精简字段、分页读取及结果分批传输。

## 长文档基线

修复旧测试入口后，使用合成 Markdown 粘贴进入完整编辑器，再切换到 390×852 的只读专注模式，以 41 次脚本滚动采样：

| 块数 | 同步粘贴 ms | 粘贴至布局就绪 ms | 滚动帧间隔 P95 ms | 最大帧间隔 ms | DOM 元素数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 300 | 477.1 | 543.0 | 17.3 | 17.4 | 1170 |
| 1500 | 2290.4 | 2404.9 | 17.3 | 20.2 | 5850 |

这是每种规模一次的基线，不是优化前后对比。粘贴测量包含解析、事务和布局等工作，不等同于打开已有文档；脚本滚动也不能替代真实触摸惯性滚动。当前样本提示应优先进一步拆分大批量粘贴/初始化成本，尚不能定位到具体函数。目录索引和代码高亮没有在本轮单独计时，继续列为待测。

## 第二个性能子批次：连续文本解析（2026-09-09）

Markdown 行内解析原先为每个普通字符创建临时片段，并逐个合并属性。现在连续普通文本一次输出，到图片、链接、粗体、斜体或行内代码的潜在起始符才重新判断语法。没有改变粘贴事务、撤销分组、目录索引或折叠方式，也没有异步插入半成品文档。

同一 1,500 块合成 Markdown，在 Node/tsx 中单独调用 `mdToDelta` 三轮：修改前约 294.1 / 161.2 / 156.6ms，修改后约 47.6 / 44.5 / 22.6ms。该数据不包含编辑器和 DOM，不可视作整个粘贴过程的提升比例。

Chromium 同环境、无其它测试并行，每个规模各一次的新测量：

| 块数 | 同步粘贴修改前 → 后 ms | 布局就绪修改前 → 后 ms | 修改后 dispatch ms | 修改后 dispatch 之外 ms |
| --- | ---: | ---: | ---: | ---: |
| 300 | 619.3 → 391.2 | 679.9 → 449.1 | 366.9 | 24.3 |
| 1500 | 2171.7 → 1931.3 | 2292.4 → 2033.4 | 1862.9 | 68.4 |

修改后的基准增加临时 `view.dispatch` 计时，完成后恢复原函数；两个规模同步粘贴均只有一次 dispatch。dispatch 包含状态应用、插件、DOM 更新和同步回调，不等同于纯 DOM 时间；dispatch 之外还包含解析、转换、命令准备等，不能当作纯解析耗时。单次样本受运行时预热影响，不承诺固定提升比例。DOM 数量和滚动高度保持一致，滚动帧间隔 P95 仍约 17ms。

下一步应继续拆分 dispatch 内部成本，而不是继续假定 Markdown 解析是主要瓶颈；真实已有文档打开耗时仍待单独测量。本轮补充长 Unicode 文本、空格/Tab、混合行内语法与无效标记单测，以及大段粘贴的结构、单步撤销重做和光标回归。

## 复现命令

```sh
NR_SEARCH_BENCHMARK=1 npx playwright test e2e/search-performance.spec.ts --workers=1
NR_EDITOR_BENCHMARK=1 npx playwright test e2e/editor-rendering-benchmark.spec.ts --grep '300 块|1500 块' --workers=1
```

两个基准均显式启用，使用隔离浏览器中的合成数据，不读取用户资料库。长文档基准已改用文档 API 创建测试内容，不再依赖隐藏的随笔入口。
