# 文档密码加密（待实现）

状态：需求与安全边界已确认，尚未实现，也未宣称当前文档已受密码保护。

## 交互与边界

- 指定文档独立设置密码；切换离开后重新打开须重新验证，不在本地持久化密码或解密密钥。
- 正文、正文元数据（含书签片段）、图片和历史正文不能留下可通过普通读取接口访问的明文旁路。现有明文备份、Git 历史和共享图片需单独说明，不能宣称新加密会追溯抹除它们。
- 本地存储、跨端同步和备份应保留密文；密码遗失不能找回。
- 标题、路径作为明确公开的定位信息。标签、概念等公开元数据的范围须在设置密码前说明。

## 搜索硬性要求

用户追加要求：**任何形式的搜索都不展示加密正文内容，即使该文档当前已经解锁。**

- 不向全文搜索索引、Worker 或持久化搜索缓存写入解密正文；设置密码后必须失效已有明文索引。
- 搜索结果、快速切换、相关文档推荐、概念页、预览摘要、集中书签、版本预览等不得泄露正文、命中上下文、书签名称/片段等受保护内容。
- 可通过明确公开的标题/路径定位，加密状态可见，打开正文仍经验证。全局搜索不能因为当前编辑器解锁而自动扩展权限。
- 当前已解锁编辑器内部查找需要与跨文档搜索隔离，不能将查找结果带回全局界面或持久化。
- 验收覆盖：加密前已搜索、加密后搜索、当前文档已解锁、切换离开、刷新、第二标签页、备份恢复/同步、桌面版和 PWA。

## 路径加密与空目录持久化

- 除单文档保护外，支持为一个路径设置共享密码，递归覆盖所有后代文档。新建、导入、移动和恢复文档进入受保护路径时，必须继承保护，不能只处理设置密码时已存在的文档。
- 加密路径必须拥有独立、稳定标识的持久化记录；现有“从文档推导目录”的方式无法满足这一要求。目录记录包括规范化路径和加密参数，不保存明文密码。
- 删除其所有后代文档及子目录后，该加密路径本身仍显示为空的加密目录。普通空路径继续沿用现有自动消失行为。
- 改名或移动路径须保留目录保护身份；显式删除加密目录须独立确认，不能因删除最后一篇文档或清理回收站而连带删除。
- 路径保护记录须与文档密文一起导出、同步和恢复，包括无文档的空加密目录。合并冲突、旧客户端不支持的情形应明确报错，不能静默丢失目录记录。
- 跨边界移动须验证相应保护身份，原子重加密；移出受保护路径不能隐式移除保护或输出明文。
- 第一版建议禁止重叠/嵌套的独立密码策略；已有单篇密码文档进入加密路径时，应验证原密码后转换为路径密码，不默默保留两个密码来源。此类转换失败必须全部回滚。
- 密钥派生应绑定稳定保护身份，而不是可改名的路径字符串；删除后同名重建的目录不能意外复用旧身份。
- 用户仍可通过公开路径定位文档，但解锁目录不能使其内容进入全局搜索、摘要、集中书签或其他旁路。

验收增加：三级子路径共用密码、新建/导入继承、跨目录移动/改名、不同保护冲突、最后子文档删除、回收站清理、空目录重启保留、空目录备份/同步往返、并发写入失败回滚。

## 实施前需完成的技术检查

1. 加密包格式、密码派生、随机盐/nonce、完整性验证与错误处理。
2. 当前正文和历史版本原子转换，失败不破坏原数据；并发编辑/恢复不能把密文覆盖成明文。
3. 图片共享及历史副本处理；禁止只隐藏 UI 而留下可导出的明文。
4. 自动保存、紧急恢复文件、编辑器会话缓存、跨窗口与各端旧版本兼容。

技术参考：[Web Crypto AES-GCM](https://developer.mozilla.org/en-US/docs/Web/API/AesGcmParams)、[OWASP 密码派生建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。采用标准 API 并不自动代表整个应用的加密设计已经安全，仍须逐项验证上述边界。
