# EPUB 重开与文件存储（2026-09-11）

手机 PWA 重开出现 `The object can not be found here.`。之前仅增加解压降级，没有验证异常所处阶段；不能据此断言是 Worker 回调丢失。

File API 定义的 `NotFoundError` 包括 Blob 底层资源在读取时不可用的情况（[规范](https://www.w3.org/TR/FileAPI/#errorsAndExceptions)）。原实现把用户选择的 File 存入 IndexedDB 的 books 记录，保存进度又重写包含原文件和封面的整个记录。错误与这一读取路径相符，但仍需要 iPhone 真机验证，浏览器测试无法证明原设备的存储状态。

## 当前行为

- EPUB 数据库 v3 增加 files store，以 ArrayBuffer 保存原文件，以字节数组保存封面。books 只保存元数据与阅读进度。
- 旧版 Blob 在第一次成功读取时迁移。先完成文件读取，再在一个事务中写入字节并移除旧字段；迁移时重新读取最新进度，避免覆盖其它窗口的更新。读取失败不删除旧数据。
- 同一书籍的打开、迁移、保存、关闭后的缓存保留和删除按调用顺序处理。失败不会阻断后续操作。
- 缓存只保存解压后的不可变书籍数据，最近使用/关闭后保留两分钟，最多三本且总计不超过 64 MiB；超大书不进入缓存。每次打开仍读取最新进度、书签与批注。
- iframe 和对象 URL 由各阅读实例独立持有和销毁；切换书籍创建新实例，重复点击关闭只保存一次，旧实例关闭回调不能关闭后续实例。
- 解压超时终止异步任务并显示可重试错误，不在主线程同时启动另一轮解压。阶段错误区分文件读取、内容解析和章节准备。
- 单书阅读备份接口继续返回内存 Blob 用于指纹，不把二进制数据放进 JSON。删除书籍同时删除原文件并失效缓存。

## 验证

`tests/unit/epub-book-cache.test.ts` 覆盖共享加载、过期、容量淘汰、失败重试与失效任务，及长时间阅读后关闭的保留窗口。

`e2e/epub-reopen.spec.ts` 覆盖并发打开与顺序保存、冷启动、封面、备份恢复、删除、v2 迁移、模拟 NotFoundError 后保留数据，以及手机界面四轮连续关闭重开。使用 Chromium 和 WebKit 执行。

已丢失底层字节的旧 Blob 无法靠新缓存恢复；保留原记录并提示用户重试或从原文件重新导入，不将这种情况报告为“压缩包损坏”。
