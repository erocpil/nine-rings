# 桌面启动、退出与异常恢复

适用于 macOS、Windows、Linux Tauri；Web/PWA 不读取原生会话文件。

## 会话检测

主实例初始化时在应用数据目录写入 `desktop-session.json`，包含会话 ID、PID、版本、启动/更新时间、阶段和故障信息，不包含正文。记录通过临时文件、同步写入和重命名发布。第二实例由 single-instance 插件处理，不替换主实例的会话记录。

阶段包括启动、运行、数据库只读保护、退出前数据库合并、资源清理、退出请求和正常退出事件。前次记录未到正常退出事件、有异常信息或记录无法读取/解析时，判定为需要检查。首次写入中断留下临时文件也会提示检查。

强制结束、崩溃或断电不依赖退出处理器：下次启动读取未完成的持久记录即可检测。但首次升级使用本机制前的历史退出无法追溯。

## 检查与恢复

每次启动打开原数据库，由 SQLite 恢复可用的已提交 WAL 事务，再执行 `quick_check` 和非阻塞的 PASSIVE checkpoint。展示实际 checkpoint 返回值，包括 busy、WAL 页数和合并页数。

数据库完整性检查失败时保持原文件，启用 SQLite `query_only`，跳过迁移并停止写入。通用查询的临时只读保护恢复连接原状态，不能解除异常保护。不会删除数据库、WAL、用户内容或重建一个空数据库。严重错误导致数据库无法打开时记录启动失败；应用可能无法进入界面，应保留数据库文件及日志排查。

自动恢复只覆盖已提交的数据，不保证恢复未保存的内存编辑。异常时显示可关闭的启动提示；设置 → 高级 → 启动与退出诊断展示当前状态、前次退出、修复结果、Windows 子进程保护状态、日志路径，并支持刷新和复制诊断。

## 退出与证据边界

确认退出的快捷键路径先等待前端保存完成，提示“本机已保存，正在清理并退出…”，随后合并 WAL、清理 Tauri 资源并请求退出，不增加固定等待。托盘退出保留既有路径，日志以 `source=tray` 区分；它不是前端保存握手完成的证据。

日志 `nine-rings-startup.log` 写入系统临时目录，包含完整时间、时区、PID、平台、会话、检查结果、checkpoint、清理耗时、退出请求和退出事件。日志可能被系统清理，会话检测依赖应用数据目录中的持久记录。

Windows 仅在 Job Object 的限制设置和进程分配均成功后报告子进程保护已启用，失败关闭临时句柄并记录原因。所有平台均记录退出过程；收到正常退出事件不代表操作系统已经释放全部子进程和文件锁。Windows/WebView2、Linux/WebKitGTK 的进程释放仍须真机外部观察，不能由即将退出的应用自行确认。

## 验证

Rust 回归覆盖未完成/正常会话、坏记录、退出异常、损坏数据库保护、查询不解除只读保护，以及子进程写入 WAL 后直接退出、父进程重新打开恢复已提交数据。浏览器通过 Tauri IPC 模拟验证诊断面板、启动提示与刷新；它不能替代原生进程和文件锁验证。
