# 手动增量同步（0.3.0）

更新于 2026-10-17。Web/PWA 与 Tauri 的 JavaScript 宿主正式开放格式 1 / 编码 1 的手动增量同步。旧版全量备份仍可使用；已有备份不会因升级自动切换。

## 先理解范围

这里的“增量”指逐实体比较、选择合并及维护本机接受基线：文档、模板、保护记录和已认证设置分别比较。远端仍保存完整、不可变的 JSON 快照，并非已经按文档拆分上传。删除传播、外置附件分片、后台自动同步、远端快照自动清理不在本版范围。远端缺少某个实体不会自动删除本机实体。

参与同一备份空间的 Web/桌面客户端必须升级到 0.3.0 或更高且支持该空间声明的特性。Flutter 尚未开放此协议，请暂停其对该空间的 Push/Pull，或使用独立的旧格式备份连接。不能只修改版本字符串或勾选确认来绕过能力认证。新客户端遇到未来协议/未知特性同样停止写入。

## 首次接入

1. 在设置的云端同步页配置 GitHub 备份仓库与路径，测试连接。仓库需要已有分支/提交；完全空白的 GitHub 仓库先通过原有备份流程初始化，或添加 README。
2. 点击“预检实体差异”。程序固定分支 HEAD，验证 Git 对象、控制文件、快照摘要与完整父链。未开启的空间还核验所有可达父提交，不能仅因没有本机基线就认定可以迁移。
3. 导出本地 JSON 备份并确认已经保存，选择该文件核验。核验绑定实际本机内容修订和当前审查，过期文件不能代替当前数据备份。
4. 确认所有参与设备已升级、最低版本及首次切换。已有旧快照时先审查差异并保存选择；空命名空间则审查首次发布的本机实体数量。
5. 点击“首次迁移并发布”。本机保存屏障完成后再次核验本机、远端 HEAD、备份与保护关系。快照、latest 指针和协议控制文件在同一个 Git 提交发布，分支只做非强制快进更新。

迁移后，见过协议的连接持久阻止旧格式发布；普通“导入 JSON”也不接受协议封装快照。换设备请通过增量审查接入，不要手动删除控制文件、修改 latest 或导入封装来绕过该边界。本机连接及协议事实不随备份传播，凭据不进入快照。

## 日常同步

每次先预检，再为不同的实体明确选择来源、忽略或处理冲突。选择草稿可恢复，但本机或远端变化会使旧审查失效。Push 使用冻结候选，Pull 只应用选定实体，未选中的本机文档和设置保持原样；相同内容使用单独的接受确认，不为无变化制造远端提交。

两台设备同时编辑同一实体会产生冲突。非强制发布只能有一个竞争提交进入分支；失败一方重新预检与合并，不能强推覆盖。两台设备的独立接受基线不通过导入复制。

## 中断与恢复

启动只读取未完成操作的摘要，不自动联网、重发或回滚，也不会为显示提示而加载完整正文。

- 发布结果不明：在设置中执行只读核验。检查冻结提交与当前远端的关系后确认结果，不重新发送 PATCH。进程重启后仍使用原冻结日志。
- 尚未触碰分支的 PREPARED / OBJECTS_READY，或明确被远端拒绝的 REJECTED：可二次确认取消，保留证据并标为 ABORTED，然后重新预检。UNKNOWN / PUBLISHING / CONFIRMING 不能用取消跳过核验。
- 首次发布在分支更新前中断：取消后允许在完整“从未启用”历史证据下重新准备；旧格式保护标记仍保留。已经观察到正式协议时绝不退回旧格式。
- Pull 应用确认丢失：核对实际存储与冻结目标，确认后补接受基线；不再执行一次导入。实际内容发生变化或证据损坏时停止，保留本机数据供处理。

操作提示可能要求重新预检、重新备份或处理原有恢复记录。这些检查用于避免把旧选择、过期解锁或未保存编辑当作新授权。

## 预算和性能

候选单快照最多 64 MiB；固定读取与冻结日志另外有各自预算，不能用压缩后大小绕过。超出或不受支持的正文会明确拒绝，不删字段、不静默格式化原文。初次大文件认证和历史核验可能耗时，界面确认不是自动后台同步。

设备私有缓存只保存已验证的不可变 Git 提交缺席证明及快照头摘要。缓存按空间和 Git SHA 绑定；当前固定提交中的文件仍必须存在且 SHA 匹配，最新正文仍完整校验。缓存上限 4096 条 / 2 MiB，不包含私有正文，不导出或同步；损坏、配额不足均回退完整读取。冷历史超出单次预算时预检停止，重复预检可复用已经核验的片段，未走完根或父提交不能发布。

## 验证边界

真实完整私有备份已通过候选认证和原生 SQLite 的导入、关闭重开、失败事务回滚。公开 fixture 用于真实 GitHub 双端发布/Pull、离线、竞争和进程重启恢复演练；测试只写新建隔离分支，未迁移用户备份。详细结果见[真实备份审计](sync-real-backup-audit.md)。实际 macOS Tauri GUI、Windows/Linux 真机与真实手机仍需各自补充验证，不能将浏览器验证称为这些设备的实际操作结果。


### 下载超时诊断（2026-10-17）

固定读取先从已验证的 Git tree 获取 Blob 原始字节数，再按 Base64 传输量计算下载预算（至少 120 秒，最多 600 秒）；元数据请求仍为 20 秒。预检、实体审查、发布前读取及恢复共用此策略，不能把 23 MB 的正文也限制为 20 秒。只读超时/网络失败最多重试一次同一 GET，HTTP 鉴权失败、限流、取消与解析错误不自动重试；写请求不使用这条重试路径。日志指出仓库、分支 HEAD、提交、目录或 Blob 阶段、通道和耗时；大 Blob 另外显示原文字节数与预算，不打印 Token 或正文。网络本身若仍不可达，应按失败阶段继续诊断，较长预算不代表联网保证。
