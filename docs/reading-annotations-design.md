# 只读文档阅读标注：详细设计与审查稿

状态：**阅读标注功能已暂时停用，等待设计审查；已有标注数据保留，不读取、不展示、不修改**。2026-10-20。

当前暂停由 `READING_ANNOTATIONS_ENABLED` 集中控制。恢复功能前，应先按本文完成事件链取证、权威位置映射和持久化边界审查；不要仅通过自动化用例恢复入口。

本稿依据当前代码编写，覆盖已有实现、已确认的设计缺陷和拟议方案。用户已报告 `v3c6eb78.20261020T033801` 及后续修复仍不能正常使用标注。浏览器自动化通过不足以证明 macOS Tauri 的实际故障已解决；本文不将“WebKit 清除选区”认定为已经查明的根因。

## 1. 产品目标与约束

只对**设置为只读、处于普通渲染视图或专注渲染视图的文档**开放创建标注。行为接近 PDF 的阅读高亮：

1. 用户通过正常单击拖动选择一段文字，右键选择“添加阅读高亮”。
2. 高亮可以没有附注；附注是可选的纯文本。
3. 指针进入高亮文字时显示已有附注及操作入口：修改附注、清空附注、删除高亮。
4. 清空附注保留高亮；删除高亮同时删除附注。
5. 全部高亮与普通书签共同汇总在“书签与标注”，使用不同图形、颜色和类型标签区分。
6. 点击汇总项定位到原文；必要时展开包含目标的折叠区域。
7. 不向 Markdown、Delta 正文或文档发布元信息插入标记，不改变原文的复制、导出结果。
8. 文档后来改为可编辑并发生编辑时，标注跟随原文字移动。**只有确认所标文字已经全部删除，才能自动删除对应标注**。
9. 正常的文本选中、拖选、复制和只读双击折叠继续可用。

“只读”限制标注的创建和管理入口，不意味着底层锚点可以停止跟随正文变更。导入、同步替换、版本恢复、源码修改都可能改变一份曾被标注的文档。

## 2. 当前实现：可从代码确认的事实

| `src/components/RenderedLinkMenu.tsx` | 外层链接右键事件捕获，也需要参加菜单优先级审查 |

当前完整渲染链路：

```text
DOM 原生选区
  → editor.view.posAtDOM(anchor/focus)
  → from/to 缓存
  → React 正文 contextmenu
  → 普通正文右键菜单中的标注操作
  → createReadingAnnotation
  → IndexedDB 写入完成
  → React annotations 状态
  → ProseMirror Decoration.inline
```

当前局部渲染链路：

```text
DOM 原生选区
  → data-reading-text-start/end 包裹元素
  → Range.toString().length 估算块内偏移
  → from/to 缓存
  → React 正文 contextmenu
  → 独立的 .reading-annotation-context
  → 同一个 IndexedDB 存储模块
  → React 分段 mark 高亮
```

### 2.2 当前存储

独立数据库 `nine_rings_reading_annotations`，版本 1，表 `annotations`，主键 `id`，按 `noteId` 建索引。记录包括：

```ts
interface ReadingAnnotation {
  id: string;
  noteId: string;
  from: number;       // ProseMirror 文档位置，不是 DOM 字符偏移
  to: number;
  exact: string;     // 所标原文
  prefix: string;    // 前文，最多 32 个 UTF-16 单元
  suffix: string;    // 后文，最多 32 个 UTF-16 单元
  note: string;
  createdAt: string;
  updatedAt: string;
}
```

这套记录不是普通书签的文档元数据。当前独立存储本身**不等于已接入全量导出、增量备份、跨端同步或 Tauri 主数据库**；不能向用户承诺这些标注随 GitHub Push 备份。实现阶段必须逐项核对数据通路。

### 2.3 最近一次修复的实际范围

`dbafbb17` 增加了选区变化、指针释放和键盘选区变化时的范围缓存，尝试在右键事件发生时原生选区已经消失的情况下继续提供入口。它没有证明真实故障就是选区丢失，也没有完整诊断菜单是否被截获、关闭、裁剪或定位到视口之外。

自动化覆盖完整/局部渲染中的高亮新增、附注修改/清空/删除、书签汇总、正文不变及删除目标文字后的清理；另有真实拖选后主动清空 DOM 选区再右键的回归。后一个用例验证的是缓存回退能力，**不证明真实 Tauri 交互经过了同一事件链路**。

## 3. 已确认的设计问题与尚未确认的故障点

### 3.1 已确认的问题

- **创建入口分裂。** 完整视图使用普通正文菜单，局部视图使用专用标注菜单。两边的触发、关闭、定位和焦点没有同一份交互契约。
- **选区缓存缺少身份。** 当前缓存只有 from/to，没有文档修订、活动视图实例、原文校验及失效原因。不能把“有缓存”直接当成“有合法的本次选区”。
- **局部渲染的 DOM 长度不一定等于模型长度。** 当前 `Range.toString().length` 会受到中英文间距等展示文本的影响。简单英文用例不能认证中文混排、样式拆分及跨块选区。
- **丢失锚点会被当成删除。** 当前重定位算法在找不到完整 exact，或多个位置得分相同的时候直接返回删除 ID。部分文字被改写、同文重复、视图转换不一致都可能触发；这不符合“全部删除才自动删除”。
- **纯状态计算中带有持久化副作用。** ProseMirror 插件的 apply 分支会异步删除存储，异常被忽略，难以控制交易回放、失败恢复和用户反馈。
- **持久化边界没有完整定义。** 独立 IndexedDB 尚缺统一的同步、加密、文档删除和全量覆盖策略。受保护文档的原文摘录若直接写入这里会产生明文副本。
- **错误可见性不足。** 部分失败仅写日志，用户看不到当前到底停在选区识别、菜单、映射还是存储阶段。

### 3.2 待验证的故障点

| 假设 | 需要取得的证据 |
| --- | --- |
| 右键时原生选区被清除 | 真实 Tauri 中 pointerdown、selectionchange、contextmenu 的顺序与选区摘要 |
| contextmenu 没有到达正文处理器 | 原生捕获、React 捕获与冒泡的同一事件追踪 |
| 链接、块菜单等提前截获 | 事件目标所属区域、哪个处理器调用了 preventDefault/stopPropagation |
| 菜单立即被关闭 | 打开与关闭时间、关闭来源、期间的 scroll/blur/mousedown |
| 菜单存在但不可见 | 菜单实际 rect、visualViewport、遮挡元素及祖先 stacking/containing block |
| 选区映射失败或得到空文本 | DOM 端点到模型端点的映射结果、校验结果及失败代码 |
| 选择发生在派生内容中 | Flow、公式、Mermaid、自动目录等实际 DOM 所属渲染器 |

以上均不能在未取证前写成已解决的根因。

## 4. 拟议架构：一个控制器，多个选区适配器

复用已有正文权威模型。新增统一的阅读标注控制器，负责选区状态、右键仲裁、创建、管理、持久化及可观测性；完整渲染和局部渲染只负责 DOM 与模型的映射和高亮展示。

```text
完整渲染适配器 ─┐                    ┌─ 菜单 / 附注气泡
                ├─ 阅读标注控制器 ───┼─ 书签与标注汇总
局部渲染适配器 ─┘                    └─ 标注存储服务
                          ↑
                     文档修订与交易映射
```

### 4.1 选区快照

```ts
interface ReadingSelectionSnapshot {
  documentId: string;
  revision: string;
  viewId: string;
  from: number;
  to: number;
  exact: string;
  rects: readonly DOMRectReadOnly[]; // 只在当前交互中使用，不持久化
  source: "pointer" | "keyboard";
  capturedAt: number;
}
```

快照来自属于当前活动正文的真实原生选区。创建前必须重新核对文档、修订、from/to 和 exact；同一交互中的原生选区暂时消失可以使用快照，不能跨文档或跨修订盲目复用。

主键盘/指针操作开始新的选择、点击别处、切换文档或视图、正文修订变化、退出只读时，让快照失效。打开菜单后，候选范围归菜单事务持有；鼠标点击菜单按钮导致 DOM 选区消失不应改变该范围。

不以固定毫秒超时作为正确性的依据。时间戳用于诊断和防止意外复用，身份与交互阶段才是主要判断条件。

### 4.2 状态机

| 状态 | 进入条件 | 可执行操作 | 退出条件 |
| --- | --- | --- | --- |
| idle | 当前没有合法选区 | 正常阅读、选择 | 识别到合法选区 |
| selected | 已捕获并校验快照 | 复制、右键 | 新选择、文档变化、打开菜单 |
| menu | 右键事务已持有快照 | 添加高亮、复制、取消 | 成功创建、Esc、点击外部 |
| saving | 提交标注存储事务 | 等待结果，防止重复提交 | 成功或可见错误 |
| highlighted | 已持久化并展示高亮 | 悬停、定位、删除 | 管理气泡、正文变更 |
| editing-note | 编辑附注草稿 | 保存、取消；输入框可正常编辑 | 保存成功或取消 |

完整与局部视图必须遵守同一状态机，不能各自添加不同的菜单关闭策略。

### 4.3 右键仲裁

优先级为：已有标注的管理操作 → 只读正文有效文本选区 → 链接操作 → 块操作或普通正文菜单。有效选区包含链接文字时，仍应可以标注，不被链接菜单抢走。图片、Mermaid SVG 等非正文文字区域不伪造文本选区。

同一次 contextmenu 只由一个控制器处理。先判定当前目标与选区，确定由应用接管后再阻止系统菜单。没有合法选区时，不应悄悄使用过去的范围创建标注；若用户当前确实有选中文字但无法映射，需要显示明确的不可标注原因。

建议第一阶段在统一正文菜单中提供清晰的“添加阅读高亮”，而非完整/局部两套不同菜单。菜单承载层与内容动作分开，避免再次把故障归结为是否开启自定义右键菜单。

### 4.4 菜单定位、焦点和关闭

- 菜单和气泡通过 Portal 放到统一的顶层浮层容器，避免编辑区祖先的 transform、overflow 或局部层级影响 fixed 定位。
- 以右键位置为首选锚点，读取真实菜单尺寸后按 visualViewport 四边收敛；右下角应向左上展开。
- 菜单打开后通过键盘可以操作；定位或聚焦菜单不修改已经捕获的文本范围。
- 第一次 Esc 只关闭当前标注菜单/附注编辑；下一次再按应用既有优先级处理其它界面。
- 菜单内部的指针、滚动、输入不触发“外部点击关闭”。正文主动滚动、切换文档可关闭菜单。
- 指针从高亮进入气泡允许短暂过渡；编辑附注期间不因 pointerleave 自动关闭。
- 保存失败保持草稿与菜单状态并显示原因；成功写入后才展示成功结果。

## 5. 文本位置映射与可支持区域

存储坐标统一使用权威 ProseMirror 文档位置，DOM 像素和浏览器生成的选择范围仅用于本次交互。

| 内容 | 拟议第一阶段支持范围 |
| --- | --- |
| 普通段落、标题、粗斜体、行内代码、链接文字 | 支持；样式分段不能改变字符位置 |
| 列表、引用、代码块中的实际文本 | 支持；保留换行与嵌套边界映射 |
| 表格 | 先支持同一单元格内的文本；跨单元格范围须额外认证 |
| 折叠内容 | 标注可存在；创建只针对实际可选内容；从汇总定位时展开目标 |
| 局部渲染 | 保留选择涉及的已挂载区域；未挂载内容不靠 DOM 猜位置 |
| Flow 展示文本 | 先提供明确不支持提示，待其派生 Markdown 到代码块源码的精确映射认证后开放 |
| Mermaid、图片、公式、自动生成的 /toc 条目 | 不按普通原文文本标注；不使用其派生 DOM 偏移冒充正文坐标 |

局部渲染适配器应输出显式的模型文字段到 DOM 文字段映射。中英文自动间距增加的展示字符必须映射为零宽的模型间隔；不能直接按渲染字符串长度累计。完整渲染的特殊 NodeView 也必须显式声明映射能力。

反向选择、多段样式、跨段换行、emoji、组合字符和中文混排都需验证。坐标单位与 ProseMirror 一致使用 UTF-16，不混用 Unicode 码点数量。

## 6. 标注定位、编辑和删除策略

### 6.1 定位信息

保留 from/to 快速定位、exact/prefix/suffix 辅助校验，增加文档修订和锚点状态。后续可以保存结构提示，但不能依赖会随视图重建而变化的 DOM ID。

建议状态：`resolved`、`ambiguous`、`unresolved`、`deleted`。失去唯一匹配只能降级为 ambiguous/unresolved；书签汇总保留记录，提示“原文位置待确认”。

### 6.2 编辑交易

正文编辑交易的 mapping 优先于全文搜索。在交易中映射端点并判断原范围是否全部删除；插入端点的归属需要固定策略，例如端点之外新增文字不自动纳入，范围内部插入纳入。

部分原文删除或替换时保留剩余锚点并更新摘录；是否将完全替换视为删除，要根据交易中的被删范围与新插入内容明确判定，不能仅以 exact 是否还能找到为准。完整删除可形成墓碑，支持同步及必要的撤销恢复。

状态转换先得到纯计算结果，再由存储服务执行批量写入/删除。ProseMirror apply 中不启动数据库事务，不吞掉写入错误。

### 6.3 源码、导入与同步

源码编辑优先复用源码到渲染模型映射；未能证明新旧坐标对应时执行保守重定位。全量替换、恢复历史和同步后优先按 noteId 与文档修订关联，再结合摘录上下文找唯一位置。

重复原文匹配、部分改写、解析行为变化都不能直接触发永久删除。没有交易证据时，保留为待定位记录比错误删除更符合用户预期。

## 7. 数据、只读权限与备份边界

标注与正文独立，可采用独立实体服务；存储服务通过现有平台能力层提供，避免视图直接依赖专用 IndexedDB。

- 标注保存不改变正文、Markdown 源码或原文最后修改时间；可单独维护标注修改时间。
- 草稿、菜单、DOM 范围不持久化；稳定锚点、附注和删除墓碑可持久化。
- 当前功能不能宣称支持跨端备份。正式接入时，需要全量导出/导入、增量实体、冲突、删除、覆盖和旧版兼容的完整认证。
- 加密/受保护文档不得将 exact、prefix、suffix、note 明文复制到普通标注库。在可用的加密存储设计完成前，应明确禁用这类文档的标注入口。
- 软删除文档时保留标注以支持恢复；最终删除或用户明确清除标注时再清理。同步/覆盖不能误把另一份同名文档的标注套过来。
- 多窗口对同一标注修改须通过版本或修改时间防止静默覆盖；错误应可见。

本节为拟议要求，不代表当前实现已满足。

## 8. 汇总、视觉与管理

普通书签和阅读高亮共用“书签与标注”面板；行内显示类型、摘录与可选附注。不能只靠颜色识别类型。长摘录在列表中截断，气泡或详情中可以查看完整文本。

高亮的颜色与当前块背景、搜索匹配、原生文本选区不同；按主题提供明暗配色，保留文本原有前景色。初期仅提供一套主题适配的高亮色，多色分类不作为当前故障修复的前置条件。

无附注时不展示空白内容框，仍能通过悬停操作条或右键菜单修改/删除。附注编辑字段按纯文本处理，不直接渲染任意 HTML。

## 9. 诊断设计：定位真实断点

记录一次阅读标注交互的关联 ID 与阶段：`selection-captured`、`contextmenu-seen`、`mapping-validated`、`menu-opened`、`menu-closed`、`save-started`、`save-completed/failed`、`highlight-rendered`。

诊断信息包括平台/WebView、当前模式、文档修订摘要、选区长度、端点类型、是否属于活动正文、菜单实际矩形、关闭原因、存储耗时和失败代码。**不记录选中文字、附注、文档全文或其它敏感原文。** 高频 selectionchange 只维护内存摘要，正式菜单操作时输出一条关联诊断，避免刷屏。

真实 macOS Tauri 必须回答：事件是否到达；选区是否存在；映射为何成功/失败；菜单是否打开；若打开，为何不可见或被关闭。取得这些证据后再选定修复，不能继续仅增加缓存或监听器来猜测。

## 10. 验证与完成标准

### 10.1 纯逻辑测试

覆盖文本模型映射、上下文重定位、重复原文歧义、部分删除、全部删除、边界插入、撤销/重做、文档修订失效、存储失败和重试。歧义或找不到 exact 时断言保留记录，避免把当前错误删除策略固化进测试。

### 10.2 浏览器交互测试

真实鼠标拖选或键盘选区 → 真实右键 → 菜单可见并可点击 → 高亮可见 → 附注管理 → 重开文档恢复。程序化构造 Range 和主动清空选区仅用作额外边界测试，不作为主要验收依据。

矩阵包含 Chromium、WebKit；完整与局部渲染；普通与专注；左/右固定目录或书签；视口四角；中文混排及样式拆分；链接文字、列表、引用、代码、表格；连续重复操作与切文档。还需断言正文与导出结果未改变。

### 10.3 原生验证

macOS Tauri 真实窗口中验证鼠标右键、触控板双指点击和 Control+单击；确认菜单没有被原生选择菜单、链接菜单或失焦事件抢走。Windows/Linux 的原生右键路径独立验证。浏览器 WebKit 通过不能替代这一步。

### 10.4 完成门槛

1. 找到并记录用户实际环境中的故障断点。
2. 基于该断点的回归能在修复前失败、修复后通过。
3. 新增、管理、汇总、重启恢复均能在真实应用使用。
4. 正文不变、普通选择复制不退化、未确认删除不丢标注。
5. 存储与备份/保护文档的支持边界在产品内可理解。

在达到原生验证前，只报告浏览器验证结果，不再宣称实际问题已经解决。

## 11. 等待审查的决策与后续顺序

建议审查重点：统一菜单与控制器是否符合预期；是否接受第一阶段明确排除派生内容；本机标注与备份能力的分期；受保护文档的门禁；失去锚点时保留待定位记录的策略。

通过设计审查后，实施顺序为：真实交互取证 → 明确断点 → 统一选区/菜单契约 → 实际故障修复 → 锚点删除及存储修正 → 原生与浏览器完整验收。首批只做能定位和修复现有不可用问题的必要改动，不将整个设计重构作为验证菜单能否弹出的前提。
