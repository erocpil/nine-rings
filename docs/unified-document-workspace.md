# 统一文档工作区

更新：2026-10-28。

## 目标

数据库文档和磁盘文件在相同格式、权限、布局和配置下，使用相同的编辑／阅读组件与命令呈现。文件来源只决定身份、内容读写、授权、重命名和必要提示；不能再决定工具栏、菜单或目录条目怎样实现。

源码与富文本仍分别由 CodeMirror 和 TipTap 承担，不把两种不同文本模型合并成一个编辑器。两种内核共用外围组件、命令呈现协议和来源能力边界。

## 收敛方向：以现有数据库工作区为基线

不再通过逐项补齐两套工作区来维持表面一致。保留数据库工作区已经稳定的组合方式，逐步将其抽为不依赖来源的组件，数据库和磁盘各自提供会话与持久化适配器。对照检查用于识别必须保留的行为，不用于决定哪一类来源实现天然更优。

源码编辑的公共内核本来就是 `MarkdownSourceEditor`，不能因为基线选用数据库入口就重写或删除磁盘入口已有的能力。源码壳层现已从 `MarkdownDocumentView` 提取为 `DocumentSourceSurface`，两种来源均直接使用它：同一懒加载编辑器、工具栏 portal 与状态栏 portal。数据库继续把编辑器放入 `MarkdownSplitPreview`；磁盘只向同一组件注入原始源码与会话回调，不经过 Markdown 序列化来打开源码。组件不要求数据库 ID，也不获取任何来源服务。

### 两类源码入口的核对结果

| 契约 | 数据库适配器 | 磁盘适配器 | 公共工作区要求 |
| --- | --- | --- | --- |
| 当前文本 | `SourceNavigationSession`，投影为 Delta 保存 | `sourceRef` / CodeMirror 文本，文件快照为保存基线 | 只接收当前文本及编辑回调，不自行解析后覆盖原文 |
| 撤销与选区 | 保留当前文档的 CodeMirror `EditorState` | `localFileSessions` 保留 CodeMirror 状态及滚动快照 | 使用宿主传入的 session 与 onReady，不新建第二份历史 |
| 恢复位置 | 源码／渲染位置映射及数据库阅读状态 | 文件身份、行锚点、滚动快照及恢复中的写入保护 | 不把磁盘恢复换成数据库的 localStorage 键 |
| 保存与失败 | 自动保存批次、刷新与会话确认 | 手动保存、草稿检查点、外部版本核验和原子写入 | 不在公共组件中选择写入路径，也不吞掉宿主保存失败 |
| 格式与权限 | 元数据中的语言，允许只读查看格式覆盖 | 文件名检测及只读查看覆盖，保留 BOM／换行约定 | 格式选择、只读防护、状态栏设置继续复用源码内核 |
| 书签／导航 | 由源码修订映射至文档位置 | 行偏移投影与文件书签存储 | 通过已有导航组件注入，禁止伪造 `nr-note:` 链接 |
| 并排预览 | 现有派生预览 | 尚未提供同一预览切换入口 | 保留可组合插槽；后续迁入公共视图控制器，不复制另一套同步实现 |

磁盘内容不进入数据库保护／同步包装器。打开、关闭、只读查看、切换布局都不能触发重新序列化或保存磁盘文件。后续抽取渲染会话时仍需遵守此边界。

## 分层

| 层次 | 职责 | 边界 |
| --- | --- | --- |
| 来源适配 | 内容与版本、权限、保存、草稿、书签投影、资源授权、必要的来源提示 | 不实现另一套工具栏、导航条目或菜单 |
| 工作区组件 | 标题栏、只读锁、源码／阅读工具栏、右键菜单、选区命令、目录、符号、书签、同词、状态栏 | 只调用宿主明确提供的能力，不自行查找数据库 ID 或磁盘服务 |
| 布局策略 | 悬停／固定、左右侧、标题下方定位、宽度、面板组合与比例 | 不修改正文、选区或撤销历史 |

## 已接通

- `document-workspace-layout.ts`：数据库和本地文件均可选择文档布局／紧凑布局；两类来源的默认值不同，布局选择与内容格式无关。布局状态见[共享源码与导航组件](source-navigation-components.md)。
- `DocumentNavigationWorkspace`：数据库源码与本地源码／渲染共用导航控制、符号解析、搜索排序、书签菜单和匹配列表。本地适配器只注入源码修订、当前偏移、书签投影和跳转／滚动／持久化回调。
- `DocumentChrome`：`DocumentTitleBar`、`DocumentAccessToggle`、`DocumentToolbar` 统一外围结构。源码与渲染可提供各自适用的命令，编辑工具栏的收起／专注定位样式只作用于编辑命令，不误隐藏只读阅读或源码工具。
- `DocumentReadingToolbar`：两类普通只读渲染共用查找、跳转块、章节折叠及级别、选区复制。显示／隐藏跟随共同“更多工具”状态。
- `EditorContextMenu`：两类普通渲染使用同一正文菜单和关闭／边界定位逻辑。菜单 portal 到窗口，避免被编辑区或侧栏裁切；Esc 优先关闭菜单。数据库可以提供块引用能力，本地未提供该能力时不生成无法解析的数据库链接；原始 Markdown 复制作为可选能力注入。
- `editor-command-surface` 与 `SelectionHoverToolbar`：右键分组和选区弹层读取当前工具栏的真实命令，沿用原按钮的启用、选中、菜单锚点及执行保护。只读菜单只呈现安全的编辑／文档阅读分组，不显示格式修改命令。
- 普通渲染继续共用 schema、NodeView、`DocumentRenderBody` 和 gutter，详见[共享文档渲染](document-rendering.md)。

只读选择监听只记录“是否有选区”，实际复制或打开菜单时才提取文本，避免拖选大文档时反复复制整段字符串和触发正文布局。

## 继续收敛的边界

目前已共享外围组件和主要命令呈现，但尚不能声称两类工作区只剩来源差异：

1. 查找／跳转界面已由 `DocumentToolPanels` 统一，互斥面板与查询状态由 `useDocumentTools` 统一，匹配及块号校验由 `document-tools` 统一。匹配只在用户导航时定位，输入查询不直接滚动。`FullNoteEditor` 与 `DocumentReadingView` 仍分别持有折叠定位及部分标题／阅读会话控制；下一步应从数据库实现提取共同控制器，而不是继续扩建第二套阅读实现。
2. 数据库富文本可直接编辑；本地 Markdown 渲染仍是只读投影，原文件只在源码模式编辑。允许本地渲染编辑前，必须确定源码保真策略，不能在打开／关闭视图时无条件重新序列化原文。
3. 数据库标题编辑／属性与磁盘重命名／文件属性仍由适配器提供。标题栏框架和锁已共享，完整属性模型及重命名能力还需要继续对齐。
4. 块菜单共用呈现组件，但部分动作集合仍由不同宿主组装，应继续收敛成能力驱动的动作工厂。数据库版本历史、同步和加密能力只能按能力提供，不强加给磁盘文件。

后续重构以跨来源对照用例约束行为，逐步减少宿主逻辑，不把共享组件重新拆成 `isLocalFile` 风格分支。

## 验证策略

- 布局切换：核对编辑器 DOM 身份、源码、阅读位置及另一布局的保存状态，不能通过重建视图实现布局切换。
- 同内容对照：普通只读文档和本地 Markdown 显示相同阅读工具，右键使用相同菜单，实际复制返回相同文本，来源不支持的能力不显示。
- 保真与权限：本地渲染操作不回写原文，原始粘贴和程序化编辑仍被只读门禁拒绝；源码撤销、草稿及外部文件版本核验继续由既有回归验证。
- 菜单与选区：右键打开时不弹出悬停工具栏；关闭菜单后保留选区，Esc 不穿透关闭其它界面。复制模拟只验证宿主调用与文本，真实系统剪贴板由独立 Chromium 权限用例覆盖。
