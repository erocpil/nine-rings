# 双栏浏览独立产品评估

日期：2026-11-10。当前已接通桌面目录确认队列及柔和配色，详见文末。此前批次说明保留其实施时边界。状态：共享核心及界面已接入两种宿主；独立 Web 原型已支持共享源码编辑、安全保存与恢复草稿，已接入共享原生服务并生成独立 macOS ARM64 `.app`；三平台交付与原生 GUI 验收待完成。

## 判断与定位

可以演进为独立产品。建议定位为面向开发者的本地双栏文件工作台：浏览、可核对的文件操作、目录比较、快速预览和源码/Markdown 查看。先做好这组闭环，再决定是否扩展归档、远程文件服务或完整 IDE；不把 Nine Rings 的数据库文档、同步、词汇学习等能力全部带入。

现有入口已是可单独启停的可信内置插件，但它仍运行在 Nine Rings 宿主中。“插件独立”不等于“应用已经独立”。[现有双栏契约](../plugins/plugin-dual-pane-browser.md)及[宿主边界决策](../decisions/002-dual-pane-file-browser.md)继续有效。

## 已有基础与实际耦合

可复用的基础包括每栏导航/标签状态、分页和排序、比较预算、拖放确认、操作队列、结果历史，以及原生的授权目录读取、摘要与安全传输。写入继续要求明确确认、草稿预检、排他发布及未知结果人工核对；独立产品不能简化这些约束。

尚不能直接复制组件发布：

| 位置 | 当前依赖 | 拆分时应保留的职责 |
| --- | --- | --- |
| `src/lib/local-files/browser-provider.ts` | 插件身份、主区域视图、最近文件、焦点标签、编辑检查点 | 在授权范围内读取和打开文件，正确交接当前编辑器 |
| `src/lib/local-files/browser-operations.ts` | 会话、草稿、路径状态迁移、主区域身份 | 移动成功后迁移打开文件；未知结果不伪装成功 |
| `src/lib/local-files/service.ts` | 工作区面板、插件权限、授权、会话与操作锁 | 保留宿主权限与写入所有权 |
| `src/components/LocalFileView.tsx` | 共享编辑/渲染、菜单、状态栏与导航 | 复用一份编辑模型，不再复制第二套文件编辑器 |

## 第一批实施：共享核心

已将文件模型、目录读取/摘要/预览、操作执行器和串行队列抽成同目录下的可移植模块：`file-model.ts`、`browser-contract.ts`、`browser-provider-core.ts`、`browser-operation-contract.ts`、`browser-operation-core.ts`、`browser-queue-core.ts`。路径检查、比较、排序、导航等原有纯逻辑继续复用，没有复制另一套实现。

Nine Rings 原有 `browser-provider.ts`、`browser-operations.ts`、`browser-operation-queue.ts` 保留公开调用方式，并实际委托这些核心。宿主必须提供授权、文件服务、打开文件、草稿检查、操作租约及移动/删除后的状态协调；队列结果历史通过可选持久化端口接入。共享核心不读取插件单例、主区域或浏览器存储。现有文件服务仍执行实际授权与路径安全检查。

两个隔离宿主的契约测试覆盖读取撤权、打开文件失败、移动协调、队列串行与取消；导入边界测试防止核心重新引入应用模块。它们证明核心可以脱离 Nine Rings 服务装配。第二批进一步处理界面依赖，形成下述只读原型；原生写入和编辑生命周期仍不能用空保存检查代替。

实现决策和保护规则见[共享核心决策](../decisions/003-shared-file-workbench.md)。

## 第二批实施：独立 Web 入口

共享的 `FileBrowserWorkspace` 由两个入口装配：

- Nine Rings：`DualPaneFileBrowser` 保留原插件接口，经 `createNineRingsBrowserHost` 接入目录授权、原有队列、设备设置、保存门禁及主区域打开。
- File Workbench：`file-workbench.html`、`src/apps/file-workbench/main.tsx` 与 `host.ts`，按能力装配服务（第二批只读，第三批支持文本保存）；不启动 Nine Rings App、文档数据库、内置插件集、同步或 Service Worker。暂用 File Workbench 作为工作名称。

两者复用相同的列表、目录标签、路径、分页、排序、多选、快速预览、目录比较和正文搜索组件。根目录读取/选择、能力、绝对路径、状态存储、队列和变更通知由 `BrowserWorkspaceHost` 指定。共享界面缺少宿主时明确报错，不偷偷使用 Nine Rings 单例。可编辑查看器的进一步装配不在本批伪造。

### 运行与构建

```bash
npm run dev:workbench
# http://127.0.0.1:1421/file-workbench.html

npm run build:workbench
npm run preview:workbench
# http://127.0.0.1:1421/file-workbench.html
```

构建只输出到 `.local-tools/file-workbench-dist/`，依赖优化缓存单独保存；不会覆盖 `dist/`，也不向 Nine Rings 的更新入口发布。构建门禁拒绝引入 `App.tsx`、Nine Rings `main.tsx`、文档 API 或数据库适配器入口。独立原型的设置键使用 `file-workbench:` 前缀，包含浏览状态、列宽、常用目录与配色；队列历史暂不启用，不读取或清理 Nine Rings 历史。正式部署须使用独立 origin，不在 Nine Rings 的 PWA scope 下部署；默认开发端口有助于隔离浏览器授权。

### 第三批：共享源码查看、编辑与保存

文本打开改用与 Nine Rings 本地文件相同的 `DocumentSourceSurface` / `MarkdownSourceEditor`：语法着色、查找、折叠、选区/右键菜单、格式化、撤销等来自原实现。文本读取遵循原文件服务的 UTF-8/二进制检查和 4 MiB 上限，不再使用快速预览的 1 MiB / 65536 字符截断。搜索结果根据原始快照修订定位，不能将过期偏移应用到已变化文件。图片仍复用原来的只读预览。

打开文本默认只读，点击“允许编辑”后可修改。目录快照只能导出副本；支持写入的授权目录在显式保存时请求浏览器权限，并通过同一文件服务验证原始修订，外部变化时拒绝覆盖并提供差异比较。未提供强制覆盖快捷入口；可导出当前副本，或在保留草稿后重新读取磁盘。

`saveLocalSource` 被 Nine Rings 本地编辑器和独立宿主共同调用：先接收磁盘回执并更新基线，再处理恢复草稿；保存期间的新编辑以新基线保留。草稿更新或宿主收尾失败不能把已经完成的磁盘写入变成可盲目重试的失败，也不能宣告当前编辑全部保存。副本下载复用 `source-download.ts`，保留 BOM 和换行约定，导出后仍标记原文件未保存。

恢复草稿使用同一 `createLocalDraftStore` 实现，数据库独立为 `file-workbench-local-recovery`，旧 Nine Rings 数据库名称、结构和默认 API 保持不变。独立宿主选择 `retainUntilResolved` 策略，不自动过期或淘汰未处理草稿；达到五份上限时拒绝新事务并保留现有记录，须在草稿入口下载并确认删除旧记录，或保存当前文件。每个数据库的同一身份共享有序事务，写入与删除确认以事务完成为准；过期清理须核对旧值，不能删除刚发布的新草稿。离开时可保存、保留已确认持久化的草稿，或取消；失败继续保留编辑器、文本和撤销历史。

### 当前范围与限制

支持真实授权目录（浏览器支持时）或目录快照，保留同源双栏浏览、比较、搜索和图片预览。已提供独立桌面预览版，但尚不开放目录变更队列；文件内容写入和目录操作是两个装配边界。源码工具的偏好沿用共享字段结构，依赖独立 origin 隔离；浏览状态/列宽/常用目录/配色继续带独立前缀。

Web 目录句柄和快照仅在当前会话有效，重新启动需重新授权；重新授权的身份不同，不自动将旧草稿套用到可能只是同名的文件。“恢复草稿”入口可查看和下载此前内容，核对路径后手动恢复。同一会话重开文件可显式恢复对应草稿。强制关闭页面或进程只能尽力暂存；未保存编辑触发浏览器退出提示，不承诺异步事务在强制终止后必然完成。

完整 Markdown/Flow/Mermaid 渲染工作区、目录/符号/书签的宿主装配、位置与打开文件状态恢复、原生目录操作及三平台安装交付继续分批处理。原型不会为追求一次性复用而引入数据库文档 API，也不会复制第二套编辑器。

独立 Playwright 配置 `playwright.workbench.config.ts` 使用自己的 1421 端口，真实目录快照验证浏览、预览、比较、工作线程搜索及设置隔离。它从 Nine Rings 默认 E2E 计划排除，由 Test workflow 中的独立 Chromium/WebKit 步骤针对生产产物执行，避免在错误宿主上重复运行。构建后可使用 `NR_WORKBENCH_PREVIEW=true npx playwright test --config playwright.workbench.config.ts --browser=chromium` 验证生产资源路径，默认配置测试开发入口。

## 第四批：独立桌面宿主

`native/file-host` 是唯一的 Rust 授权目录与安全传输实现，原有单测一起迁移。Nine Rings 通过 `commands::local_files` 重导出接入，文件名、授权 JSON、IPC 命令和参数保持兼容；独立应用仅注册这组命令及自己的关闭握手，不包含数据库和同步命令。共享库的授权文件位置由 `LocalFiles::load(dir)` 持有，未初始化时拒绝持久化，避免写入当前目录。CI 同时测试原应用和独立 Cargo workspace，防止迁移后的依赖单测被遗漏。

独立工程为 `native/file-workbench/src-tauri`，应用标识 `com.ninerings.fileworkbench`、版本 `0.1.0`，使用标准系统标题栏及单实例召回。系统应用数据目录由该标识确定，授权记录独立；WebView 使用独立应用默认配置，草稿仍存入 `file-workbench-local-recovery`。使用独立猫咪图标及托盘入口；没有全局快捷键、同步或自动升级通道。

```bash
# 不改变系统 PATH；复用仓库内已安装工具
bash scripts/with-local-tools.sh npm run tauri:workbench -- dev
bash scripts/with-local-tools.sh npm run tauri:workbench -- build \
  --target aarch64-apple-darwin --bundles app -- --locked
# 本机已有缓存时，可在最后追加 --offline
```

产物位于 `.local-tools/target/aarch64-apple-darwin/release/bundle/macos/File Workbench.app`。启动器必须进入独立 Tauri 工程目录；只在原项目上叠加配置仍会构建 Nine Rings。原应用及独立应用共用目标缓存，但各有清晰 Cargo lock，原 lock 仅新增路径依赖，未升级原应用工具链。

标题栏关闭只隐藏到托盘，保留文件编辑实例、未保存内容及运行任务；托盘左键在窗口前台时收起、隐藏/最小化或后台时召回；右键“显示”和 macOS Dock 可召回前台，单实例启动同样召回。全屏关闭先请求退出全屏，在后续非全屏尺寸事件中隐藏，避免直接销毁全屏窗口。macOS Command+Q 首次在上方提示，两秒内再次按下才进入退出流程；超时或窗口失焦重新确认。托盘“退出”直接进入离开确认。先注册退出和确认事件，再通知原生 ready，最后挂载可编辑界面；握手失败不开放编辑。实际退出仍需通过前端保存/放弃/取消及目录操作门禁，原生再次检查命令行任务，保存成功或恢复草稿事务完成后才确认退出，取消和失败保持工作区。`beforeunload` 仍用于页面离开保护，不能替代此原生握手。强制结束进程仍只恢复已提交草稿。

桌面副本导出复用同一文件服务的系统另存对话框，取消不算成功；Web 维持已有直接下载行为。导出不清除原文件未保存状态。完整 Markdown 渲染、目录操作队列与草稿/打开身份迁移、最近打开及位置恢复留待后续。

本机已成功构建 `.app` 并核对 ARM64 可执行文件、应用标识和版本。浏览器中的 Tauri 桥接夹具验证关闭握手和编辑保护；这不代替真实系统窗口、目录授权、系统 Quit、另存窗口和跨平台运行验收。当前未安装至 Applications、未启动用户 GUI 或读取 Nine Rings 数据目录。

## 文件菜单补充

双栏右键菜单在两个产品中共用，采用紧凑分组、主题色背景和级联“打开方式”；支持鼠标、方向键、Enter 与 Esc。打开方式包括内置编辑器、系统默认应用和其它应用程序选择器，后两项仅桌面版启用；目前不自动枚举或记住推荐应用，不修改系统默认关联。

目录显示修改时间（原生端），大小默认显示“—”，不在浏览时递归扫描。Web 无目录时间时仍显示未知。既有上级目录按钮和面包屑承担 `..` 导航，不列出 `.`/`..` 伪条目。系统打开、应用选择器和不同平台的关联行为需要原生 GUI 验收；自动测试不会运行真实外部程序。

## 独立工作台的紧凑界面

独立宿主声明 `presentation: "compact"`；同一 `FileBrowserWorkspace` 仅调整外观，不改变提供者、文件操作能力、队列和保存协议。Nine Rings 未声明此选项，保留原界面。

- 不再显示应用内的产品介绍标题和“文件浏览／活动栏为来源”等说明行，窗口/网页标题仍为 File Workbench。
- 主工具栏使用图标、悬停提示与无障碍名称，包含文件操作、预览、比较、搜索及宿主提供的恢复草稿/配色工具。不可用的目录操作继续禁用，并明确说明原因。
- 面包屑与路径输入共用一个地址栏：默认可点路径段，点击空白或编辑图标后输入；Enter 核验并导航，Esc 取消输入及在途校验，不跳转。
- 名称过滤按钮位于路径历史左侧，输入框向左悬浮，不挤压布局；宽度随当前目录栏变化。关闭或 Esc 清除过滤，空过滤取消不改变文件选择；点击其它位置只收起输入框，已有过滤通过按钮高亮和提示保留可见线索。
- 目录标签位于地址栏下方、文件列表列头上方。独立入口不再常驻排序选择框或隐藏项复选框，排序统一使用名称/类型/大小/修改时间表头，类型列支持双向排序与列宽记忆。打开文本/图片后仍保留图标形式的宿主工具，恢复草稿不依赖浏览视图可见。

## 推荐边界

同仓库维护可复用核心和两个应用装配入口。Nine Rings 使用现有宿主适配器；独立应用使用自己的适配器。先通过少量明确接口切断宿主耦合，再考虑物理移动目录，不先复制整个应用再删功能。

宿主接口至少覆盖：授权文件服务、文件打开/关闭、未保存内容检查、编辑检查点与路径迁移、设置/主题、剪贴板、通知。它们表达实际能力和失败语义，不能以空实现绕过草稿或权限检查。原生文件操作也应抽取共享 Rust 库，而非维护两份安全传输实现。

独立应用必须有独立的 bundle identifier、用户数据目录、授权记录、设置、更新通道和发布产物。Nine Rings 的打开文件/最近访问数据不能因安装另一个应用而被覆盖。

## 分阶段实施

1. **边界准备**：在现有插件内部引入宿主适配接口，保持用户行为不变。用原有浏览、保存失败、停用清理、移动迁移回归验证接口真实可用。
2. **最小独立宿主**：复用双栏和现有本地文件查看器，仅装配必要的服务。打通目录授权、浏览、操作、预览、编辑及退出前保存。此时再评估共享模块应成为哪些包。
3. **独立交付**：完成安装包、设置、快捷键、主题、状态恢复、更新与跨平台门禁；补齐真实权限、跨卷、系统回收站及异常退出验收。
4. **产品扩展**：依据实际需求选择远程提供者、归档、Git 等能力，分别定义权限和错误恢复，不提前承诺所有系统文件管理器功能。

优先桌面 Tauri 三平台。Web 可继续提供已授权目录的受限版本，但不承诺完整磁盘路径、后台任务及系统回收站等原生能力。自动化浏览器夹具不替代三平台真实文件系统验收。

## 投入与验证

主要成本是宿主边界、应用生命周期和交付，不是重新画两栏。独立可运行原型与可日常使用的产品应分开估算；未验证依赖拆分前不提供精确工期。先以一轮边界准备统计需改动的接口、编辑器依赖和打包结果，再估算后续工作。

推荐的检查层次：核心状态/队列单元测试；共享交互 E2E；两个宿主分别运行保存门禁和资源生命周期契约；三平台原生文件操作与打包；真实跨卷、授权撤回、外部变化和崩溃后的人工核对。复制/移动成功率之外，重点记录错误是否明确、是否误重试及打开文件身份是否保持。

成熟产品可参考 [Double Commander 的双栏定位](https://doublecmd.github.io/doc/en/about.html)和[目录同步工作流](https://doublecmd.github.io/doc/en/syncdirs.html)。应用拆分应保留 [Tauri 权限边界](https://v2.tauri.app/security/permissions/)，而不是为了独立发布而扩大所有窗口的文件访问权限。


### View 菜单和快速提示

桌面宿主在系统菜单中增加 View → 显示隐藏项（当前栏），保留系统 File/Edit/Window/Help 入口；Web 使用相同语义的应用内 View 菜单。菜单映射当前活动栏/标签的状态，不是全局修改两栏；打开编辑器/图片后禁用，没有授权目录时也不可操作。通过只读菜单状态发布与显示命令端口复用浏览状态，不让菜单直接拥有目录状态。原生更新串行发送，退出监听后拒绝迟到回调；原生菜单初始化失败时回落 Web 菜单。

类型按目录或文件扩展名推导，不读取正文或扫描 OS UTI。新增列宽字段对旧配置默认 90px，未改变旧名称/大小/时间宽度；类型升降序都保留目录优先，排序在分页前完成。Nine Rings 保留原默认三列及排序/隐藏项控件，紧凑入口才显示第四列。

独立入口现在同步挂载既有 QuickTooltips：鼠标首次悬停等待 120ms，键盘焦点即时提示，打开菜单、点击、滚动或离开后消除，抑制浏览器较慢的重复 title 提示。并非降低全局动画或改变 Nine Rings 的提示时序。

### 浏览效率与过滤反馈

参考 [Total Commander 快速过滤](https://www.ghisler.com/screenshots/en/10.html)与 [Finder 列表浏览](https://support.apple.com/guide/mac-help/organize-your-files-in-the-finder-mchle9f0a1b2/mac)，优先完善现有导航，而不是增加常驻工具行。

- 当前目录栏内 Command/Ctrl+L 进入路径输入，Command/Ctrl+F 打开名称过滤。重复按下聚焦已有输入，不切换关闭；不从编辑器、弹层或另一目录栏抢焦点。这里只做目录名称过滤，正文搜索保留独立入口。
- 过滤输入中 Enter 收起输入并回到列表，保留条件；Esc 关闭并清除。在列表中 Esc 清除现有过滤，不执行文件操作。输入法组字时不接管 Enter。
- 条件在底部以紧凑、可截断的文字展示，完整内容可悬停查看，提供明确清除按钮；点击其它区域收起输入框不会悄悄清除条件。没有结果时显示“没有匹配的文件或目录”，与空目录和读取失败区分。
- 已知大小为零的文件显示 `0 B`；目录仍显示未知内部大小，不为改善展示而递归扫描。

下一批优先评估浏览偏好（密度、列显示和日期格式）、多标签导航与状态恢复；再推进独立宿主目录操作队列及退出恢复的真实能力接入。写入操作必须具备真实草稿/打开文件协调，不能直接启用现有禁用按钮。


### 独立桌面目录操作与柔和配色

当前桌面授权目录支持与文件相同的复制到另一栏、移动、重命名、批量重命名及系统回收站操作，也支持新建文件/目录。使用同一确认弹层与串行队列；目录包含全部子项和隐藏项，现有原生预算、符号链接限制、排他发布及跨卷核验不变。同名不会覆盖。单栏重命名/新建/回收站不再要求另一栏先打开目录，复制与移动才需要可写目标栏。

右键菜单不再保留不适用的灰色条目：目录隐藏打开方式/快速预览，Web 快照隐藏系统打开及写入命令。仅暂时缺少目标栏或正在操作的可恢复状态仍使用禁用反馈。

存在未处理恢复草稿时，当前先保守阻止所有目录操作，请先保存或下载并确认处理草稿；不会自动丢弃或移动草稿。队列未结束时禁止打开编辑器及真正退出，但允许隐藏窗口到托盘；可通过操作队列停止未开始项，并等待当前原生调用收尾后退出。队列状态不自动重放，真实跨卷及系统回收站需桌面验收。

配色工具提供柔和浅色、柔和深色、清雅和物哀。前两者避免纯白/近黑背景，后两者参考 Nine Rings 现有绿色与玫瑰色墨色，保持文件列表/菜单/代码视图一致；颜色选择独立持久化，兼容旧深浅设置，不改变 Nine Rings 的风格。

### 预览工具与返回列表

双击打开的文本和图片都在右侧用 × 关闭，悬停显示“关闭预览，返回文件浏览”；文本编辑权限、保存、导出及重读按钮均提供快速提示。图片保留专用缩放操作，不展示无实际导航能力的上一/下一文件按钮；Nine Rings 中的双栏快速预览仍保留原有逐项导航能力。

打开前保存来源列表元素，真正离开预览后在已重新显示的原目录栏恢复焦点，使用 preventScroll 保留双轴滚动与当前文件选择。未保存文本仍先经过保存/草稿确认，取消时不恢复列表；新的弹层或用户已转移的焦点优先。独立图片打开时聚焦查看区，Esc 可关闭；共享双栏预览默认不自动抢走列表焦点。文件列表两轴滚动条统一为细型，WebKit 的宽高均为 6px。

### 工具栏配置、多目录与连续预览

- 工具栏右侧、恢复草稿左侧提供“添加工具”，可新增、编辑和删除工具定义；已添加工具也可右键进入配置。包含名称、程序、逐行参数、提示、近 90 个分组预置图标、Unicode 和导入图片。保存后即可出现在工具栏，配置独立持久化。
- 命令仅桌面版运行，Web 可配置但不会伪造本机执行。参数不需要额外引号；`{path}` 是当前目录，`{file}`/`{name}` 是首个选中项，`{target}` 是另一侧激活目录，独占一行的 `{files}` 展开为全部选中路径。无文件上下文的通用程序不要求先选择目录。使用的是磁盘内容，不包含编辑器中尚未保存的文本。
- 刷新右侧的“纵向目录数”可选择每侧 1～4 个目录区，各区可独立过滤，保留标签、路径、排序和位置；高度不足时可滚动该列。减少显示数只停放其它目录区，重新增加可恢复；来源/目标为两列各自当前激活区，其余区标为“待选”。
- 标签支持指针拖动排序：按下捕获、拖动提示、松开提交，仍保留方向键/Alt+方向键操作。排序不改变当前标签身份。
- 空格/F3 保留上下键快速预览。双击进入全视图后，左右键切换当前已加载列表中所有可预览文本/图片，而不是仅相同扩展名；跳过目录、已知二进制和超预算文本项（图片不受文件大小预算限制），不自动绕回。文本默认只读时可用左右键，可编辑时方向键用于编辑，使用上一/下一按钮会先确认未保存改动。
- 工作台弹层背景统一为 1px 轻微模糊和低透明度遮罩，弹层本身保持清晰。

### 自定义工具使用

点击“添加工具”填写名称和程序；参数每行一项，无需人为加引号。选择“命令行（捕获输出与退出码）”可在执行弹层查看进度与详细输出；默认“启动应用”只显示启动 PID。按钮右键可修改，工具类型可选竖线分隔，配置底部箭头调整位置。{files} 独占一行表示将全部选中文件/目录分别传入；{file} 为首个完整路径，{path} 当前目录，{target} 对侧目录，{name} 首项名称。

点击工具后先检查完整命令与工作目录，再按“执行”。关闭执行弹层不会停止命令，可用工具栏信息按钮重新查看；“终止当前进程”不影响其后代进程。输出只保留各通道最后128KiB，重启不保留。目录标签使用双击或右键关闭，不再显示×；固定标签关闭前需要确认，最后一个固定标签确认关闭后留下空白页。

### 管理授权与应用图标

顶部工具栏的盾牌按钮“管理授权目录”可查看完整路径并逐项撤销。先点击撤销，再确认；不删除文件，也不改动 macOS 系统隐私授权。父子目录分别授权时，移除子目录授权后仍能从父目录进入子目录；反过来也保留子目录独立授权。操作失败可以重试，草稿仍保留。

固定目录标签可双击或右键关闭，但会额外提醒；关闭其它/右侧若包含固定项也会确认。取消时全部保留；最后一个固定项关闭后保留空白页，可恢复最近关闭的标签。

独立猫咪应用图标来自 FKFl4.jpg，PNG/ICO/ICNS 及源图位于 native/file-workbench/src-tauri/icons，生成方法见该目录 README。Nine Rings 图标不变。

### 固定标签的目录锚点（已实现）

固定时保存独立目录锚点，默认采用“名称和目录锚点固定、允许自由导航”：地址栏继续显示当前完整路径，父目录和兄弟目录仍可访问；“限制在固定目录内”为独立右键勾选项，越界导航会提示，可新建标签或关闭限制后继续；它不是磁盘授权边界。离开固定目录显示轻量标记，悬停同时列出当前位置与固定目录。

提供“返回固定目录”右键项和返回按钮，列表聚焦时使用Alt+Home。避免复用双击，因为已经用于关闭；也不默认在切换标签时重置位置，右键可独立开启切换到此标签时自动返回。锚点应保存 rootId、相对目录和固定标题，目录移动/重命名时协调迁移，删除/撤销授权后明确标记失效，不静默重新授权。TC 的目录锁定与允许目录变化模式可借鉴，但不把所有选项强行合并为一个开关。

参考：[Total Commander 官方更新记录](https://www.ghisler.com/mailing.htm) 中的锁定目录返回、当前/固定目录区别提示及切换标签自动返回选项。旧固定标签从当前路径迁移锚点，移动/改名迁移路径，删除或撤销授权标记锚点失效，不自动改成其它授权。

### 不支持预览的文件、系统属性与大图

空格快速预览与双击全视图中，二进制、非UTF-8或暂不可解码的图片展示“暂时无法内置预览”和文件详情，不作为编辑错误提示。名称、路径、类型、字节大小及修改时间始终尽力提供；原生授权文件补充创建/访问时间和权限。目录大小标为目录条目本身，不误称递归总大小。

文件和目录右键均有“属性”：macOS调用Finder“显示简介”，Windows调用Shell属性页；Linux调用FileManager1的ShowItemProperties接口，系统不可用或拒绝调用时回退应用内属性页。路径经过同一授权及规范化校验，以参数而非脚本拼接传递；不自动打开文件或改变关联。

图片取消旧8 MiB/20 MiB限制，双击连续预览也不因大图跳过。原生与Web按768 KiB分段读取，读取间让出事件循环并检查取消/授权，预览使用Blob URL而非可能超过WebKit长度限制的Data URL。预览关闭、切换、中断以及授权失效时释放自己创建的对象URL，取消后不再请求后续分段，迟到结果不展示；当前已发出的单段IPC不承诺强制终止。解码阶段提供独立中断入口并卸载图片，不承诺浏览器立即释放解码器内部内存。仍受系统可用内存和WebView格式支持限制。文本快速预览与可编辑源文件预算保持不变。

### 原生双栏拖放

主窗口关闭Tauri内置拖放处理器，由共享HTML5拖放生成操作提案。默认复制、Shift移动，文件和目录均可多选；落在文件夹行时使用该子目录，其它列表区域使用本栏当前目录。松开后仍先确认再加入队列。只修改网页代码或通过浏览器测试不足以验证原生宿主；窗口配置变化后须重新编译安装包，完整退出旧实例后再启动新版本。

### 系统打开、工具文件参数和构建身份

独立桌面入口双击普通文件使用系统默认应用，本机主修饰键+双击（macOS Command，Windows/Linux Ctrl）使用内置查看；目录继续进入，Enter及显式内置菜单仍走原查看入口，Web快照没有系统打开能力时保留内置查看。系统启动失败显示反馈，不静默换一种打开方式。Nine Rings的文件浏览宿主保持原双击策略。

工具栏分隔符可右键配置，也可通过“添加工具”左侧列表点选带名称的分隔符条目，再使用“删除工具”；保存失败不改变内存列表。工具接受同一工作台内、已冻结来源的文件/目录拖放，使用来源根和父目录替换本次上下文。已有{file}/{files}/{name}参数保持原样，否则仅对本次调用追加{files}，不改写工具配置。拖放不会直接执行命令，仍显示完整程序/参数，确认后沿用运行任务门禁；外部Finder拖入或伪造token不成为授权。

系统About界面显示应用版本、8位Git提交号及完整提交号；构建时存在跟踪文件的未提交更改会额外标识。build.rs监视HEAD、分支引用、packed-refs、索引及前端源目录，避免只改变提交号时沿用旧缓存；无Git环境显示unknown。提交号标识源码基线，脏构建不声称全部内容来自该提交。

产品继续使用 File Workbench 名称；本轮讨论的短名称仅作候选研究，不进行改名。保持 com.ninerings.fileworkbench、授权目录、草稿库和偏好前缀不变。

### 2026-11-12：工具启动与右键菜单

工具单击仅启动程序，不传入配置参数或选中文件，不等待双击识别。仍通过同一预备计划、原生复核和运行门禁；无参数启动自动执行，失败时打开结果界面，捕获输出的命令行工具直接展示进度。macOS Control+点击保留右键语义，不能额外启动程序。

拖放使用配置参数：已有文件占位符时替换，否则为本次调用追加{files}，配置保持不变。右键“打开当前选中文件”复用完全相同的调用规则，没有选择时禁用；“使用配置参数运行”保留原预览/确认路径。

右键菜单复用共享文件菜单的键盘、Esc、定位和分组：打开应用/无参数运行、打开选中文件、使用配置参数运行；编辑/复制；向左/右移动、此前插入分隔符；删除。分隔符仅提供编辑、移动和删除。变更先持久化，成功后才更新列表；删除工具只移除配置，不终止已经启动的进程。配置界面说明点击、拖放与占位符规则。

工具保存/错误通知通过portal挂在document.body，固定在窗口底部并高于配置遮罩，独立于工具栏容器查询及滚动裁切。通知使用显式关闭按钮样式，保留5秒消失、手动关闭及窄屏宽度限制，不改变工具配置或执行状态。

修改时间列默认按浏览器实际字体测量所有已加载时间文本，同时预留表头排序箭头和8px操作空间。表头与虚拟列表共享测量结果，多余空间交给自动名称列；滚动不按当前可见几行反复改变宽度。手动调整关闭该列自动宽度，双击分隔恢复；旧默认145px升级自动，既有不同宽度保留。日期用缓存的Intl.DateTimeFormat统一显示和测量，避免每项重新构造本地化器。

文件/目录完整路径由宿主按当前目录解析一次，再与条目名称组合，不逐项读取属性。路径提示复用QuickTooltips的顶层定位和边缘钳制，仅文件列表使用data-tooltip-path接入；移除原生title路径，避免无法控制的系统提示。滚轮/滚动立即隐藏，滚动停止后重新命中当前指针位置（包含虚拟列表换行），而非复用旧条目；菜单/弹层、离开窗口和点击会取消恢复。路径优先使用窗口宽度，超过可用宽度才折行，普通工具提示保留原宽度与交互。
