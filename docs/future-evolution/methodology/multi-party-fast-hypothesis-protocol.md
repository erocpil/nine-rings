# 多主体互动的极速假设协议

> 状态：v0.3 子协议；尚未完成行为与结果验证
> 所属：[认知与行动方法论](../cognitive-action-methodology.md) · [主闭环](cognitive-action-learning-system.md)
> 用途：高压或快速的多主体互动中，以影响范围、承诺强度和修复成本可接受的动作获得可追溯 Feedback；不替代主闭环、专业审查、组织治理或应急预案

## 结论先行

当多个主体对同一 Decision 有影响，而信息、授权或约束尚不完整时，实践者不应把一次拒绝、沉默或质询直接解释为对方的恶意、人格或私有动机。更稳妥的最短路径是：保留可观察事实和我方边界，选择一个影响范围、承诺强度和修复成本可接受的下一步，并预先约定什么结果会支持、削弱或中止当前工作假设。

```text
互动事实与边界 → 可控制成本的下一步 → 可证伪预期 / 升级条件
        ↑                                   │
        └──── 新的公开信息或原始 Feedback ────┘
```

这不是博弈论的简化求解器。收益矩阵、信号成本、可信承诺或均衡等概念只适用于信息足够、影响较高且有充裕分析时间的独立分析；单次互动反馈不能证明对方的私有收益函数，更不能证明已经达成均衡。

---

## 1. 适用边界与原则

### 1.1 何时使用

适用于同时满足大部分条件的事项：

- 至少两个主体对同一 Decision、资源、接口、责任或时间安排有实际影响；
- 存在公开可观察的卡点，例如未审批、接口不兼容、标准不明或消息未获回应；
- 仍可做一个影响范围、承诺强度和修复成本可接受的动作；
- 当前情绪、时间压力或信息不完整，容易诱发指责、讽刺、报复或仓促承诺；
- 后续可以获得与该动作有关的反馈。

不适用于：单体技术排障、低风险例行事务、已有标准流程的执行，以及时间短到连最小核对都会妨碍安全处置的事件。后者应直接执行既有预案或保守动作，并按主闭环的“立即行动”模式保留事后事件痕迹。

本协议不用于操纵他人、规避知情同意、威胁、报复、公开羞辱或绕过组织授权。涉及安全、法律、医疗、财务、人事申诉、骚扰或明显权力不对称的情形，专业流程和受保护的报告渠道优先。

### 1.2 四项原则

1. **观察替代归因**：只记录角色、已知授权、公开约束与可观察行为。不可见动机只能作为未验证的候选解释，不能写成事实。
2. **动作优先可控制成本**：信息不完整时，优先选择影响范围、承诺强度和修复成本可接受的澄清、提案、试点、配置开关或技术边界；人际动作很少完全可逆，不能因其看似“礼貌”或“技术化”而默认低风险。
3. **预期可证伪**：探针要说明预期可观察的响应、时间窗和停止 / 升级条件。局面稳定后，至少保留一个非人格化的替代解释。
4. **安全路由闭环**：同一工作假设反复被削弱、损益或风险超过轻量处置阈值，或形成可复用规则时，停止极速模式并进入主闭环。

### 1.3 禁区

- 不将单一反馈表述为“证明了收益矩阵”“识别了真实动机”或“达成了纳什均衡”。
- 不将卡点直接归因于对方人格、恶意或意图；“故意拖延”“权力挤压”等未经证实的表述不是合规输入。
- 不把 Tit-for-Tat、威胁、公开曝光或自动抄送无关人员作为默认策略。
- 不用“探针”掩盖实际上不可逆、影响面大或未经授权的变更。

## 2. 三项审计

极速模式不要求填写主闭环的完整字段，只保留三项内容。

```text
┌───────────────────────────┐
│ 1. 互动事实与边界 (Facts) │
└─────────────┬─────────────┘
              │
              ▼
┌───────────────────────────┐
│ 2. 可控制成本动作 (Probe)   │
└─────────────┬─────────────┘
              │
              ▼
┌───────────────────────────┐
│ 3. 可证伪预期 (Trigger)   │
└───────────────────────────┘
```

### 2.1 互动事实与边界

记录：

- 已知的决策参与者、公开授权或仍未知的决策权归属；
- 发生了什么、何时发生、来自哪个可追溯来源；
- 我方 Goal、授权范围和不可突破的 Constraint。

事实记录默认使用以下句式：

```text
在 [时间 / 渠道]，我观察到 [原话、行为、日志或数据]，
其直接影响是 [可观察结果]。
```

例如，“方案提交五个工作日后尚未获审批；例会上提出了 A、B 两项合规问题”是 Observation；“管理者出于控制欲拖延”不是事实。后者若确有讨论必要，也只能写为低置信度、待检验的工作 Claim，并须同时保留其他解释。

### 2.2 非技术场景的动作阶梯

在人际和组织互动中，提出任何方案都可能传递立场、承诺或关系信号；“可逆”不等于“中立”。应优先选择与当前不确定性相称的最低层级动作：

| 层级 | 默认动作 | 适用目的 |
|---|---|---|
| 0 | 确认收到、延后回应 | 防止在高压下输出不可逆表达 |
| 1 | 澄清问题 | 询问标准、决策人、时限或缺失信息 |
| 2 | 选项菜单 | 提供多个可接受路径，请对方选择或补充约束 |
| 3 | 小范围试点 | 在已有授权、退出方式和影响评估下验证方案 |
| 4 | 资源承诺、规则变更、正式升级 | 不再属于极速探针，应进入主闭环或既有治理流程 |

### 2.3 可控制成本的下一步

记录：

- 最小的提案、澄清、信息补充、非生产试点或技术边界是什么；
- 直接 Cost、受影响对象、退出或调整方式；
- 所需授权，以及为何该动作在当前条件下的影响范围、承诺强度和修复成本可接受；
- 受众范围、可能被转述的方式，以及被拒绝、沉默或误解后的关系修复成本。

“部署自动 Reject”不天然属于低风险探针。若涉及生产流量、数据完整性或外部用户，至少应采用影子校验、灰度发布、功能开关或已批准的回滚方案；否则应升级为主闭环中的较高风险 Decision。

### 2.4 可证伪预期与升级条件

记录：

- 若当前工作假设足够有用，预期在何时观察到何种具体反馈；
- 局面稳定后，至少一个尚未消除的非人格化替代解释；
- 什么信号、风险或时限会使实践者停止探针、补充信息、请求协调或进入完整 Review。

预期响应只能更新关于**公开卡点**的工作假设。例如，试点被接受可以支持“试点风险控制是当前可行路径”，不能证明管理者的私有收益函数。未收到响应也不自动等于拒绝。

## 3. 10 秒核对与事后补充

### 3.1 当下核对

若时间只允许约 10 秒，使用一行记录：

```text
边界：……；卡点：……；先做：……；若……则暂停 / 升级。
```

若识别到防御、愤怒或羞耻风险上升，立即启用输出护栏：在不妨碍安全处置的前提下，暂停三类表达——指责性定性、不可逆承诺、面向无关受众的公开升级。此时允许的即时动作仅为确认收到、提出澄清、请求短暂延后，或执行既有安全预案。暂停不要求固定秒数；若任何暂停会妨碍安全处置，则直接转入预案。

### 3.2 局面稳定后的最短补充

在动作之后、响应出现前或首次 Review 时，补充：预期反馈的时间窗、直接 Cost / 回滚方式，以及至少一个非人格化替代解释。若这些信息会改变是否行动，就不应以“极速”为由跳过，而应降速进入轻量或完整闭环。

## 4. 示例

### 4.1 方案审批卡顿

**互动事实与边界**

- Observation：重构方案提交五个工作日，尚未获得审批；例会上收到关于审计日志与回滚路径的具体质询。
- Goal / Constraint：推动架构演进；未经合规确认不得上线。

**可控制成本的下一步**

- Decision：先以书面澄清请求确认试点的审批标准、决策人和反馈时限，并附上对审计日志与回滚问题的一页式答复；只有在标准明确后，再提交分阶段、非核心模块试点方案。
- Cost / Reversibility：当前动作不承诺上线或资源投入，可在获得新信息后调整；其社会成本是公开表明项目优先级，应控制收件人范围并保留可修订空间。

**可证伪预期与升级条件**

- Prediction：两个工作日内获得对审批标准、责任人、试点可操作性或缺失材料的具体答复。
- Alternative explanations：未放行可能来自审计政策变化、当前优先级、预算 / 人力约束，或对回滚机制缺乏可验证信息。
- Trigger：在约定时限后仍无法取得具体标准，且项目影响超过当前等待成本阈值时，进入主闭环，重新评估优先级、资源和替代路径。

### 4.2 接口治理冲突

**互动事实与边界**

- Observation：上游团队发布后返回结构与已约定 Schema 不符，导致解析失败；日志可定位到版本、字段和发生时间。
- Goal / Constraint：保证服务可用性与数据完整性；不持续手动修复不合规数据；不得在未经评估的情况下扩大拒绝范围或泄露日志中的敏感数据。

**可控制成本的下一步**

- Decision：先在影子模式记录 Schema 违规；确认影响范围后，通过功能开关启用契约校验，返回已约定的 Error Code 与可修复说明，并按双方接口治理流程通知责任技术负责人。
- Cost / Reversibility：影子模式不阻断流量；开关可回退。若校验会影响生产可用性或数据恢复，则升级为主闭环中的高风险 Decision。

**可证伪预期与升级条件**

- Prediction：在约定支持窗口内，上游团队修复格式、提供变更计划，或联系协商兼容方案。
- Alternative explanations：持续违规可能来自其上游数据源异常、发布流程漏洞、版本传播延迟或人员交接缺失。
- Trigger：错误率、持续时间、受影响用户数、数据完整性风险或错误预算达到预先约定的阈值，且未形成有效协调路径时，停止单对单探针，转入共同的接口治理或事故协调流程。

## 5. 与主闭环的数据路由

| 极速协议内容 | 主闭环对象 | 转换规则 |
|---|---|---|
| 可观察卡点、原始响应、时间与来源 | Observation / Feedback | 原始记录不得混入对动机的解释 |
| 已知角色、公开授权、当前流程 | Context | 决策权归属未知时必须保留 Unknown |
| 我方目标、授权范围、底线 | Goal / Constraint | 不能被“推进互动”这一短期目标覆盖 |
| 对公开卡点的暂定解释 | Claim（低置信度） | 与事实分开；须标出依据和替代解释 |
| 尚未消除的替代解释 | Unknown | 不因一次响应自动关闭 |
| 可控制成本的下一步、Cost、退出方式 | Decision / Action Plan / Cost | 标记受影响对象、授权、承诺强度、受众范围和修复成本 |
| 预期响应、时间窗、停止 / 升级条件 | Prediction / Review Trigger | 偏离预期只更新工作假设，不推断私有动机 |

出现以下任一情况时，应中止极速模式并进行主闭环的分层诊断：

1. 同一工作假设连续两次被削弱，补充信息仍无法区分替代解释，且事项影响已超过轻量处置阈值；
2. 探针引发预料之外的安全、法律、关系、生产或数据风险；
3. 需要改变长期资源分配、责任边界、接口规则或组织关系；
4. 已形成可能在相似互动中复用的规则，需明确其适用条件和副作用。

“两次”是触发复核的默认信号，不是机械证明。若反馈仍高度含混、成本极低且风险可控，可以先补充信息；若一次事件已造成重大风险，则应立即升级。

## 6. 验证与收缩条件

验证时，应与自由对话、普通轻量闭环或既有组织流程比较，至少观察：

- 从卡点出现到作出可控制成本的下一步的时间，以及是否因此延误必要处置；
- 人格化归因、报复性表达和未经授权变更是否减少；
- 探针是否获得可追溯且能区分替代解释的 Feedback；
- 升级是否过早、过晚或正确地进入既有治理流程；
- 是否降低返工、接口事故、重复沟通成本或关系损害；
- 是否因动作的受众范围、承诺强度或被转述方式产生了额外关系成本；
- 用户是否因记录本身增加焦虑、对抗感或虚假的控制感。

出现下列结果时，应收缩或放弃该子协议：

- 用户仍频繁把反馈直接解释为对方私有动机；
- “可控制成本的探针”实际造成不可接受的生产、关系或权限风险；
- 相比普通澄清、既有流程或主闭环，它没有以更低成本获得更好的信息；
- 10 秒核对明显拖延处置，或成为逃避必要升级和复盘的理由。
