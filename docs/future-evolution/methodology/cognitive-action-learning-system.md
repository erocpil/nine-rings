# 认知—行动—学习闭环方法论

> 状态：v0.3；概念体系与操作协议已定义，行为效果与长期结果仍待验证
> 性质：独立方法论；不依赖任何产品、特定人群、工具或商业目标
> 相关文档：[方法论导航](../cognitive-action-methodology.md) · [最小可验证方法](minimum-viable-method.md) · [语义模型与适用边界](semantic-model-and-boundaries.md) · [理论证据与案例](evidence-and-cases.md)

## 结论先行

人不能仅靠积累事后总结，稳定地改善相似情境中的判断与行动。更可靠的最小路径是：在结果未知时保留事前认知基线；让决策、行动和现实反馈可追溯地相连；在复盘中区分事实、解释与价值判断；把确认的认知修订写成带适用条件的规则，并在下一次相似情境中重新调用。

```text
事前判断 → 决策 / 行动 → 现实反馈 → 复盘 → 认知修订 → 情境化复用
      ↑                                                    │
      └──────────────── 下一次相似事项 ────────────────────┘
```

这不是“凡事记录”的主张，也不是保证成功的因果公式。它只适用于重要、可行动、存在不确定性、能够获得反馈且可能再次遇到的事项。该方法的价值需要通过实践验证；完整填写记录、获得好结果或拥有更多知识，都不能单独证明它有效。

本文以金字塔结构组织：先说明主张、边界和成功标准，再定义系统构件，随后给出一轮闭环的执行协议，最后规定质量控制、验证与否定条件。

## 1. 方法论的主张、边界与成功标准

### 1.1 核心命题

对于符合进入条件的事项，以下机制有望比纯事后总结更可靠地支持学习：

1. **保存基线**：在 Outcome 已知前写下当时的语境、判断、预期与标准，降低后见偏差和标准漂移。
2. **保留链路**：区分 Decision、实际 Action、Reality、Outcome 和收到的 Feedback，避免用结果倒推“当时本应如何做”。
3. **受约束解释**：复盘时并列检验认知、决策、执行、环境、运气与测量，而不是将成败归因于单一原因。
4. **明确修订**：把变化写成可追溯的 Revision，或明确记录“证据不足，暂不修订”。
5. **条件化复用**：将 Revision 绑定到适用情境、触发线索和不同做法，使其进入下一轮判断。

方法不声称人的认知能够被完整记录，也不把 Revision 等同于“更正确”。它要提高的是：认知变化的可观察性、解释的可审查性，以及下一次实践中调用经验的概率。

### 1.2 适用与不适用的边界

一个事项只有同时满足下列大部分条件，才值得进入完整闭环：

| 条件 | 要问的问题 | 不满足时的默认做法 |
|---|---|---|
| 影响 | 结果是否值得额外的记录与复盘成本？ | 直接行动或使用简单任务清单 |
| 不确定性 | 是否存在会改变行动选择的未知、假设或预测？ | 按既有流程执行 |
| 可行动性 | 是否能作出 Decision、采取 Action 或明确选择不行动？ | 先进行开放探索或等待条件成熟 |
| 可反馈性 | 能否在可接受的时间内观察到结果或有效代理信号？ | 仅记录问题、来源或探索线索 |
| 可复用性 | 未来是否可能出现相似判断？ | 做一次性事后记录，或不记录 |

以下活动不应被强行纳入此体系：低风险例行事务、纯粹休息与关系体验、无意转化为行动的阅读、不可逆但长期无反馈的人生选择，以及记录成本高于可预期收益的事项。开放探索可以只保留 **Exploration Question**，不必伪造 Goal、Prediction 或 Success Criteria。

当可用决策时间短于完成最小记录所需时间时，实践者应先执行既有的安全措施、应急预案或保守动作，而不是为了留下记录延迟行动。此时是否、何时复盘，取决于事件影响、异常性和未来复用价值；不应把事后补录变成默认债务。

### 1.3 什么算成功，什么不算

方法的近端成功不是“结果一定更好”，而是实践者能够：

- 还原行动前实际持有的判断与标准；
- 明确 Prediction、Outcome、Feedback 和解释之间的差异；
- 形成有依据、带边界的 Revision，或有理由地维持原判断；
- 在下一次相似事项中检索该记录，并可观察到它影响了 Decision 或 Action；
- 在上述过程中付出的时间、注意力、压力和延迟行动成本可接受。

一个 Outcome 好，不等于当时的 Decision 好；一个 Outcome 坏，也不等于当时的 Decision 不合理。结果受执行质量、外部条件、运气和测量方式共同影响。闭环的任务是改善下一次的判断条件，而不是为过去的成败寻找单一归因。

## 2. 系统结构：六层对象与三类时间

### 2.1 六层对象

完整体系不是一张大表，而是六类具有不同语义的对象：

```text
价值与边界层：Goal / Non-goal / Constraint
认知与证据层：Source / Observation / Claim / Unknown
承诺与执行层：Decision / Prediction / Action / Cost
现实与信号层：Reality / Outcome / Feedback
解释与更新层：Review / Evidence Assessment / Revision
迁移与记忆层：Reuse Rule / Retrieval Event / Operational Model
```

它们的最小定义如下。

| 对象 | 回答的问题 | 必须避免的混淆 |
|---|---|---|
| Goal | 为什么值得处理？ | 不是具体任务或已经发生的结果 |
| Non-goal | 本次明确不追求什么？ | 不是永远不做、也不是没有价值 |
| Constraint | 哪些边界不能用收益轻易交换？ | 不等于普通 Cost |
| Source / Observation | 看到了什么资料或现象？ | 不等于已接受的判断 |
| Claim | 在特定语境下相信什么？ | 不等于永恒事实 |
| Unknown | 哪个不确定性会影响选择或解释？ | 不等于未穷尽的一切细节 |
| Decision | 在当时语境下承诺做什么或不做什么？ | 不等于实际执行 |
| Prediction | 基于当前认识，预计会发生什么？ | 不等于希望发生什么 |
| Action | 实际采取了什么行为？ | 不等于计划或意图 |
| Outcome | 与事项相关、可观察的实际结果 | 不等于 Decision 质量或 Benefit |
| Feedback | 接收到的原始信号 | 不等于已经解释后的证据 |
| Review | 比较预期与实际、检查替代解释 | 不等于事后摘要 |
| Revision | 确认的认知更新 | 不等于任意文字修改 |
| Reuse Rule | 下次何时、为何、怎样调用经验 | 不等于模糊的“以后注意” |

### 2.2 三类时间必须分开

为了防止事后覆盖事前，每个关键对象至少区分：

| 时间 | 含义 | 例子 |
|---|---|---|
| 发生时间 | 事件在现实中发生的时间 | Action 执行、指标变化、对话发生 |
| 观察时间 | 实践者获知该事件的时间 | 读到监控告警、收到反馈 |
| 记录 / 修订时间 | 写下事实、解释或更新判断的时间 | 补录日志、完成 Review、确认 Revision |

事前状态、原始 Feedback、Success Criteria 与 Revision 都应保留版本、时间和变更原因。允许补录，但补录必须标明是补录，不能伪装成当时已知的信息。

### 2.3 从现实到认知更新的链路

```text
Source / Observation ─→ Claim ─→ Decision ─→ Action
                                  │             │
Goal / Constraint ───────────────┘             ↓
Prediction / Success Criteria ───────────→ Reality
                                             ↓
                                     Outcome / Feedback
                                             ↓
                                          Review
                                             ↓
                               Evidence Assessment
                                             ↓
                              Revision 或暂不修订
                                             ↓
                                Reuse Rule / 下一次调用
```

**Reality** 是发生的事实；**Feedback** 是被接收到的信号；**Evidence Assessment** 是对信号支持或削弱某个 Claim、Prediction 或 Decision 的解释。三者不能合并，否则新的证据或不同解释会迫使实践者修改原始记录。

## 3. 一轮闭环的操作协议

### 3.1 第零步：选择记录强度

先判断当前可用决策时间与事项风险，再选择记录强度，而不是先填表。可使用四档：

| 模式 | 适用事项 | 最少保留内容 |
|---|---|---|
| 立即行动 | 时间窗口短于记录时间，或已有明确的安全 / 事故处置预案 | 执行预案或保守动作；保留自动时间戳、系统日志或事后最短事件说明即可 |
| 极速基线（约 10 秒） | 高压、快速博弈或机会短暂，但仍可留下一句判断 | 当前关键假设或优先检查点；出现什么现象就停止、撤退、切换或升级 |
| 普通记录 | 低影响、一次性或仅供回忆 | 内容、日期、必要上下文 |
| 轻量闭环 | 有不确定性但影响或复用价值有限 | 当前判断、Decision、Review Trigger、简短 Outcome |
| 完整闭环 | 符合 1.2 的大部分条件 | 本章全部关键阶段 |

立即行动与极速基线不是“填写得不完整的完整闭环”。前者优先保证安全和行动连续性；后者只保存足以事后辨认当时判断与退出条件的最小锚点。选择降级、暂停或退出也是正确结果。方法不能把“没有完整记录”解释为失败。

这里的“断路器”应指预先定义的停止、撤退、切换或升级条件，不是要求用户在紧急时多写一张表。例如，当关键安全边界被触及、关键证据与当前假设冲突、或无法在时限内判断时，应停止继续押注当前路径，并转入预案、保守动作或请求支援。

### 3.2 事前：冻结认知基线

在 Outcome 已知前，针对一个可复盘事项记录以下内容。应简洁到不妨碍行动，但足以让未来的自己理解当时为什么这样判断。

| 字段 | 最小问题 | 何时需要扩展 |
|---|---|---|
| 事项与范围 | 现在要解决什么，边界在哪里？ | 多方协作、长期事项或范围易漂移时 |
| Goal / Non-goal / Constraint | 为什么做；不做什么；哪些底线不可突破？ | 风险、伦理、资源或关系权衡显著时 |
| 当前 Claim 与依据 | 我目前认为关键机制是什么，依据是什么？ | 证据相互冲突或来源可靠性不同时 |
| Unknown 与备选解释 | 哪些未知会改变选择？还有什么可能解释？ | 高风险或不可逆 Decision 时 |
| Desired Outcome 与 Success Criteria | 希望得到什么；何时、按什么条件判断？ | 成功标准可测量或易被事后重写时 |
| Prediction | 若判断成立，预计出现什么可观察信号？ | 需要区分愿望与预期时 |
| Decision 与 Action Plan | 做什么、不做什么；下一步是什么？ | 多步骤执行或存在触发条件时 |
| Review Trigger | 何时、凭什么信号回来检查？ | 反馈延迟、周期长或易遗忘时 |

**事前基线的硬规则**：不要求预测精确，但必须允许未来发现“当时并不是这样想的”。因此，不能在 Outcome 出现后无痕修改 Prediction 或 Success Criteria。

**极速基线模板**：`当前先按……判断 / 先检查……；如果出现……，则停止、撤退、切换或升级。` 若连这一句都会妨碍行动，则不记录，待局面稳定后只保留可获得的原始事件痕迹。

多主体、高压互动可使用[多主体互动的极速假设协议](multi-party-fast-hypothesis-protocol.md)。该子协议只增加角色、公开约束和可逆探针的表达，不允许将对方的不可见动机当作事实或因果结论。

### 3.3 决策与行动：把承诺和执行分开

Decision 是在当时信息、约束与选项下的选择；Action 是之后实际发生的行为。两者之间可能出现偏离，且偏离本身就是重要反馈。

执行阶段至少记录：

- 实际 Action、发生时间和关键偏离；
- 预期与实际 Cost，包括时间、注意力、风险、机会成本和副作用；
- 新出现但会改变原判断的 Observation；
- 预先定义的触发条件是否已出现。

若新信息要求改变 Decision，应创建新的版本或新的 Decision，而不是把旧 Decision 改写为“本来就想这么做”。这样才能区分“原判断被证据修正”与“原计划没有执行”。

### 3.4 现实反馈：先保留信号，再解释信号

收到结果或信号后，先写原始事实，后写解释。

**Outcome / Feedback 最小记录**：

```text
发生了什么？何时发生？如何得知？
哪些数据、原话、观察或测试可追溯？
它与哪一个 Prediction、Success Criteria、Decision 或 Action 有关？
有哪些不确定性、缺失数据或相互冲突的信号？
```

原始 Feedback 可以来自人的反馈、测试、日志、指标、文档、观察或环境变化。它可能真实、错误、延迟、片面或与其他信号冲突；因此不能自动标为“支持”或“反驳”。

### 3.5 复盘：按固定顺序检查差异与替代解释

复盘不应从“结果好不好”直接跳到“我对不对”。推荐固定顺序：

1. **比较**：Prediction、Desired Outcome、Success Criteria 与 Outcome 分别哪里一致、哪里不一致？
2. **核验记录**：事前基线是否完整？结果和 Feedback 是否足以支持判断？是否存在补录或标准变更？
3. **分层诊断**：差异主要可能来自认知、Decision、执行、环境、运气还是测量？
4. **替代解释与反证**：至少提出一个合理替代解释；说明最强反证、仍缺什么证据，以及什么证据会改变当前结论。
5. **评估证据**：对每个关键 Claim 或 Prediction，标出支持、削弱、冲突或无法判断，以及证据的来源、强度、独立性和适用范围。
6. **决定更新**：形成 Revision、维持原判断、缩小适用范围，或明确“证据不足，继续观察”。
7. **安排复用**：写出下一次出现何种线索时应检索该结论，以及应怎样不同地行动。

诊断时使用下表，避免单因归因：

| 可能层次 | 要问的问题 | 不应得出的仓促结论 |
|---|---|---|
| 认知 / Claim | 核心假设、因果解释或信息来源是否有误？ | 结果不佳就说明所有认识错误 |
| Decision | 在当时约束下，选择是否忽略了更好的可得选项？ | Outcome 差就说明选择必然不理性 |
| 执行 / Action | 是否按计划执行；能力、时机、质量是否足够？ | 把未执行归为判断错误 |
| 环境 / 运气 | 外部条件是否改变；偶然事件是否关键？ | 用运气回避所有可学习因素 |
| 测量 | Outcome、指标、时间窗和样本是否能代表问题？ | 把单次、噪声信号当作定论 |

对于高影响、不可逆、涉及他人利益，或已发生重复重大失败的事项，Review 还应进入独立质询：由未参与原 Decision 的人、领域专业流程，或明确扮演红队的审查步骤，针对原始 Feedback、替代解释和反证提出质疑。独立质询不等于找人附和，也不能替代法定、专业或安全审查。无法安全地引入第三方时，至少应保留一份与原结论分离的反方论证，并明确该限制。

### 3.6 修订：把变化写成可使用的差异

Revision 是实践者确认的认知更新。每条 Revision 必须可以回答：

```text
之前在什么语境下相信什么？
现在改为相信什么，或把它限制在哪些条件下？
依据哪些 Feedback、证据评估和替代解释？
置信度与未解决的 Unknown 是什么？
下次在何种情境中应调用它？
调用后准备怎样不同地判断或行动？
```

Revision 必须区分它改变的是哪一种判断：

| 类型 | 可以主张什么 | 不应凭什么直接升级 |
|---|---|---|
| 观察性 | 在特定时间、样本和来源下观察到什么模式 | 把观察当成普遍规律或机制 |
| 预测性 | 某个预期在当前条件下被支持、削弱或仍未判定 | 因单次命中就宣称预测能力已校准 |
| 因果性 | 在具备重复、对照、机制证据或可靠外部证据时，某因素可能造成何种影响 | 用单次 Outcome、相关性或事后叙事确立因果规则 |

单次复杂事件通常只足以产生“继续调查”“缩小适用范围”或“采取可逆保护动作”的 Revision。出现意外信号、样本过少、关键反馈来源不独立、或环境发生结构性变化时，应把已有结论降级为未决，并重新进入探索或验证，而不是把 If–Then 规则写得更精细。If–Then 可用于行动触发，不自动构成对世界机制的因果解释。

合法的更新不只有“接受新观点”。至少包括：

| 类型 | 含义 |
|---|---|
| 加强 | 证据增加，对 Claim 更有信心 |
| 削弱 | 证据不再支持原强度 |
| 限定 | Claim 仅在明确条件下成立 |
| 替换 | 更好的解释取代原解释 |
| 拆分 | 原来混合的 Claim 被分成不同情境或机制 |
| 暂缓 | 证据不足、冲突或测量不可靠，暂不更新 |
| 拒绝 | 经过审查后不接受候选 Claim |

“我以后会更认真”“下次注意风险”不构成 Revision，除非它说明触发情境、具体判断规则或可观察的行动变化。

### 3.7 复用：让经验有机会改变下一次

复用不是把历史记录存档，而是在新事项出现时建立有意识的连接。每条可复用 Revision 应至少包含：

- **适用条件**：什么问题结构、信号、约束或风险表明它相关；
- **不适用条件**：什么差异会使它不能直接迁移；
- **检索线索**：下次应问的一个问题、看到的现象或关键词；
- **行动差异**：引用它后会新增、避免、延后或改变什么 Decision / Action；
- **复用证据**：下一次是否被检索，是否实际改变了选择，结果如何。

复用可能得出“不适用”或“检索后仍维持原做法”，这同样是有效证据。要求的不是机械服从旧结论，而是让旧结论接受新语境的检验。

## 4. 记录模板与最低质量线

以下模板可用纸张、文本或任何可保留版本的媒介执行；它不是软件界面规范。

产品可以把这些内容实现为原子卡片、引用关系或图谱，但每次 Review 仍必须能还原完整的决策事件时间线：当时知道什么、做了什么、发生什么、怎样解释、后来怎样更新。降低输入摩擦不能以切断时间和因果语境为代价。

```markdown
# 可复盘事项

## 事前基线（记录于：）
- 事项与范围：
- Goal / Non-goal / Constraint：
- 当前 Claim 与依据：
- 关键 Unknown 与替代解释：
- 最强反证；什么证据会让我改变结论：
- Desired Outcome / Success Criteria：
- Prediction：
- Decision：
- Action Plan 与预期 Cost：
- Review Trigger：

## 执行与原始反馈
- 实际 Action 与偏离：
- Outcome：
- 原始 Feedback / 来源 / 发生与观察时间：
- 新出现的 Unknown 或冲突信号：

## Review（记录于：）
- 预期与实际的差异：
- 认知 / Decision / 执行 / 环境 / 测量的可能影响：
- 替代解释与仍缺的证据：
- 红队 / 独立质询意见（如触发）：
- Evidence Assessment：

## Revision 与复用
- 更新前 → 更新后：
- 依据、置信度与适用范围：
- 暂不修订的理由（如适用）：
- Reuse Rule：下次看到……时，检查……并改为……
- 后续复用事件：
```

一轮完整闭环至少达到以下质量线：

1. 事前记录早于 Outcome 被知晓，或清楚标注为事后补录；
2. Prediction 与 Desired Outcome 不混淆，且至少有一个可检查的关联信号；
3. Feedback 能回到来源、数据或原始表述；
4. Review 至少考虑一个替代解释和一个非认知层面的原因；
5. Revision 保留前后差异、依据和适用条件，或明确不修订；
6. Reuse Rule 能指向未来可识别的情境，而非抽象口号。

## 5. 失效模式与防护原则

| 失效模式 | 表现 | 防护原则 |
|---|---|---|
| 后见偏差 | 结果出现后重写自己原来的判断 | 冻结事前基线，保留版本与补录标识 |
| 结果偏差 | 只因 Outcome 好坏评价 Decision | 分开诊断认知、选择、执行、环境与运气 |
| 标准漂移 | 事后改写 Success Criteria 使结果看似成功 | 保存定义时间；修改时记录原因与影响 |
| 伪精确 | 为复杂世界编造单一分数、置信度或因果结论 | 标注不确定性、证据强度和替代解释 |
| 控制错觉 | 因为链路完整而误以为已掌握现实因果 | 区分观察、预测与因果 Revision；单次复杂结果默认不建立强因果规则 |
| 单因归因 | 将复杂结果全归于一个 Claim 或行动 | 至少检查一个替代解释与测量限制 |
| 过度记录 | 记录本身拖延行动、制造压力 | 按模式降级；仅对高价值事项使用完整闭环 |
| 选择性取样 | 只收集或保留支持既有判断的 Feedback | 保留反例、缺失与忽略理由；高风险事项接受独立质询 |
| 把来源当信念 | 摘录、AI 建议或他人观点自动进入认知模型 | 只有确认的 Claim / Revision 才代表当前判断 |
| 把复盘当学习 | 写了总结但下次从未检索 | 为 Revision 写出触发线索并记录复用事件 |
| 自动化越权 | 工具替用户确认 Claim、Revision 或价值判断 | 自动化只能提示候选、保留来源；确认由实践者完成 |

该方法不应用于替代专业医疗、法律、财务、安全或心理支持中的专业判断；在高风险领域，约束、外部审查与专业规范优先于个人闭环记录。

## 6. 验证与可证伪框架

### 6.1 需要分别验证的假设

“闭环有效”不是单个命题，至少包含：

| 假设 | 观察问题 |
|---|---|
| 可理解性 | 实践者能否稳定区分核心对象而不混淆？ |
| 可执行性 | 不依赖专用工具，能否在真实事项中完成最短闭环？ |
| 认知可观测性 | 事前与事后差异是否暴露了原本难以发现的变化？ |
| 解释质量 | 受约束 Review 是否减少后见之明、单因归因和标准漂移？ |
| 迁移与复用 | Revision 是否在后续相似事项中被检索并改变判断或行动？ |
| 净收益 | 上述收益是否大于记录、等待、压力与延迟行动的成本？ |

远端的 Decision 质量、返工、风险和 Outcome 改善也值得观察，但不能用单次结果证明或否定方法，因为它们受太多外部因素影响。

### 6.2 最低成本的验证顺序

1. **概念走查**：用已完成事项检查对象、问题和边界是否自洽；它不能证明有效性。
2. **前瞻性实践**：在 Outcome 出现前完成事前基线，观察闭环完成率、耗时、遗漏与理解错误。
3. **交替比较**：在相似事项中交替使用自由记录、简单 Decision Journal 与本方法，比较可追溯性、解释质量、具体 Revision、复用与主观负担。
4. **重复情境追踪**：观察历史 Revision 是否在下一次相似事项中被检索，以及它带来的行动差异和后续结果。

验证时应预先定义事项范围、时间窗、成功阈值与负面指标；不能在看到结果后只挑选成功案例。

### 6.3 建议指标

- 事前基线、反馈、Review 和 Revision 的完成比例与耗时；
- 四档模式的选择分布、模式选择耗时，以及极速 / 立即行动是否反而延迟处置；
- Prediction、Desired Outcome、Outcome 和 Feedback 被混淆的比例；
- Review 中替代解释、测量限制和非认知原因的出现比例；
- Revision 是否包含前后差异、证据、适用条件和 Reuse Rule；
- 后续相似事项中的检索率、实际 Decision / Action 改变率；
- 返工、错误复发、预测校准或风险暴露的变化（仅作情境化指标）；
- 过度记录、拖延、焦虑、自我合理化和退出率。
- 高风险 Review 的反证提出率、独立质询覆盖率、异议保留率，以及质询后结论被缩小、暂缓或改变的比例。

### 6.4 收缩或否定条件

出现下列模式时，应缩小、重写或放弃方法，而非通过增加字段解释失败：

- 实践者经少量示例后仍无法区分核心概念；
- 大多数事项无法在合理时间内得到足以 Review 的 Feedback；
- Review 长期只产生泛泛总结，没有具体 Revision 或适用条件；
- 历史 Review 很少在后续相似事项中被检索；
- 简单记录以更低成本产生相同的可追溯性、解释质量与复用；
- 记录负担导致更少行动、更多压力或明显的自我合理化；
- 极速模式在真实高压情境中仍显著拖延行动，或成为逃避必要复盘的常态；
- 独立质询只产生形式性附和、侵犯隐私，或未能暴露比自我复盘更多的替代解释；
- 观察到的改善主要来自投入更多时间、外部辅导或其他干预，而非闭环中的基线、反馈分离、受约束 Review 与 Revision 机制。

## 7. 方法论的最短执行清单

对一个准备进入完整闭环的事项，依次确认：

1. 它是否重要、可行动、不确定、可获得反馈且可能复用？
2. 我在 Outcome 已知前，是否留下了判断、Prediction、Decision 和 Review Trigger？
3. 我是否把实际 Action、原始信号与后来解释分开？
4. 我是否比较了预期与实际，并检查认知以外的替代解释？
5. 我是否形成了可追溯的 Revision，或明确说明为何暂不修订？
6. 我是否写出了下一次的适用条件、检索线索和行动差异？
7. 这轮记录的收益是否仍大于其成本？若否，是否应降级或退出？

如果其中任一步没有完成，最诚实的做法不是补写一个看似完整的故事，而是保留缺口：尚未获得反馈、尚未复盘、证据不足、未形成 Revision，或尚未观察到复用。缺口本身正是方法需要解释和改进的事实。
