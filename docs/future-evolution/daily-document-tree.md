# 文档树中的 Daily：后续决策记录

## 当前决策

文档树默认隐藏 `daily`。每日随笔仍由“每日”视图管理，底层数据和虚拟路径映射继续保留，不删除、不迁移数据。

原因：当前 `daily` 只是把没有 `storagePath` 的随笔按日期映射进文档树，与“每日”视图高度重复；日期持续增长也会稀释 P.A.R.A. 文档目录的主要用途。

## 重新启用的前提

如果未来要在文档树中重新展示 `daily`，它应成为“随笔沉淀为文档”的整理入口，而不只是另一份日期列表。建议至少评估以下能力：

- 按年/月/日分层，避免日期目录无限平铺；
- 默认仅展示最近 7～30 天，并允许查看完整历史；
- 支持将随笔转换或拖动到 P.A.R.A. 目录成为正式文档；
- 根节点同时显示随笔总数和覆盖天数，避免把“日期数”误认为“文档数”；
- 与每日视图共享选中、定位和刷新状态；
- 提供“在文档树显示每日随笔”的用户设置，而非强制展示。

## 决策问题

重新启用前需要回答：用户是否确实需要从每日记录中定期提炼长期知识？如果主要需求只是按日期回看内容，应继续使用独立的“每日”视图；只有当整理、转换和归档形成完整工作流时，`daily` 才有必要回到文档树。
