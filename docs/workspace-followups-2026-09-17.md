# 阅读工作区：本轮交付与后续工作

基线：`ffbb92f`。本轮处理前三项；后续性能和模块化工作不混入本轮。正文格式、备份协议及手机分栏交互不变。

## 本轮范围

1. **独立回归门禁**：GitHub CI 增加 Chromium / WebKit 矩阵，单独跑文档树、文档列表及手机布局切换、阅读状态刷新恢复、桌面浮层和边缘滚动条。失败保留 trace，避免这些用例因前面的无关 E2E 失败而未执行。文档夹具经实际 Markdown 解析器生成，页面内初始化任务通过普通结果轮询，且明确验证正文存在，不能仅以“元素不存在”作为折叠通过依据。
2. **设备本地阅读状态**：每篇普通文档的标题折叠、只读代码/引用块显示覆盖、渲染位置、源码模式/位置和局部渲染锚点记录在 `nr:readingState:<id>`。保留旧滚动位置/锚点兼容读取，快速切换、页面隐藏和关闭时提交待保存位置。只读块和局部渲染锚点须匹配文档版本，避免内容改变后命中错误位置；不写回只读正文，新增记录不参与 GitHub 备份。旧 `scrollPos:` 数值仍兼容写入并遵循既有备份规则，不改变备份协议。存储损坏、不可用或满额时尽力降级，不阻断阅读。
3. **桌面浮层交互**：Tab 聚焦分栏按钮后用右/下方向键进入面板；Enter / Space 仍使用按钮的固定并排动作。Esc 关闭并将焦点还给按钮，树内菜单优先处理 Esc。固定状态增加高亮边线和文字提示。输入框、原生选择框、嵌套菜单/模态弹层及获得焦点的阅读 iframe 不因离开按钮而立即关闭；无交互占用时仍按原延时收起。阅读资料库悬停挂载不抢正文焦点，浮层中的“退出”/Esc 返回分栏按钮。正文区指针移动提供补充关闭路径，覆盖面板过渡或延迟挂载期间缺失边缘离开事件的情形。手机不启用这些分栏行为。

### 隐私和恢复边界

- 加密正文不写入上述新记录；设置文档或路径密码、打开/锁定/离开加密文档时清除该文档的旧阅读记录和内存标题键。标题键可能含正文标题，因此不能当作无敏感性的普通设置备份。
- 原始源码不写入阅读状态，只有模式与滚动数值；正文依旧由既有自动保存流程管理。
- 刷新验证能排除仅依赖当前 JS 内存的假恢复。原生应用实际退出重启、PWA 被系统回收以及各平台存储清理策略仍需真机验收。
- 普通完整渲染/源码位置目前仍以像素位置为主；同宽度下恢复，不承诺字号、窗口宽度或正文版本改变后的逐像素一致。局部只读渲染使用版本化块锚点。

- 延续 [编辑器后续优化记录](editor-followups-2026-09-17.md) 的生产包方法，补 500 / 1500 / 5000 块、含长代码/多级列表/表格/图片的夹具。

### 5. 编辑器 / App / 设置页 / CSS 与类型继续拆分

- App：工作区导航、分栏及阅读资料打开流程独立成 hooks / 组件，减少大组件闭包相互影响。
- 编辑器：块操作、标题工具栏、状态显示和生命周期逐项提取；保持一次标准内容变更/保存流。
- 设置：按子页拆分并保持懒加载；搜索索引与实际入口一起测试。
- CSS：按工作区域归属迁移，保持导入顺序和主题变量；清理重复覆盖前先有截图/交互回归。
- 类型：优先收敛跨模块视图状态、存储边界、DOM 事件及 IPC 返回值，避免靠断言绕过检查。

### 6. 待办清单与真机验收持续收敛

- 全面复核 ROADMAP 的历史条目（部分仍停在 9 月 5 日），区分“未实现”“实现待真机”“已验证”，不把所有历史计划都当作本轮承诺。
