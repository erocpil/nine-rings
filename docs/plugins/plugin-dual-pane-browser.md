# 双栏文件浏览插件

独立产品已开始[共享核心抽离](../future-evolution/dual-pane-standalone.md)：目录提供者、操作执行器及队列由宿主端口装配，Nine Rings 插件已委托同一实现。第二批以相同 `FileBrowserWorkspace` 建立独立 Web 入口，第三批接入共享源码编辑器、安全保存和独立恢复草稿；原生独立应用和安装包尚未建立。下文仍描述内置插件的实际契约。

## 目标与边界

采用 Total Commander 的两个独立目录列表、活动栏与源/目标概念，结合 Finder 的面包屑、详情列表和多选。作为独立「双栏浏览」可信内置插件交付，与「本地文件」共享宿主授权而不覆盖左侧树的导航状态。不是可安装的第三方脚本插件，不开放任意 React/DOM 或文件系统访问。

## 独立插件入口（2026-11-07）

插件 ID 为 `nine-rings.builtin-file-browser`，在设置插件列表独立启停和查看说明。桌面活动栏提供双栏图标，手机从文档树工具区进入；此入口打开主区域浏览视图，不占用一个空的左侧列表。原本地文件树中的双栏按钮作为快捷入口保留，仅在独立插件激活时出现。活动栏点击仍经过主区域保存门禁。

Nine Rings 桌面进入双栏浏览后临时收起导航分栏，保留活动栏入口；离开时恢复进入前的面板、固定/隐藏状态与宽度。重复打开不覆盖本次快照。期间点击活动栏、调整分栏宽度、明确收起或切换分栏后，以用户新选择为准；单纯悬停或点击预览空白不算布局调整。目录、书签等已随原文档停放，不清除其固定设置。临时隐藏不覆盖设备长期偏好，手机仍使用原有抽屉规则；独立工作台没有此外围分栏行为。

首次升级仅将旧本地文件启用状态复制到 `nr:pluginFileBrowser`，之后两者独立。原 `nr:local-file-browser` 的目录、标签、位置及收藏/列宽设备键保持不变。双栏插件可自己选择授权目录；只启用它也能打开文本及图片，文本仍复用 `LocalFileView`。它拥有独立的文本和图片视图贡献，避免停用文件树时撤回双栏所打开的视图。

宿主文件资源按插件激活身份持有使用权。停用任一插件只撤回它自己的贡献；两者都停用时才释放目录句柄、取消旧代次并清理内存文件会话。文件服务允许有效的任一文件插件使用，但仍验证读写权限、请求身份和授权代次；失效请求不会因为另一插件还在而获得续权。授权和内容不进入共享备份。

影响分析：沿 `builtin-local-files` 的激活/撤销、`service.guard` 的读写调用、`browser-provider` 的文本/图片打开，以及 `LocalFileView` 相对链接、重命名和 App 最近打开入口追踪。独立视图必须绑定独立激活身份，不能借文件树的视图 ID；资源释放必须等最后一个消费者退出。相关单元测试、Chromium/WebKit 定向回归及完整前端检查通过，结论 **SAFE（上述已验证路径）**；原生 GUI 和系统权限续期仍未现场验证。详细证据见[验证记录](../validation/e2e-repair-progress.md)。

## 三批计划

1. **双栏浏览**：独立目录、前后/上级导航、面包屑与根内路径输入、名称/类型排序、多选、隐藏文件、按名称定位、手动刷新及分页；每栏保留位置和选择，双栏比例与活动栏设备本地记忆。打开文本使用现有本地编辑器，图片复用现有图片查看器，返回恢复浏览状态。所有类型均可列出，超大/二进制文本明确拒绝打开。PDF/EPUB 不自动导入阅读库；额外的非导入式二进制查看适配另行接入。手机改为活动栏显示，可切左右栏。
2. **双栏操作**：复制/移动到另一栏、重命名、新建、系统回收站、冲突决策、进度与取消。跨授权根需单独建立服务契约；首批不显示可执行的占位操作。
3. **效率增强**：目录标签页、快速预览/非活动栏预览、目录比较、批量重命名、搜索及按需求引入其它文件提供者。

## 首批宿主能力

- **目录服务**：复用授权根 ID、相对节点、分页和 stat；不受 UTF-8 文本打开的 4 MiB 限制。每次异步结果验证授权代次；页面取消与请求代次阻止迟到结果覆盖新目录。仅对可视项按需读取属性，限制并发和 DOM 数量，不为目录浏览读取正文。
- **主区域贡献**：添加受限 `file-browser` renderer，只接受授权根身份，不接受路径逃逸或外部组件。注册和打开均检查当前激活的 `views.present`、`filesystem.files.read`。宿主仍负责保存门禁、暂停、返回和插件撤销。
- **浏览会话**：两栏与本地文件树独立；在查看器往返中保留浏览组件及状态。根路径、选择、历史、宽度与滚动仅保存在设备本地，不加入共享备份。Web 临时授权丢失时要求重新选择，不伪称已经恢复权限。

## 插件职责

双栏呈现、活动栏、排序/选择、键盘和菜单属于插件。目录授权、读取、文件打开和编辑保存属于宿主。键盘只在浏览视图内处理，Tab 在两个列表间切换；输入框保留原生键盘行为，不注册全局 Vim 按键。第一批通过本地文件树工具栏的“双栏浏览”进入。

## 状态与生命周期

新的主区域请求先 pending，保存成功后才接受；失败保留原视图。浏览器打开文件后保留返回目标，返回也经过同一保存门禁。浏览器停用、授权撤销或切到无关文档后取消读取，不允许迟到响应重新打开视图。历史长度、选中项与目录条目均有预算；空目录、权限失效、路径消失和本地存储不可写必须有可恢复状态。

## 验证

单测覆盖状态规范化、历史分支、范围选择、分页及旧请求拒绝；注册器覆盖权限、不可变数据、保存期间原视图与停用清理。浏览器测试覆盖两栏互不影响、多选、分页、路径输入、隐藏文件、打开/返回保持滚动和选择、刷新恢复、插件关闭及手机布局。保留已有本地文件、主区域、保存失败和插件安装回归。原生授权及大目录磁盘性能单独验收，不以模拟句柄替代。

## 首批交付状态（2026-11-06）

入口：启用插件及「本地文件」，点击文件树工具栏的「双栏浏览」。两栏复用已经授权的目录，也可分别添加根目录；双击或 Enter 打开选中项，查看器的「返回原视图」返回双栏。单击选择，Command/Ctrl 多选、Shift 范围选择，Tab 在两栏间切换。手机使用左栏／右栏切换。

采用每页 200 条、目录总预算 10,000 条的既有目录服务，列表固定行高并虚拟化，仅对可见文件以最多 4 个并发读取属性。每栏历史最多 40 项、选择最多 2,000 项；设备状态上限 512 KiB。取消阻止接受迟到结果和后续读取，不宣称能中断已经发出的原生 IPC。排序和过滤不扫描文件正文。浏览图片不会向背后的数据库文档提供插入操作。

本地完整前端检查、生产构建通过；双栏及既有本地文件定向 Chromium 8 项通过。WebKit 首轮 7 通过、1 项在创建页面阶段进程关闭；该既有用例单独复验通过，双栏 3 项首轮均通过。没有执行完整 E2E 或原生 GUI 验收。第二、三批后续实现见下文。

## 第二批实施契约

双栏以活动栏的选中项为源，另一栏当前目录为目标，执行前显示来源、目标、数量并确认。复制/移动仅在 Tauri 提供跨根接口，分别核验两个授权；Web 暂不假定 File System Access 具有排他创建或可靠跨根移动能力，仍可使用现有目录内操作。目录快照保持只读。新建、重命名和系统回收站复用已有服务能力。

不自动覆盖或合并目录。同名冲突逐项选择跳过、输入其它名称重试，或停止；已完成项不回滚且明确汇总。取消在当前项结束后停止后续项，不宣称能中断正在运行的原生复制。原生复制先在目标目录创建独占临时目录，复制完成后使用不覆盖的原子改名发布，失败清理自己创建的临时内容。拒绝链接、特殊文件、目录递归环；同磁盘移动使用排他改名，跨设备采用下述 2026-11-08 校验与可恢复收尾契约，不永久删除来源。

所有源路径先检查未保存编辑/恢复草稿；复制明确针对磁盘内容。移动和重命名迁移会话、书签、位置、最近打开和 tab 身份，删除清理已打开身份但不永久删除。目录服务与浏览会话独立：操作冻结捕获的源/目标，不随用户切换活动栏改变；收起或暂停视图不撤销已确认的队列，插件停用阻止启动后续项，正在进行的一项可能已经完成，返回后刷新列表。第二批不改变备份格式。

## 第二批交付与限制（2026-11-06）

双栏上方新增操作条，明确标识来源与目标。复制/移动支持批量确认、同名冲突改名或跳过、逐项进度、停止后续项和部分成功汇总；重命名、新建文件/目录、移入系统回收站复用已有服务。操作完成刷新两栏与本地文件树，移动目录同步修正另一栏位于该目录内的历史与路径。没有自动覆盖、目录合并或失败后自动重试。

原生新增 `local_files_transfer`，保留两个授权根、相对节点与单个名称的契约，不允许前端传入任意绝对路径。复制普通文件字节和目录结构，最多 10,000 项、深度 64，不承诺 Finder 的 ACL/扩展属性完整复制。取消为选中项边界；一个目录的内部复制尚无实时字节进度。此阶段尚未开放跨设备移动，后由 2026-11-08 批次扩展，见下文。复制中进程崩溃可能留下 `.nine-rings-copy-*` 临时目录，当前不会在启动时猜测删除这些目录。

Web 复制和跨根移动按钮禁用并提示需要桌面版；可写授权目录允许新建和重命名，目录快照保持只读，系统回收站仍仅原生支持。浏览器不是以读入文本再写出来的方式复制二进制文件。

验证：完整前端检查（Vitest 223 文件、2483 项）通过，之后补充的迁移/部分失败断言定向 15 项通过；生产构建、Rust 文件服务 4 项和全目标全特性 Clippy 通过。Chromium/WebKit 双栏及既有文件操作各 7 项通过。未运行完整默认 E2E；跨磁盘错误、真实系统回收站和 Windows/Linux 原生 GUI 仍待现场验证。

## 第三批实施契约

- 目录标签页：每栏最多 16 页，每页独立历史、排序、隐藏项、选择与滚动；使用版本化设备状态恢复，原两栏状态迁移为各一个标签。不增加共享备份字段。移动/删除修正所有标签的历史。
- 快速预览：在另一栏显示选中文件的只读磁盘预览，不替换主区域文件会话；保留原目录，关闭即恢复。文本预读前检查 1 MiB 预算、仅显示前 64 KiB 字符；图片预检 8 MiB，拒绝其它二进制，切换/隐藏/停用丢弃迟到结果。手机以预览暂代当前列表，关闭后返回。
- 目录比较：只读比较两栏当前层级，完整分页收集后按同名匹配，对文件读取大小/修改时间；“元信息一致”不等于正文相同，目录内部不递归比较。结果分页展示，读取失败明确为未知，取消/切走终止后续扫描。
- 批量重命名：`{name}`（不含扩展名）、`{ext}`（含点的扩展名）、`{n}`（起始编号）模板，按选中顺序预览。拒绝重复目标和选中项间交换/占用，跳过未变化项，执行复用第二批脏草稿检查、冲突决策和路径迁移；不做自动循环改名或覆盖。
- 正文搜索：复用既有 Worker 搜索与预算，默认活动目录，可取消，结果打开时携带匹配位置及修订；不另写解析器。没有明确来源需求时不添加其它文件提供者。

## 第三批交付（2026-11-06）

上述五项已接入双栏浏览。每栏顶部的 `＋` 创建当前目录的新标签，关闭按钮只关闭标签，至少保留一个；切换或重新进入恢复各自位置。快速预览保留另一栏原目录，关闭预览即可恢复；手机预览暂时代替列表。比较目录、搜索正文使用居中工具弹层，比较结果每页 200 项，并支持过滤及从左/右侧打开。批量重命名的模板和编号输入先生成最多 100 行的预览，确认后冻结计划并执行，未变化项不写磁盘。

目录标签状态使用同一设备键的版本 2 格式，迁移旧两栏状态，不写入共享备份。标签页切换依赖稳定 ID 重新建立可视列表并按保存位置加载分页，不能将两个相同路径标签的滚动位置混在一起。移动/删除作用于所有标签；删除历史条目后保留当前条目的索引，避免误跳到前进分支。原生接口及第二批排他写入规则未改变。

验证：完整前端检查通过（Vitest 224 文件、2492 项）；随后补充删除旧目录历史不改变当前目录的用例，双栏相关 24 项定向通过。生产构建通过，Chromium/WebKit 各 11 项定向通过，包含前三批全部功能与既有本地文件操作。没有运行完整默认 E2E，也未执行原生大目录、磁盘权限续期和系统回收站真机验收。

### 第二批：操作队列与结果（2026-11-07）

确认操作后冻结来源、目标、选中路径及批量命名计划，进入激活身份拥有的串行队列。工具栏「队列」可查看执行中/待执行任务与逐项结果；收起或 Esc 只关闭弹层，执行继续，可以继续确认新任务。切到文件编辑器或返回原视图后仍保留本次激活的队列，再从双栏入口查看。插件停用停止全部后续任务；当前原生写入不强制中断，完成后照常结算。队列不是持久化磁盘任务计划，重启/刷新/重新激活不自动重放。

每个任务最多 2000 项，整个队列最多 20 个任务、4000 个结果条目；达到限制时仅回收最早已结束的结果，不能丢弃仍在排队的任务，空间仍不足则拒绝加入并提示。结果按任务折叠，首屏最多列出 100 项，可继续展开；支持复制结果及清除已结束记录。进度按选中项而非字节计算，整个目录仍计一项；结果显示耗时、成功、跳过、预检失败、未执行及需核对状态。

任务失败暂停后续队列，用户处理后通过「继续排队任务」明确继续。重试只生成包含未执行或预检失败项的新任务；成功、主动跳过以及可能已写入的“需核对”项均排除。未知磁盘/传输/结算错误保守视为需核对，不猜测写入是否发生。已安排重试的记录显示关联新任务，避免双击重复入队；重复失败应查看新任务。对同名目标继续使用原有不覆盖、跳过或另取名称决策。

宿主临时路径锁覆盖当前来源及其子路径，文件编辑器临时只读，保存接口也拒绝写入；不改写只读偏好，结束或失败后释放。队列执行前保持整批草稿预检，每项真正执行前再次检查，避免排队期间新增编辑被忽略。其它本机路径操作同样经原有 `assertLocalPathClean` 门禁；路径锁不是系统级锁，不能阻止外部程序修改磁盘。固定计划不会因其它任务移动路径而自动改写，来源变化将失败并交由用户审查。

### 第二批完成：安全跨文件系统移动（2026-11-08）

`local_files_transfer` 的参数和成功返回值不变。先尝试原有排他重命名，只有明确的 `ErrorKind::CrossesDevices` 才进入跨设备分支；权限、同名或其它错误不得触发复制。源数据不提前隐藏或改名，保证复制中退出后仍可在原位置找到。

跨设备流程使用目标卷上独占的 `.nine-rings-copy-<uuid>` 临时目录：沿用平台文件复制接口、刷新到磁盘并保留普通文件/目录权限；完整列举目录（含隐藏项、空目录）并分块计算 SHA-256，核对相对路径、类型、长度、正文摘要及来源修改状态。目录深度仍为 64、条目仍为 10000，不受文本编辑器 4 MiB 限制。散列按开始时的文件长度分块读取，拒绝增长/截断，避免校验因外部持续追加而无限读取。Unix 临时目录以 0700 创建；符号链接、重解析点和特殊文件拒绝。

校验成功并重新检查授权路径后，排他发布目标；同步目标目录，再校验目标和来源，最后以快速元数据清单复核两者没有在长时间散列期间继续变化。只有这一步通过才把来源送入系统回收站，不做递归永久删除。macOS 使用 NSFileManager，避免 Finder 自动化授权；Windows 在独立 STA 调用 IFileOperation，明确设置 `FOFX_RECYCLEONDELETE`、提前失败及禁止连带操作标识，不仅依赖“尽可能保留撤销”的标识。Linux 使用既有 Freedesktop 回收站实现。回收站不可用时不降级永久删除。Windows 标识语义见 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags)。

发布前错误保留来源，清理本次临时目录；清理失败报告其路径，不删除其它临时目录。发布后任何错误统一为 `MOVE_COPY_PUBLISHED`，队列视为需核对并暂停，不做移动身份迁移，即使底层错误带“目标名称已存在”也不能作为改名重试。发布完成但来源未确认收尾时可能存在两个副本，这是显式可审查状态；成功才迁移会话/书签/位置/最近打开和 tab。进程在发布前退出时来源仍在；发布后退出时目标已经存在，来源可能仍在原位置或已在回收站。重新启动不自动重放任务或猜测清理。

这不是具备系统快照或跨文件系统事务的归档工具。ACL、扩展属性、命名辅助数据流、所有者、硬链接关系等不作完整校验/保留保证；外部程序仍可在最后检查与回收之间修改文件，保留可恢复来源用于这一边界。停止仍在当前选中项结束后生效，大文件校验会产生多轮读取；不虚构实时字节进度。浏览器能力不变。文件树原来的根内移动入口仍使用原生排他改名，跨设备扩展入口在双栏浏览。

影响结论 **SAFE（已验证路径）**：追踪 `move_exclusive` 的根内移动、重命名/回滚、普通复制发布和双栏传输调用，内部返回改为保留 OS 错误种类，对外仍映射原 String 错误。普通复制保留既有平台复制接口，并补充权限及刷新，IPC、授权检查和前端成功迁移接口均未变。新模块隔离清单和复制验证流程；17 项原生文件服务测试及前端回归覆盖数据保留与错误分类。Windows API 已按项目锁定的 0.58 源码核对；Windows/Linux 原生编译与实际跨卷回收站仍需 CI/真机验证，未冒充本机验证结果。

传输还避免在长时间复制/散列期间持有全局目录授权互斥锁，允许后台队列执行时继续读取其它目录；改为短暂加锁核对授权快照，并在发布和回收来源前重查。普通复制也在发布前重查授权。撤销授权不追溯取消已经完成的当前原生项，仍阻止后续项目。

成功移动时，还会先补存已挂载文件的最新光标/视口，再迁移缓存和设备状态；只有受影响的当前挂载失效，避免旧视图卸载重新写入旧路径。宿主 `MainViewRegistry.relocateLocalFile` 原位更新 current/pending 的路径身份及名称，保留请求 ID、暂停状态和不相关的待打开请求，不额外发起导航或越过保存门禁。发布后失败不会调用这一迁移。后台移动期间打开来源文件、完成后跟随目标并保留光标有真实 UI 回归；其它挂载和未来导航不会被强行切回。

### 第三批：受限内容比较、拖放与目录标签（2026-11-08）

仍由 `nine-rings.builtin-file-browser` 可信内置插件贡献入口与主视图。比较、标签和拖放编排均在插件视图及 `browser-*` 模块中；共享宿主继续管理授权、读取、保存门禁和排他写入。本批不新增权限、IPC、第三方可执行代码或文件来源，也不把双栏重新并入本地文件树插件。停用双栏插件后相关界面及异步读取随激活会话释放。

目录比较默认保持当前层元信息模式；用户选择 0–8 层递归及“核验 UTF-8 正文”后明确重新比较才生效。每侧累计最多 10000 项，完整分页且包含隐藏项，越界路径、重复项、分页不前进、目录不可读或超条目预算都停止本次完整结果，不伪称为空目录。名称列显示相对比较根的完整子路径，打开条目使用其实际根内身份；目录行不判定相同，深度边界之外没有认证。

正文模式复用已有文本快照的**原始字节 SHA-256**，不是比较归一化后的显示文本或截断预览；BOM、LF/CRLF 差异仍算不同。单文件最多 4 MiB，两端读取预算合计 32 MiB，顺序读取以限制峰值内存；二进制、非 UTF-8、超预算、读取失败或前后大小/修改时间变化标记未知并显示原因。默认模式不读取正文。取消、关闭比较或停用插件后拒绝迟到结果。此功能是有界文本核验，不是任意大二进制哈希服务、文件系统快照或同步算法，最终读取后仍可能被外部修改。

拖放仅接受本次插件视图中发起、内存保存身份的内部拖动，系统文件/URL/其它页面伪造数据不能成为授权。选中多项时冻结整组；未选中项单独拖动。落在文件夹行以该文件夹为目标，其余列表区域以当前目录为目标；浮层显示目标路径和复制/移动，不挤动列表。默认复制，Shift 表示移动；松开只打开原操作确认，确认后才入队。相同目录、自身/子目录、无桌面传输能力、失效授权仍受校验，不绕过冲突、不覆盖目标。Web 保留原传输能力限制；触屏可继续使用按钮操作，不要求拖动作为唯一入口。

目录标签可拖动在同一栏内排序，Alt+左右键或右键菜单提供等价操作；排序保留稳定 tabId、活动标签和各自历史/滚动位置，不按访问时间重排。固定关闭前需额外确认，不锁定当前路径，也不强行聚集固定项。关闭其它/右侧若包含固定项同样先确认；最后一个固定项确认关闭后保留空白占位标签；最近关闭记录每栏最多 16 个，恢复生成新身份，保留路径、排序及浏览位置。原版本 2 设备状态增加可选 `pinned`/`closed`，旧状态正常读取；恢复不授予目录权限，移动/删除也会迁移/清理关闭记录。状态只在本机保存，不进共享备份。

影响分析：`compareBrowserDirectories` 原四参数调用兼容，新增可选比较选项并提取到独立模块，旧导出保留；`localDirectoryProvider.contentDigest` 是只读适配，前后检查激活与读取状态。`BrowserTabGroup` 新字段可选，追踪 `parseBrowserWorkspace`、活动标签更新、交换/同路径、移动/删除及持久化全部调用。拖放生成原 `BrowserOperation`，原确认、冻结队列、草稿门禁和原生传输不变。验证证据及平台限制见[回归记录](../validation/e2e-repair-progress.md)。

### 接续批：预览与选择反馈（2026-11-08）

延续独立双栏插件的只读适配，未新增权限、IPC、跨平台文件接口或持久化数据。快速预览原有 150ms 防抖、取消及过期结果拒绝继续使用，文本最多读取 1 MiB 并显示前 65536 字符，图片沿用 8 MiB 预读门禁；预览与正文编辑/保存仍分离。

- **预览查找**：仅在已显示文本内做字面搜索，可区分大小写、前后跳转及 Enter/Shift+Enter，最多渲染 1000 个匹配并标注上限。使用原始 UTF-16 位置，不通过改变长度的大小写副本计算偏移；不解析用户正则，不改正文。匹配定位只调整预览滚动区域，不滚动工作区。查找保留文本选择与复制；⌘/Ctrl+F 仅在预览内接管，Esc 先收查找，下一次再收预览并恢复来源列表焦点。查询与大小写选择在逐项预览间保留。
- **连续预览**：标题中的上一/下一按钮及预览标题/按钮区域的上下方向键按当前已加载、排序和过滤后的文件顺序移动，跳过文件夹、不循环、不自动跨根或递归。来源列表原上下键行为保持；预览正文方向键用于滚动，查找输入框方向键保留文本操作。达到加载范围边界明确提示，可回来源列表继续分页，不伪称目录里再无文件。切换只改变当前项/单选，不自动打开编辑器。
- **图片缩放**：复用宿主 `imageFitScale` 和手势缩放因子，适窗不放大小图，100%/200% 按原始像素计算，手动缩放范围 1%–400%；放大后在图像实际范围内双向滚动，普通 touchpad 滚动保持原生行为。Ctrl/Command+滚轮或 Safari gesture 仅在图片预览内缩放，不改变页面或原图。适窗跟随可视区尺寸；换文件重置变换，失败图片有明确提示。此处只做非破坏性查看，不接入图片编辑或修改已有完整查看器的设置。
- **选择大小**：只汇总已加载条目及已知元数据，无新增扫描、正文读取或递归统计。零字节且已有元数据的文件可计入；目录单独标记“未统计内部”，缺少元数据/未加载/无效或溢出数值标记未知，不把目录或未知文件冒充零字节。多选去重，动态元数据会更新结果，列表刷新和既有分页行为不变。

影响分析覆盖 `FileBrowserPane` 的选择、虚拟列表、分页、当前位置和可视高度，以及唯一调用方 `DualPaneFileBrowser` 的来源身份、预览往返和 Esc 层级。新增的预览导航 handle 只操作仍可见且已完成加载的当前列表，不通过 DOM 伪造快捷键，不写文件、不增加共享全局事件。预览文本和图片组件独立呈现；停用/隐藏时原异步读取清理，卸载时事件和 ResizeObserver 释放。结论与证据见[验证记录](../validation/e2e-repair-progress.md)。

### 后续批一：跨会话结果记录（2026-11-09）

队列执行权仍属于当前插件激活，不恢复历史任务。新增 `BrowserQueueHistory` 只保存有界纯文本摘要，完全不反序列化操作对象，不参与 enqueue/retry；存储篡改也没有通往磁盘写入的接口。队列弹层可展开其它会话记录、复制及清除。排队/执行/预检等未确认状态要求手动检查磁盘，其它窗口可能仍在执行，不能据历史认定未写入。

每激活身份独立本机键，不互相覆盖；最多保留最近 5 会话，每会话最多 20 任务，每任务最多前 100 项/10000 字符，序列化整体最多 256K 字符，超限明确截断早期明细。开始前和任务状态变化/终态立即保存，其余进度 250ms 合并；pagehide/停用刷新，停用后当前原生项迟到结果仍可更新原会话。它不是事务日志，不承诺进程崩溃前最后一次进度已落盘，也不提供跨重启直接重试。存储失败只提示，不改变磁盘执行结果；清除当前已结束记录也会清除对应本机会话快照。记录不在共享备份设置白名单中。

影响分析：`BrowserOperationQueue` 原构造调用默认不变，生产工厂才启用结果保存；检查 publish、stop/dispose、冲突等待、终态和清除路径，文件锁/草稿/重试分类未变。界面以 React 纯文本展示，损坏/超限记录拒收；订阅和 pagehide 释放，跨窗口 storage 事件只刷新报告。新增纯状态/存储回归及插件重新激活的真实 UI 回归。设计选择见[宿主边界决策](../decisions/002-dual-pane-file-browser.md)，准确验证见回归记录。

### 后续批二：受限原始字节摘要（2026-11-09）

比较面板提供互斥的 UTF-8 正文和原始字节选项，修改后明确重新比较才执行；默认仍是元信息。原始字节不做文本解码，支持二进制及超过正文 4 MiB 上限的普通文件。相同/不同按 SHA-256 判断，不将文件长度或修改时间当作内容认证；超预算、不支持、权限失败或变化显示未知及原因。

宿主新增只读 `local_files_digest`：仅主窗口和已有目录授权，检查根内路径、普通文件、链接和文件身份，以固定 64 KiB 缓冲读取，单文件硬上限 256 MiB，比较累计上限 512 MiB。开始与结束核对文件身份/长度/时间，结束重新核对授权；不长时间持有全局授权锁，不返回文件正文。流最多读取最初长度加一字节，拒绝增长和截断，不因持续追加无限读取。此处不放大编辑器/预览读入预算，也不新增写权限。

Web 使用授权句柄或本次目录快照中的 File，预检单文件最多 16 MiB、比较累计最多 32 MiB，WebCrypto 计算原始字节摘要，前后核对激活、授权和元信息；不伪称为分块恒定内存计算，较小预算限制 ArrayBuffer 及平台内部副本。串行比较减少同时分配，取消阻止接受结果及下一文件读取；已经发出的原生 IPC/WebCrypto 任务不强行中断。

边界仍是普通文件系统的有界核验，不是文件快照或 ACL/扩展属性/命名数据流归档认证。文件在最后一次检查后仍可能被外部改变；超过 256/16 MiB 或需要无限制目录认证另行设计，不自动提高预算。可信双栏插件通过只读适配调用，现有第三方声明式包没有原生文件权限。接口影响检查包括 Rust 注册、camelCase 的 digest/size/modifiedMs 字段、TS 服务/提供者、比较的旧可选四参数调用及原正文模式，详见验证记录。

### 原生宿主的 HTML5 拖放配置

Nine Rings与独立File Workbench的主WebView都显式设置`dragDropEnabled: false`。本项目拖放由共享DOM组件处理，未注册Tauri DragDropEvent消费者；默认原生处理器会把拖放转换为Tauri事件并消费，导致浏览器中能用、原生包中收不到DOM drop。尤其当前Wry macOS实现会在其处理器返回true时不转交WKWebView，而Tauri默认处理器始终返回true。Windows同样要求关闭WebView2的原生拦截才能使用HTML5拖放。

关闭该处理器不代表增加系统文件导入或目录权限；目标仍必须属于已授权目录、具有写入能力，且只接受本视图生成的内部拖动身份。配置回归同时检查两个宿主，独立入口交互测试覆盖多选、取消后再次拖动、确认后才写入及Shift拖动目录到指定子目录。
