# 双栏文件浏览插件

## 目标与边界

采用 Total Commander 的两个独立目录列表、活动栏与源/目标概念，结合 Finder 的面包屑、详情列表和多选。作为独立「双栏浏览」可信内置插件交付，与「本地文件」共享宿主授权而不覆盖左侧树的导航状态。不是可安装的第三方脚本插件，不开放任意 React/DOM 或文件系统访问。

## 独立插件入口（2026-11-07）

插件 ID 为 `nine-rings.builtin-file-browser`，在设置插件列表独立启停和查看说明。桌面活动栏提供双栏图标，手机从文档树工具区进入；此入口打开主区域浏览视图，不占用一个空的左侧列表。原本地文件树中的双栏按钮作为快捷入口保留，仅在独立插件激活时出现。活动栏点击仍经过主区域保存门禁。

首次升级仅将旧本地文件启用状态复制到 `nr:pluginFileBrowser`，之后两者独立。原 `nr:local-file-browser` 的目录、标签、位置及收藏/列宽设备键保持不变。双栏插件可自己选择授权目录；只启用它也能打开文本及图片，文本仍复用 `LocalFileView`。它拥有独立的文本和图片视图贡献，避免停用文件树时撤回双栏所打开的视图。

宿主文件资源按插件激活身份持有使用权。停用任一插件只撤回它自己的贡献；两者都停用时才释放目录句柄、取消旧代次并清理内存文件会话。文件服务允许有效的任一文件插件使用，但仍验证读写权限、请求身份和授权代次；失效请求不会因为另一插件还在而获得续权。授权和内容不进入共享备份。

影响分析：沿 `builtin-local-files` 的激活/撤销、`service.guard` 的读写调用、`browser-provider` 的文本/图片打开，以及 `LocalFileView` 相对链接、重命名和 App 最近打开入口追踪。独立视图必须绑定独立激活身份，不能借文件树的视图 ID；资源释放必须等最后一个消费者退出。相关单元测试、Chromium/WebKit 定向回归及完整前端检查通过，结论 **SAFE（上述已验证路径）**；原生 GUI 和系统权限续期仍未现场验证。详细证据见[验证记录](../validation/e2e-repair-progress.md)。

## 三批计划

1. **双栏浏览**：独立目录、前后/上级导航、面包屑与根内路径输入、名称/类型排序、多选、隐藏文件、按名称定位、手动刷新及分页；每栏保留位置和选择，双栏比例与活动栏设备本地记忆。打开文本使用现有本地编辑器，图片复用现有图片查看器，返回恢复浏览状态。所有类型均可列出，超大/二进制文本明确拒绝打开。PDF/EPUB 不自动导入阅读库；额外的非导入式二进制查看适配另行接入。手机改为活动栏显示，可切左右栏。
2. **双栏操作**：复制/移动到另一栏、重命名、新建、系统回收站、冲突决策、进度与取消。跨授权根需单独建立服务契约；首批不显示可执行的占位操作。
3. **效率增强**：目录标签页、快速预览/非活动栏预览、目录比较、批量重命名、搜索及按需求引入其它文件提供者。

## 首批宿主能力

- **目录服务**：复用授权根 ID、相对节点、分页和 stat；不受 UTF-8 文本打开的 4 MiB 限制。每次异步结果验证授权代次；页面取消与请求代次阻止迟到结果覆盖新目录。仅对可视项按需读取属性，限制并发和 DOM 数量，不为目录浏览读取正文。
- **主区域贡献**：添加受限 `file-browser` renderer，只接受授权根身份，不接受路径逃逸或外部组件。注册和打开均检查当前激活的 `views.present`、`filesystem.files.read`。宿主仍负责保存门禁、暂停、返回和插件撤销。
- **浏览会话**：两栏与本地文件树独立；在查看器往返中保留浏览组件及状态。根路径、选择、历史、宽度与滚动仅保存在设备本地，不加入共享备份。Web 临时授权丢失时要求重新选择，不伪称已经恢复权限。

## 插件职责

双栏呈现、活动栏、排序/选择、键盘和菜单属于插件。目录授权、读取、文件打开和编辑保存属于宿主。键盘只在浏览视图内处理，Tab 在两个列表间切换；输入框保留原生键盘行为，不注册全局 Vim 按键。第一批通过本地文件树工具栏的“双栏浏览”进入。

## 状态与生命周期

新的主区域请求先 pending，保存成功后才接受；失败保留原视图。浏览器打开文件后保留返回目标，返回也经过同一保存门禁。浏览器停用、授权撤销或切到无关文档后取消读取，不允许迟到响应重新打开视图。历史长度、选中项与目录条目均有预算；空目录、权限失效、路径消失和本地存储不可写必须有可恢复状态。

## 验证

单测覆盖状态规范化、历史分支、范围选择、分页及旧请求拒绝；注册器覆盖权限、不可变数据、保存期间原视图与停用清理。浏览器测试覆盖两栏互不影响、多选、分页、路径输入、隐藏文件、打开/返回保持滚动和选择、刷新恢复、插件关闭及手机布局。保留已有本地文件、主区域、保存失败和插件安装回归。原生授权及大目录磁盘性能单独验收，不以模拟句柄替代。

## 首批交付状态（2026-11-06）

入口：启用插件及「本地文件」，点击文件树工具栏的「双栏浏览」。两栏复用已经授权的目录，也可分别添加根目录；双击或 Enter 打开选中项，查看器的「返回原视图」返回双栏。单击选择，Command/Ctrl 多选、Shift 范围选择，Tab 在两栏间切换。手机使用左栏／右栏切换。

采用每页 200 条、目录总预算 10,000 条的既有目录服务，列表固定行高并虚拟化，仅对可见文件以最多 4 个并发读取属性。每栏历史最多 40 项、选择最多 2,000 项；设备状态上限 512 KiB。取消阻止接受迟到结果和后续读取，不宣称能中断已经发出的原生 IPC。排序和过滤不扫描文件正文。浏览图片不会向背后的数据库文档提供插入操作。

本地完整前端检查、生产构建通过；双栏及既有本地文件定向 Chromium 8 项通过。WebKit 首轮 7 通过、1 项在创建页面阶段进程关闭；该既有用例单独复验通过，双栏 3 项首轮均通过。没有执行完整 E2E 或原生 GUI 验收。第二、三批后续实现见下文。

## 第二批实施契约

双栏以活动栏的选中项为源，另一栏当前目录为目标，执行前显示来源、目标、数量并确认。复制/移动仅在 Tauri 提供跨根接口，分别核验两个授权；Web 暂不假定 File System Access 具有排他创建或可靠跨根移动能力，仍可使用现有目录内操作。目录快照保持只读。新建、重命名和系统回收站复用已有服务能力。

不自动覆盖或合并目录。同名冲突逐项选择跳过、输入其它名称重试，或停止；已完成项不回滚且明确汇总。取消在当前项结束后停止后续项，不宣称能中断正在运行的原生复制。原生复制先在目标目录创建独占临时目录，复制完成后使用不覆盖的原子改名发布，失败清理自己创建的临时内容。拒绝链接、特殊文件、目录递归环；移动只使用排他改名，跨设备失败保留源文件，不偷偷切换为复制后删除。

所有源路径先检查未保存编辑/恢复草稿；复制明确针对磁盘内容。移动和重命名迁移会话、书签、位置、最近打开和 tab 身份，删除清理已打开身份但不永久删除。目录服务与浏览会话独立：操作冻结捕获的源/目标，不随用户切换活动栏改变；视图暂停/停用阻止启动下一项，正在进行的一项可能已经完成，返回后刷新列表。第二批不改变备份格式。

## 第二批交付与限制（2026-11-06）

双栏上方新增操作条，明确标识来源与目标。复制/移动支持批量确认、同名冲突改名或跳过、逐项进度、停止后续项和部分成功汇总；重命名、新建文件/目录、移入系统回收站复用已有服务。操作完成刷新两栏与本地文件树，移动目录同步修正另一栏位于该目录内的历史与路径。没有自动覆盖、目录合并或失败后自动重试。

原生新增 `local_files_transfer`，保留两个授权根、相对节点与单个名称的契约，不允许前端传入任意绝对路径。复制普通文件字节和目录结构，最多 10,000 项、深度 64，不承诺 Finder 的 ACL/扩展属性完整复制。取消为选中项边界；一个目录的内部复制尚无实时字节进度。跨设备移动明确拒绝，用户可先复制、核验后自行决定是否移入回收站。复制中进程崩溃可能留下 `.nine-rings-copy-*` 临时目录，当前不会在启动时猜测删除这些目录。

Web 复制和跨根移动按钮禁用并提示需要桌面版；可写授权目录允许新建和重命名，目录快照保持只读，系统回收站仍仅原生支持。浏览器不是以读入文本再写出来的方式复制二进制文件。

验证：完整前端检查（Vitest 223 文件、2483 项）通过，之后补充的迁移/部分失败断言定向 15 项通过；生产构建、Rust 文件服务 4 项和全目标全特性 Clippy 通过。Chromium/WebKit 双栏及既有文件操作各 7 项通过。未运行完整默认 E2E；跨磁盘错误、真实系统回收站和 Windows/Linux 原生 GUI 仍待现场验证。

## 第三批实施契约

- 目录标签页：每栏最多 16 页，每页独立历史、排序、隐藏项、选择与滚动；使用版本化设备状态恢复，原两栏状态迁移为各一个标签。不增加共享备份字段。移动/删除修正所有标签的历史。
- 快速预览：在另一栏显示选中文件的只读磁盘预览，不替换主区域文件会话；保留原目录，关闭即恢复。文本预读前检查 1 MiB 预算、仅显示前 64 KiB 字符；图片预检 8 MiB，拒绝其它二进制，切换/隐藏/停用丢弃迟到结果。手机以预览暂代当前列表，关闭后返回。
- 目录比较：只读比较两栏当前层级，完整分页收集后按同名匹配，对文件读取大小/修改时间；“元信息一致”不等于正文相同，目录内部不递归比较。结果分页展示，读取失败明确为未知，取消/切走终止后续扫描。
- 批量重命名：`{name}`（不含扩展名）、`{ext}`（含点的扩展名）、`{n}`（起始编号）模板，按选中顺序预览。拒绝重复目标和选中项间交换/占用，跳过未变化项，执行复用第二批脏草稿检查、冲突决策和路径迁移；不做自动循环改名或覆盖。
- 正文搜索：复用既有 Worker 搜索与预算，默认活动目录，可取消，结果打开时携带匹配位置及修订；不另写解析器。没有明确来源需求时不添加其它文件提供者。

## 第三批交付（2026-11-06）

上述五项已接入双栏浏览。每栏顶部的 `＋` 创建当前目录的新标签，关闭按钮只关闭标签，至少保留一个；切换或重新进入恢复各自位置。快速预览保留另一栏原目录，关闭预览即可恢复；手机预览暂时代替列表。比较目录、搜索正文使用居中工具弹层，比较结果每页 200 项，并支持过滤及从左/右侧打开。批量重命名的模板和编号输入先生成最多 100 行的预览，确认后冻结计划并执行，未变化项不写磁盘。

目录标签状态使用同一设备键的版本 2 格式，迁移旧两栏状态，不写入共享备份。标签页切换依赖稳定 ID 重新建立可视列表并按保存位置加载分页，不能将两个相同路径标签的滚动位置混在一起。移动/删除作用于所有标签；删除历史条目后保留当前条目的索引，避免误跳到前进分支。原生接口及第二批排他写入规则未改变。

## 同类产品交互优化（2026-11-07）

参考 [Double Commander 官方快捷键](https://doublecmd.github.io/doc/en/shortcuts.html) 中的列表导航、功能键、换栏和交换/对齐目录，以及 [Apple Finder 快捷键](https://support.apple.com/en-mide/102650) 的空格 Quick Look。以下为适配 Nine Rings 的选择，并非逐项复制：不注册全局功能键，不把删除变成永久删除，不覆盖 Web 保留组合，也不通过快捷键绕过原生能力和操作确认。

本轮优化：

- 紧凑工具栏分成“文件操作”和“浏览工具”，按钮保留完整可访问名称和悬停提示；宽度不足 880px 时隐藏按钮内的功能键文字，按真实工具栏宽度判断，提示仍保留。文件夹与文件图标分色，每栏标记来源/目标。
- 焦点在文件列表时，Tab 换栏，Space/F3 切换快速预览；F2 重命名、F5 复制、F6 移动、F7 新建目录、F8 移入回收站，全部仍受原能力门禁与确认。禁用 F5 时也防止浏览器刷新。Esc 先关闭预览并恢复列表焦点；输入框、弹层与编辑器不采用这组列表快捷键。物理功能键和系统菜单的原生路由仍需真机核验。
- Home/End/PageUp/PageDown 针对已加载条目，Shift 扩展选择，Insert 切换当前项选择，普通箭头只在行超出可视区时进行最小滚动。输入连续字符按约 0.9 秒的前缀定位，重复同一首字母循环匹配；它只定位已加载条目，不伪称搜索整个目录，全文/全部名称过滤仍使用既有入口。
- 当前项与多选分开：轻描边代表当前项，底色代表选中。当前项的 tab/root 身份独立传递给快速预览，取消它的多选标记后仍能预览，不能混入另一个标签或根的当前项。修改名称过滤或隐藏项范围清空选择，防止对已不可见项目执行操作。
- “交换两栏”交换完整标签组并让活动栏跟随原内容；“两栏同路径”只把另一栏的活动标签导航到来源目录，保留其历史及其它标签。目录标签采用 roving tabIndex，方向键、Home/End 切换后恢复实际键盘焦点。
- 横向滚动同步列标题，标题宽度依据列表 clientWidth 计算并排除滚动条；窄屏和固定 32px 虚拟行共同使用相同的 363px 最小列宽。

影响分析：**SAFE（已验证范围）**。检查了唯一的 `FileBrowserPane` 调用方、`browser-tabs.ts` 所有调用及状态恢复；交换/对齐只修改设备 UI，原生文件服务、共享备份、排他传输与草稿门禁均未改变。`browser-keyboard.ts` 的定位与最小滚动、`browser-tabs.ts` 的交换/对齐均有单测；快捷键范围、隐藏选择清理、取消选择后的预览、焦点恢复与宽窄列对齐由 Chromium/WebKit 定向用例检查。未进行完整 E2E 或原生 GUI 验收，不能将 DOM 功能键事件等同系统菜单/物理 Fn 键路由已验证。

WebKit 验证发现并修复了新建标签立即编辑路径的初始化覆盖风险：路径字段改在 layout effect 同步，延迟恢复焦点时先确认用户尚未转向别处，不能覆盖已经进入输入框的焦点。窄面板导航工具采用自身横向滚动，避免按钮最小宽度撑出工作区。路径导航测试先确认目标文件可见，再切换其它同名标签，不依赖命令刚返回时的中间 DOM。

## 后续三批优化计划（2026-11-07）

1. **日常浏览效率（本批实施）**：自定义右键菜单（打开/预览、复制名称/目录路径/完整路径、已有文件操作，右键选中项保留多选）；名称/大小/修改时间列宽与标题排序；最近路径和常用目录；接近底部自动加载下一页，并保留手动重试。列宽与常用目录仅在本机保存，大小/时间排序须在完整目录范围内、分页之前执行，不伪装为当前页排序。粘贴路径只接受当前授权根内的相对路径或明确解析在已授权根内的绝对路径，不自动扩大授权。
2. **操作可靠性**：可回看的队列与结果记录、失败项独立重试；复制核验后再处理来源的跨磁盘移动；外部创建/改名/删除检测。优先保证不重做成功项、不误删来源及保持当前选择/位置。另行设计任务持久化与取消边界。
3. **进阶效率**：按需文本/哈希内容比较与受限递归、带明确目标和复制/移动反馈的拖放、标签拖动排序/固定/关闭其它/恢复关闭标签。它们不随本批隐式开放。

后续可随批完善：预览内查找与图片缩放、方向键连续预览；选中文件已知大小与尚未统计目录的明确区分。本批不引入额外写权限，不加入永久删除或覆盖策略。

### 第一批交付与影响分析

已实现文件右键菜单、名称/大小/修改时间排序、列宽拖动和键盘调整、路径历史、常用目录、临近底部自动分页。右击已选项保留多选，操作明确绑定来源栏与选择快照，沿用确认、脏草稿检查和写入能力门禁。列宽按物理栏保存；名称默认填满剩余空间，手动调整后采用指定宽度，双击分隔条恢复默认。

排序在完整目录上执行后再分页，目录始终在前；原生服务使用元数据，浏览器仅在大小/时间排序时以最多四路读取文件元数据，不读取正文。`FileNode.modifiedMs` 是可选字段，Rust 序列化为同名 camelCase；不增加 IPC 命令或权限。原名称排序与旧设备状态仍兼容。

路径输入先验证目录存在，绝对路径只能解析至已授权根，不扩大授权。常用目录、列宽和历史留在设备，不进入共享备份；浏览器无法获取系统绝对路径时，复制完整路径以授权根名称起始。授权失效的收藏不能直接访问，可清理后重新授权。迟到的路径检查与分页结果按请求取消/身份拒绝，分页失败停止自动重试，保留手动重试入口。

共享 `NotesContextMenu` 新增的标签和触发按钮处理均为可选参数，默认维持原随记菜单行为。列头组件独立处理指针捕获和键盘调整，不改变列表虚拟化的行高。影响结论 **SAFE（已验证路径）**：相关前端、Rust、跨浏览器回归未发现退化；原生 GUI、真实权限续期及三平台大目录性能仍需现场验收。实现入口为 `FileBrowserPane`、`FileBrowserLocations`、`FileBrowserColumnHeaders`、`browser-preferences` 和 `commands/local_files.rs`。

### 第二批：外部变化检查（2026-11-07）

复用原文件树的低频检查策略，不新增系统 watcher 或 IPC。仅前台有焦点、实际可见且已授权的目录参与；窗口重新获得焦点时补查。每轮完成后至少空闲 5 秒，按已加载页数逐步延长间隔，10000 项时为 50 秒。后台、隐藏的手机目录栏、目录切换、插件停用取消接受旧请求；操作/比较/搜索弹层、菜单、文本输入或分页未结束时暂停。临时目录快照不能观察磁盘变化，继续保留手动刷新。

每次读回原先已加载的分页范围，沿用排序/隐藏项/名称过滤，不递归目录、不读取正文。原生列表自带大小与修改时间；浏览器目录句柄仅补读可见行（最多 64 项、四路并发）的元数据。窗口及目录在读取期间变化会丢弃结果，不把过期结果应用到新目录；分页游标不前进、空页循环及读取失败明确报错，每次连续失败只提示一次，下一轮可恢复，也可手动刷新。单项元数据无法读取不代表文件已删除。

列表变化直接替换节点数据，不进入 loading 或清空列表。按首个可见项及后续两个候选的屏幕偏移恢复位置，目录变短时夹取合法滚动范围，横向滚动和标签不变。完整列举才能清理已消失的多选项；部分列举保留无法证明被删除的选择。失效元数据从缓存移除，变化可刷新当前快速预览，但不覆盖编辑器的未保存内容。外部重命名视为移除/新增，不猜测文件身份，不自动迁移历史路径；目录本身被删除或权限失效时保留列表并提示，用户可返回上级或重新授权。

影响分析覆盖 `FileBrowserPane` 的分页/滚动/选择、`DualPaneFileBrowser` 的操作弹层及预览修订、`localDirectoryProvider` 的激活身份校验。新增 `readBrowserRefresh` 和 `useFileBrowserRefresh`，未改变共享目录服务接口、写入逻辑或持久化格式。核心读取与锚点计算有取消、分页边界、并发预算和删除/插入测试；跨浏览器用例覆盖定时检查、可视锚点、多选、菜单暂停和迟到结果。结论 **SAFE（定向验证范围）**；实际三平台磁盘目录性能及原生授权场景仍待现场验收。

### 第二批：操作队列与结果（2026-11-07）

确认操作后冻结来源、目标、选中路径及批量命名计划，进入激活身份拥有的串行队列。工具栏「队列」可查看执行中/待执行任务与逐项结果；收起或 Esc 只关闭弹层，执行继续，可以继续确认新任务。切到文件编辑器或返回原视图后仍保留本次激活的队列，再从双栏入口查看。插件停用停止全部后续任务；当前原生写入不强制中断，完成后照常结算。队列不是持久化磁盘任务计划，重启/刷新/重新激活不自动重放。

每个任务最多 2000 项，整个队列最多 20 个任务、4000 个结果条目；达到限制时仅回收最早已结束的结果，不能丢弃仍在排队的任务，空间仍不足则拒绝加入并提示。结果按任务折叠，首屏最多列出 100 项，可继续展开；支持复制结果及清除已结束记录。进度按选中项而非字节计算，整个目录仍计一项；结果显示耗时、成功、跳过、预检失败、未执行及需核对状态。

任务失败暂停后续队列，用户处理后通过「继续排队任务」明确继续。重试只生成包含未执行或预检失败项的新任务；成功、主动跳过以及可能已写入的“需核对”项均排除。未知磁盘/传输/结算错误保守视为需核对，不猜测写入是否发生。已安排重试的记录显示关联新任务，避免双击重复入队；重复失败应查看新任务。对同名目标继续使用原有不覆盖、跳过或另取名称决策。

宿主临时路径锁覆盖当前来源及其子路径，文件编辑器临时只读，保存接口也拒绝写入；不改写只读偏好，结束或失败后释放。队列执行前保持整批草稿预检，每项真正执行前再次检查，避免排队期间新增编辑被忽略。其它本机路径操作同样经原有 `assertLocalPathClean` 门禁；路径锁不是系统级锁，不能阻止外部程序修改磁盘。固定计划不会因其它任务移动路径而自动改写，来源变化将失败并交由用户审查。

已经开始的保存单独登记在途写入，不依赖 React 保存状态是否及时提交；相交路径的任务在预检时拒绝启动，并提示保存完成后明确重试。普通保存不会令编辑器只读或禁止继续输入。成功、失败及提前校验拒绝都释放写入登记。Markdown 渲染视图在临时锁期间只显示不可切换的只读标识，避免误把临时状态写入用户权限偏好；解除锁后恢复原编辑能力。

影响分析：`runBrowserOperation` 仅增加可选结果观察回调，所有旧调用兼容；观察者异常不能改变磁盘操作结果。`assertLocalPathClean` 增加可选租约，默认调用仍检查未保存编辑，同时拒绝其它执行中路径的冲突；只有当前执行器可绕过自己的锁。`localFileService.write` 拒绝被占用路径，`LocalFileView` 订阅临时锁后恢复原只读状态。原生接口、同步格式和用户权限偏好不变。队列控制、锁释放、停止、冲突和重试均有单测及浏览器回归；结论 **SAFE（已验证调用路径）**。真实跨平台磁盘异常和应用强制退出期间的原生在途写入仍需现场验收。
