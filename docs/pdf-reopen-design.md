# PDF 关闭重开与资源管理（2026-09-11）

## 问题与处理

旧版本的 documents 记录同时包含阅读进度和原文件 Blob，保存页码会重写整个记录；关闭时也没有等待最终进度提交。当前改为数据库 v3，files 单独保存 ArrayBuffer，documents 保存元数据。旧 Blob 在成功读出完整字节后原子迁移，读取失败保留原文件记录，迁移时重新读取最新元数据，避免覆盖其它窗口的进度。

同一本文件的读取、迁移、保存和删除按顺序执行。关闭先提交最新页码，失败时留在阅读器中给出重试提示；重复关闭不会重复提交。组件卸载仍有兜底保存，后台切换也立即提交进度。重试打开按钮可重新创建加载任务。

源字节采用最多三份、总计 64 MiB 的 LRU 缓存，最后访问及关闭后保留两分钟。每次打开仍查最新元数据与批注。超预算的大文件不保留额外缓存副本，不缓存 PDF 密码或跨实例 Worker；缓存仅在当前页面内有效。删除同时移除源文件与缓存，迟到的关闭回调不会恢复已删除文件。

PDF.js 会转移输入缓冲区给 Worker，因此缓存文件交付副本，超预算且不缓存的文件直接交付本次读取的数据。每个阅读器独立拥有 Worker；关闭时取消渲染并记录异步销毁任务，下次打开同一文件先等待销毁结束。旧实例回调不能关闭新实例。

## 同类产品调研与取舍

| 来源 | 观察 | 本次采用 |
| --- | --- | --- |
| [PDF.js 官方阅读器 open/close](https://github.com/mozilla/pdf.js/blob/master/web/app.js) | 打开前 await 旧文档 close，销毁加载任务 | 等待旧 Worker 清理；分别管理源字节缓存与活跃文档 |
| [PDF.js API](https://mozilla.github.io/pdf.js/api/draft/api.js.html) | 输入数据可能被转移，文档清理不能与渲染同时随意执行 | 缓存源字节交付副本；保留已有逐页任务取消和文档代次检查 |
| [PDF.js 页面缓冲](https://github.com/mozilla/pdf.js/blob/master/web/pdf_viewer.js) | 有限页面 LRU，按可见页数量调整 | 保留当前可见页优先、邻页闲时渲染和有像素预算的位图缓存 |
| [Zotero PDF 阅读视图](https://github.com/zotero/reader/blob/master/src/pdf/pdf-view.js) | 后台暂停渲染，可按可见页及邻页修剪缓存 | 页面进入后台暂停栅格化，恢复后重启有效任务；立即保存进度 |

这些实现提供资源所有权与生命周期方面的依据，不意味着直接沿用其它阅读器的内存限额。Zotero 保留活跃解析实例的策略涉及其宿主环境；本次没有让已关闭的 Worker 长期驻留，也没有扩大手机画布预算。隐藏桌面分栏的定时资源休眠、跨刷新磁盘缩略图缓存、扫描版分块读取可另行评估，需先测量内存与恢复延迟。

## 验证

- 单元测试：缓存容量、过期、数据转移、清理顺序，以及原有 PDF 存储与单书阅读备份。
- Chromium/WebKit：v2 Blob 迁移及 NotFoundError 故障注入、冷启动、文件指纹/备份、删除、连续四轮立即关闭重开、后台恢复。
- 保留并运行 60 页往返滚动压力测试与解析中关闭 Worker 测试；入口更新为当前手机阅读手势。
- iPhone 原设备如已丢失旧 Blob 的底层字节，本次不能重建文件；会保留记录并明确提示读取阶段错误。
