# 首次内置插件宿主前置审计

> 2026-10-11。范围是可信内置代码的首次试点，依据当前实现和本地回归。门禁状态统一记录在[推进待办](plugin-readiness-todo.md)；第三方插件安装、公开 SDK 稳定性和全产品发布验收另行处理。

## 1. 门禁范围与结论

R1～R6 已通过首次可信内置宿主范围的前置检查，可开始日期插入、当前文档统计等试点。它们覆盖实际编辑、持久化、权限、消息和生命周期边界，不要求先完成全部产品优化。围栏渲染试点还要完成 C4；第三方声明式包安装还要完成 R7，二者不能由本审计代替。

本轮不改变共享文档、备份或数据库格式。插件总开关默认关闭，仅在本机记忆且排除备份。当前可调用接口保持内部试验状态，没有加载外部脚本、插件市场或第三方授权安装入口。

| 门禁 | 已接入的边界 | 可复核证据 |
| --- | --- | --- |
| R1 当前契约 | 现有功能、退役功能、目标设计与实现状态分开；版本为 0.2.0 | `plugin-system-design.md`、`plugin-release-plan.md`、`current-design.md`、推进待办 |
| R2 写入权限 | SDK 不公开 api/adapter/SQL。活动选区插入及快照检查授权、存在性、路径、只读/保护状态；保护锁内每次异步等待后重查目标和上下文 | `plugin-system/document-intents.ts`、`command-dispatcher.ts`；直接调用、保护/取消与真实编辑器回归 |
| R3 修订与目标 | 逻辑正文/属性修订、文档代次、视图/选区代次、激活代次分别管理；投影/保存回显不接受第二次编辑；正文替换使旧驻留模型无法取得新目标 | `document-save-revisions.ts`、`document-edit-sessions.ts`、双编辑器/驻留/替换回归 |
| R4 保存确认 | 编辑接受与保存成功分开；按实际字段确认水位。后台文档可等待原修订，失败/取消/恢复不伪造成功；管理和检查点等待真实队列 | `auto-save-queue.ts`、`document-write-coordinator.ts`、保存失败/检查点/跨窗口回归 |
| R5 命令契约 | 受限参数编译器、默认 scope/view/platform/exposure、入口检查、请求去重、超时/取消和类型化错误。迟到处理不得提交到另一个目标 | 参数/调度器单元测试、schema 回归及 SDK 双编辑器回归 |

R3 的共享逻辑修订不表示渲染与源码共享撤销栈。两套编辑器保留自己的撤销机制；插件插入在当前视图中形成单步撤销。精确增量范围、每次变化的完整原因分类及跨视图撤销属于后续接口/产品工作。

## 2. 写入及重新载入审计

| 实际入口 | 协调路径 | 关键保证 |
| --- | --- | --- |
| 渲染正文、源码正文、各自撤销/重做 | 编辑会话 → AutoSaveQueue → api.notes.update → protectedAdapter | 接受批次登记一次；存储确认推进实际已成功字段；PM 正文与引用/书签映射共用批次 |
| 普通属性、标题、标签及排序 | coordinateDocumentUpdate / writeThrough | 与正文共用写入顺序；调用时冻结；旧失败不能覆盖新字段 |
| 创建、导入 upsert | protectedAdapter.prepareCreate；upsert 先进入管理屏障 | 规范化实际路径，保留匹配文档保护；upsert 返回后失效旧驻留模型 |
| 显式外部 Markdown 替换、内置示例正文升级 | api.notes.replaceContent → coordinateDocumentReplacement | 替换前保存，成功后在解除屏障前失效旧模型；元数据更新仍走普通属性队列 |
| 删除/回收站、批量只读、目录/文档移动 | coordinateStorageMutation → 既有受保护适配器 | 先排空正文；管理请求串行；过程中暂停编辑，旧目标失效。管理权限不等于插件写入权限 |
| 文档/路径密码管理 | coordinateStorageMutation → withProtectionWrite → 原有原子保护提交 | 不将解锁正文提供给首期插件；保护变化与插件检查共用锁 |
| 历史版本恢复 | coordinateDocumentReplacement → restoreNoteVersion | 恢复前排空保存；成功后旧模型无法重新捕获目标，新的加载实例恢复访问 |
| 备份/手动同步载入 | 恢复上下文 → coordinateStorageReplacement → 设备存储代次 | 同源新版窗口的旧快照失效，保留草稿；不自动覆盖恢复内容 |
| 显式版本检查点 | coordinateDocumentCheckpoint / withSavedNote | 最新已保存正文在检查点前；保存失败不创建历史，后续写入不能越过检查点 |
| 自动外部载入、用户载入外部版本 | discardAndDrain、读取后核对当前选择、显式重建编辑器 | 活动写入完成后再载入；迟到结果不替换另一个文档 |
| 退出、Web 更新并刷新 | 先 suspendPluginWork，再真实保存屏障 | 阻止最后一次保存后的迟到插件编辑；失败恢复开关但不复活旧任务，遵循其它窗口的关闭偏好 |

`api` 和原生存储适配器属于可信宿主内部接口，不是安全沙箱。未来贡献点必须调用受限服务；不能把内部 API 导出给插件后宣称继承本门禁。正文替换须走专用替换入口，不能以任意普通属性写入冒充已加载新正文。

恢复互斥目前覆盖同源、运行新版代码的普通文档写入。独立原生进程、旧客户端、直接数据库操作和全部阅读器/配置写入不是全局事务互斥对象；这不构成允许插件访问这些入口的理由。

## 3. 消息、事件与生命周期预算

- protocol 1 仅传校验并复制的 JSON：128,000 UTF-8 字节、深度 16、4096 值；拒绝保留键、访问器、循环及未知协议字段。回环和端口使用相同边界。
- 每连接最多 32 个进行中请求、4096 个已用请求 ID；饱和时仍可取消/释放。编辑目标及保存修订各 256 项，目标单次使用、五分钟失效且不可跨连接。
- 每连接 8 个订阅，每订阅 32 条摘要。订阅同步安装于快照最后一次校验处；相邻同类合并或溢出要求 resync。每次读取前最多一个可用信号，100 次连续变化不会产生 100 次通知；不自动传全文或轮询。
- 快照及事件读取重新验证授权、当前文档/视图/平台、保护与代次。超过消息预算明确失败并释放未交付订阅，不截断正文；编辑已接受时错误仍保留 applied 状态。
- 停用、重激活、关闭总开关撤销授权、取消任务、逆序清理命令/连接/订阅/令牌。端口先交付已接收请求终态再发送关闭控制消息，客户端不再等到普通超时。
- 可信激活/停用钩子受异步超时和并发监督，资源由激活统一拥有；清理失败记录安全错误码，不阻止其它资源。同步死循环无法用同线程计时器强制终止，因此本机制不是不可信代码隔离。

## 4. 验证记录

本地隔离工具链执行，浏览器为 macOS 上 Chromium/WebKit。最终代码检查和测试结果记录于推进待办批次 19；前序批次结果保留日期和范围，不能将重复运行相加为独立测试数。

- 完整 Vitest：94 文件、1368 项通过；`npm test` 包括插件 schema 的 56 项回归。
- typecheck、完整 lint、既有 format:check、生产构建、bundle-size 和 IPC 静态契约检查通过。
- 既有覆盖率门禁通过；其配置只统计既有指定模块，不是新增插件模块的整体覆盖率承诺。
- 共享编辑/保存/管理/驻留/跨窗口综合回归，以及 SDK、通知、IME、开关/诊断、加密和模拟退出回归覆盖两种浏览器。新回归使用实际版本恢复，确认仍挂载的旧源码编辑器不能取得新目标或快照。
- 原生 Rust 库测试 57 项通过。IPC 检查证明调用名注册/实现一致，检查脚本尚未完成完整适配器接口覆盖解析。
- 最终相关 4 文件综合回归 Chromium/WebKit 各 9 项通过；生产 PWA 更新 5 项通过。此前 WebKit 设置刷新用例因界面未就绪而提前发送快捷键超时，补等待实际界面出现后，整组重新执行通过。

未执行全产品 E2E、原生 GUI 交互、Windows/Linux 真机退出/重启及 Flutter/iOS 构建。浏览器中的 Tauri 退出事件模拟不是原生退出真机证据；MessageChannel 不是第三方沙箱或原生 IPC 来源隔离。后续实际贡献点及原生发布仍应按范围补验证。
