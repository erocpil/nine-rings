# 文档类型、源码权威与预览

2026-10-20。文件格式已经具有实际的视图与保存语义，不再仅是源码高亮偏好。

## 视图能力

| 类型 | 渲染 | 源码 | 并排预览 |
| --- | --- | --- | --- |
| Markdown | 普通文档渲染 | Markdown 编辑与微渲染 | 支持 |
| Flow | 整份源码的流程展示 | Markdown 形式的 Flow 源码 | 支持 |
| Mermaid | 整份源码的图表 | Mermaid 源码与基础高亮 | 支持 |
| Text、C、Python、JSON 等 | 不提供 | 纯文本或对应语言高亮 | 不提供 |

独立 Flow、Mermaid 文档无需外层代码围栏；嵌入 Markdown 时继续使用原有 Flow、Mermaid 代码块。预览是只读投影，修改正文需要回到源码；文档本身仍可设置只读，禁止源码编辑和格式更改。

并排预览沿用现有桌面布局，手机保留源码/渲染单视图切换。不可预览的类型隐藏渲染、并排预览和 Markdown 专用工具；查找替换、行号、软换行、语法折叠、撤销重做、缩进、书签和状态栏继续复用。Flow 源码可以使用 Markdown 编辑辅助；Mermaid 和普通代码不会继续 Markdown 列表，也不会响应粗斜体等 Markdown 命令。

## 数据权威

Markdown 保持现有 Delta 与渲染编辑器的权威边界，`markdownSource` 保留未经渲染编辑改写的原始 Markdown。

非 Markdown 文档以 `DocumentMetadata.sourceText` 保存原始源码；`ops` 是通过 `plainTextToDelta` 生成的可搜索纯文本投影，不经过 Markdown 解析。`sourceLanguage` 决定文档类型，`sourceFormat: text` 防止普通文本中的表格、列表等符号被历史兼容逻辑重新解释。发布元信息的 `language` 仍表示自然语言。

原有纯文本导入若没有 `sourceText`，从纯文本 ops 恢复；此前只选过语法、但尚按 Markdown 存储的文档，优先使用保留的 `markdownSource`，再使用结构化序列化结果。新导入按扩展名推断类型，并立即保留源码。编码和换行解码沿用现有文本导入约定，不新增字节级文件编码编辑能力。

源码修订使用 `SourceNavigationSession`，非 Markdown 分支构造字面段落模型，并按原始行建立导航位置；不会为了目录、书签或同步滚动再调用 Markdown 解析器。Flow、Mermaid 的预览模型单独把整份源码作为一个相应代码块投影，不替换源码权威。

## 格式切换

状态栏和 macOS“格式 → 文件格式”共用文档语言选项与同一条保存链路；文档选项从代码块语言中派生，并合并 C/C++、排除 C#。

1. 刷新当前未保存的正文。
2. 取得当前完整源码；源码视图优先读取活动 CodeMirror 文档，渲染 Markdown 优先读取保留源码。
3. 切换到 Markdown 时解析为 Markdown Delta 并保存 `markdownSource`；切换到其它类型时保存 `sourceText` 与纯文本投影。
4. 通过现有正文保存链路提交，同时映射内部引用与书签；不能将表示方式变化冒充 metadataOnly 更新。
5. 按新类型启用或隐藏视图入口。源码中的字符、缩进、空行不会因文件格式选择而添加转义或被裁剪。

修改同一个源码视图的类型时不重建 CodeMirror，保留选区及编辑历史。Markdown 与纯文本之间解释方式不同；当切回渲染并继续编辑时，后续源码标准化仍遵循既有 Markdown 编辑规则。选择已生效的类型是空操作。

## 语法、预览与故障

CodeMirror 使用 Compartment 切换语法，按需加载 `@codemirror/language-data`；Text 不安装解析器，Flow 复用 Markdown，Mermaid 使用轻量词法高亮，真正的图表校验仍由 Mermaid 渲染器负责。异步语言请求具有失效检查，旧请求不能覆盖新选择。

独立预览复用 `FlowBlockContent` 和 `MermaidDiagram`。并排预览复用同一代码块渲染器，保证语法和主题一致。Mermaid 错误不会改写或删除原文；源码入口始终保留，用户可返回修正。编辑类插件在只读预览表面禁用，切回源码后恢复相应能力。

纯文本/代码保持源码视图，重开恢复源码滚动位置。Flow、Mermaid 可恢复上次渲染/源码选择；源码与图形不具有逐行一一对应关系，并排滚动使用现有锚点及滚动范围映射。

## 导入、导出与增量备份

文本导入白名单扩展到支持的代码及图表扩展名；仍先解码文本、拒绝二进制控制字符。单文档导出使用对应扩展名，原始源码不添加 Markdown 标题、不裁剪尾部空白。

增量元数据认证允许 `sourceText`，并核对其纯文本投影与正文一致。Flow、Mermaid 派生资源复用现有可移植资源检查；源码中包含不能备份的本机图片引用时不能绕过认证。源码字符串作为文字保存，不被当成 HTML 插入页面。

## 验证

单测覆盖类型能力矩阵、菜单枚举、扩展名推断、原始源码往返、纯文本导航及备份认证。Chromium/WebKit 交互回归覆盖源码专用入口、Markdown 命令门禁、空行和缩进、撤销/重做、Text/Markdown 往返、Flow/Mermaid 三种视图、连续重开和 Mermaid 错误恢复。macOS 原生菜单的实际展示需要重新构建 Tauri 后确认，浏览器测试使用同一宿主命令注册器。

### 代码类型与粘贴保真

文档格式列表合并显示 C/C++，旧 C++ 文档按该类型打开；C# 不再作为可选文档格式，既有 C# 原文仍可作为纯文本打开。代码块自身的语言列表不受影响。代码与纯文本源码使用等宽字体，独立于正文排版字体。

源码粘贴读取纯文本，不采用剪贴板的 HTML 排版。Markdown 语法高亮或微渲染只是显示层，不应改写字符。回归验证包含带 HTML 的 C 源码粘贴、渲染往返、切换 C/C++、保存重开，检查符号、Tab、空行和尾部换行。

### C/C++ 分类高亮

`source-code-highlighting.ts` 复用 CodeMirror/Lezer 的 C++ 语法树，为 C/C++ 文档提供独立分类样式。宏定义名称补充 `PreprocDirective/Identifier` 的上下文标记，不用正则猜测符号。控制关键字、定义关键字、修饰符、类型、函数定义/调用、成员、宏、预处理、字符串/字符/转义、数值与注释分别展示。普通变量继续使用正文颜色，函数定义适度加粗。

颜色使用当前风格的 `--syntax-*` 色值；对比度不足的关键字和预处理颜色与正文色混合。语法高亮关闭时取消分类色及额外字重，不修改源码或撤销历史。本能力仅为语法分析，不保证解析宏展开后的类型、跨文件符号及编译条件。

### C/C++ 本文件符号大纲

C/C++ 文档复用源码模式既有的目录面板及固定/悬停状态，面板名称为“源码符号”；Markdown 继续显示标题目录。大纲当前由 `source-symbols.ts` 适配 CodeMirror 的 C/C++ Lezer 解析器生成，包含命名空间、结构体/联合体/枚举、类型别名、类型成员、函数定义/声明及文件级变量。函数体内的局部变量不进入大纲。列表以 `{}`、`ƒ`、`T` 等窄标记区分类型、函数和别名，并采用较紧凑的行高；成员显示为 `name: type`，函数签名包含可解析的返回类型。原始 `text` 保留解析器识别的名称/签名，单独的展示文本用于列表，不改写源码。

源码变化先合并到短暂快照，再延迟解析；解析以小时间片协作推进，用户继续编辑或切换文档时会取消旧任务。目录列表复用已有折叠、当前项跟随、滚动定位和展示配置。解析不依赖光标移动，因此光标更新不会触发全文解析。用户在延迟更新窗口内点击旧列表时，先用源码编辑映射得到近似位置，再对最新缓冲区解析并按“类别 + 符号名”重新定位；重名符号取距离原位置最近的一项。如果解析期间源码仍有变化则重试，符号已改名/删除或无法取得稳定快照时不猜测跳转位置，等待大纲刷新。这样插入/删除前置内容或修改参数后仍优先跳到当前声明，而不是沿用过期偏移。

源码模式的书签仍是文档级 `metadata.bookmarks`，与渲染模式共用 ID、名称、创建时间及 ProseMirror 位置；源码解析层额外维护原始源码偏移，供源码跳转使用。添加时按光标所在文本块建立锚点，编辑时跟随源码位置映射并刷新摘要；重命名和删除直接更新同一份元数据。切换回 Markdown 渲染视图或重新打开文档后，书签仍对应同一文本块。源模式侧栏复用渲染模式的书签行、重命名对话框、删除操作和展示插件。

这是语法级单文件大纲，不提供跨文件索引、宏展开或编译条件下的语义保证。未完成/不完整的源码由容错语法树尽力识别；无法识别的声明暂不列出，不影响编辑和跳转到其它已识别符号。单元测试验证常见符号类别、嵌套层级、原始偏移及取消行为；浏览器回归验证 C/C++ 面板入口和跳转。

后续如扩展跨文件索引，需另行设计 Web/Tauri 的目录授权、文件索引和语言服务接入；不能把当前本文件解析器描述成项目级语义索引。

### 源码换行缩进

非 Markdown/Flow 源码的 Enter 使用 `source-newline.ts`：优先执行 CodeMirror 原生换行与语言缩进，再对普通单换行补充当前行的手动缩进。语言建议缩进不大于原缩进时保留原始空格/Tab 前缀；语言要求更深缩进、匹配括号的双换行，以及当前行以闭合括号开始的退缩进，继续使用原生规则。修正合成为一次编辑事务，光标移动到继承缩进之后，支持多光标与撤销，不改写粘贴内容或其它行。Markdown/Flow 保留原有列表和引用续写规则。

### Tab Size 与缩进方式

非 Markdown/Flow 的源码状态栏显示 Tab Size（2/4/8，默认 4）和缩进方式（Tab/空格，默认 Tab）。选项保存在本机工作区设置中，编辑器的 Tab 显示宽度、Tab 键缩进及语言换行缩进同步生效。既有其它 Tab Size 设置继续保留，不在打开文件时重写正文。Markdown/Flow 继续采用原有空格缩进与列表规则。

用户修改选项时，按所选 Tab Size 计算当前文档行首缩进的显示列数，然后转换为目标空格或 Tab 加剩余空格，避免改变不足一个 Tab 的对齐。Tab Size 改变时已有 Tab 的显示宽度随之变化，不按旧宽度展开后再重新缩放。只转换行首缩进；行内空白和跨行字符串/注释的内容不变。依靠语法树识别跨行字面量，解析未完成时拒绝转换并提示重试。转换作为独立的编辑事务保存，可撤销；撤销正文转换不回退本机偏好设置。只读文档禁用两个转换入口。
