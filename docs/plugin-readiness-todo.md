## 1. 两条工作线与提交规则

A 线完善已有功能及文档；B 线实现插件所需核心适配，再实现宿主与贡献点。两线按依赖推进，不等待所有产品优化完成再开始插件。

每批只处理可验证的范围，完成后记录验证并提交。没有要求推送时只提交。首次插件适配代码实现提升产品版本至 0.2.0，遵循[版本计划](plugin-release-plan.md)。不把新增未接入的类型或单元测试视为整个前置条件完成。

“全部前置条件完成”的通知必须明确范围：首次内置宿主需 R1～R6 全部通过；第三方 L0 安装另外需 R7；涉及自定义属性/查询/导出档案再分别需 C1～C3。当前尚未满足，不能通知已经具备完整插件交付条件。

## 4. L0 草案需修正的字段与规则

- [ ] integer/default/enum/choices/items 的一致性；required 引用已声明参数；上下界合法；数组/字符串和总请求都有资源限制。
- [ ] 编译 args 时分离 x-nr UI 元信息，注册受控格式，不依赖关闭 Ajv 严格模式；无参数统一空对象。
- [ ] 宏首版只调用稳定原子命令；明确派生 risk/scope/views/platforms、失败步骤和部分成功，不承诺整批撤销。
- [ ] Template.target.properties 支持受限多选数组；查询数组参数与 in/hasAny/hasAll 一致；exists/between 参数行为准确。
- [ ] SemVer 使用解析器；日期与颜色加入语义解析；明确 defaults 的规范化流程与计量单位。
- [ ] readonly/editable 与 view 分离；命令平台不能扩大包平台；stable/unstable 引用策略统一。
- [ ] 命令请求成功/失败契约、目标令牌、来源可信性、取消/超时、重复 requestId、非幂等重试策略。
- [ ] 包 entry 显式拒绝于 L0 安装入口；ZIP 路径/碰撞/资源解码预算；完整性覆盖与恢复启用不能替代信任。
