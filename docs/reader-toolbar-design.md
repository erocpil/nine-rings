# PDF / EPUB 阅读工具栏分组（2026-09-07）

## 参考与取舍

- [Apple Books 阅读控制](https://support.apple.com/en-ie/guide/iphone/iphc1af7c57/ios)：通过阅读菜单进入目录、搜索、主题与设置；字号和页面外观集中设置。
- [Acrobat 界面概览](https://helpx.adobe.com/acrobat/desktop/get-started/learn-the-basics/overview.html)：导航、常用操作与专门工具分组，避免所有工具同时竞争正文空间。

本项目采用“常用导航常驻、专业工具按需展开”，不照搬产品整个侧栏布局，也不移除原有功能。手机仍直接保留目录、书签、前后页/章、专注入口；EPUB 的本章顶端/末尾按钮不藏入设置。

| 格式 | 默认显示 | 按需展开 |
|---|---|---|
| PDF | 返回、标题、目录、当前页书签、页码/翻页、搜索/设置/批注入口、全屏 | 阅读设置：缩小/放大、适宽/适高、横向/纵向；批注：五种绘制工具、批注列表、高亮显隐、导出标注 PDF |
| EPUB | 返回、标题、目录、书签、章号/前后章、本章顶端/末尾、搜索/设置入口、专注 | 阅读设置：字号、三种主题与长按自定义背景、智能断行开关、人工修复入口 |

搜索框仅在打开搜索时展示，查询和结果不会因关闭面板丢失。PDF Ctrl/Cmd+F 会先打开搜索面板，全屏时先退出全屏；Escape 优先关闭面板，下一次才交给阅读器。输入框/按钮上的方向键不再误触发翻章/翻页。

PDF 选择绘制工具后关闭面板，显示当前工具与“完成批注”；进入全屏时退出绘制状态，避免隐藏操作入口后仍在画图。文字选中后的高亮/摘录浮层沿用原实现。

## 实现边界

- `ReaderToolbar.tsx` / `ReaderToolbar.css` 统一呈现、互斥开关、关闭/焦点交还、响应式布局；CSS 不继续堆入全局大文件。
- PDF/EPUB 会话继续持有分页、字号、主题、搜索结果、标注与存储，不迁移渲染/锚点/手势引擎。
- 面板留在阅读器内部，不 Portal 到全屏根节点之外；绝对定位覆盖正文，不改变正文视口高度，不重建 canvas/iframe。设置/批注面板的透明关闭层阻断误点底层，搜索保留正文交互。
- 手机常态两行工具栏；默认字号下 320 / 390 / 768 / 1280px 均校验横向边界。正常手机高度下设置完整显示，小高度/键盘场景允许面板内部滚动，最大高度使用应用可视视口与安全区。
- PDF 操作提示在面板内或悬浮展示，不因提示出现让正文跳动。
- EPUB 背景默认值、长按色板、人工断行位置保持、章节阅读位置、全屏点按和滑动机制未改动。

## 验证入口与限制

- `editor-ui-boundaries`：菜单互斥/关闭、布局切换不重建编辑器、选区/撤销、跨文档命令边界。
- `reader-toolbar`：真实文件导入后检查四种宽度、全部可见按钮边界、面板不挤压正文、不重建内容、查询保留、人工修复、实际绘制/高亮显隐与 PDF 下载。
- `reader-toolbar-shell`：不依赖文件存储的真实工具栏组件测试，覆盖 StrictMode、触屏、焦点、Escape、小视口、专注根节点和提示不改变正文几何。它不是完整阅读器测试。
- `pdf-reader` / `epub-reader`：继续运行既有完整流程；只为新的面板入口和更准确的可访问名称调整测试步骤，不放宽缩放定位、进度、全文搜索、高亮恢复等断言。

Linux Playwright WebKit 的完整阅读用例仍在既有 PDF/EPUB IndexedDB 文件导入事务失败，未进入阅读界面；与[先前阅读备份记录](reading-data-backup.md)一致。本轮未修改资料库存储实现，不能将独立组件测试解释为 WebKit 完整阅读通过。iPhone 安装版、Windows WebView2 仍需要真机核对。
