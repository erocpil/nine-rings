# 随笔 / 文档视图按钮审查

基线：`35aac69`。范围是两种视图的入口、侧栏行内操作、菜单、共享正文工具栏及其选择状态；按入口追踪处理器，再用真实鼠标/触控事件检查结果，而不是仅检查按钮是否出现。

## 已复现并修复

| 问题 | 原因与处理 | 回归 |
| --- | --- | --- |
| 操作未选中随笔时先打开了该随笔；手机上还会收起侧栏 | 行导航在 `mousedown` 执行，子按钮仅阻止 `click`，时机太晚。行导航跳过按钮等交互元素 | `view-buttons.spec.ts`：取消置顶、只读、日期取消、删除，检查当前笔记与侧栏保持不变 |
| “全部随笔”的标签按钮变色但列表不变 | 全部列表使用独立缓存，绕过上层标签结果。对实际显示的数据源应用标签过滤 | 同上：桌面 / 手机选择、清除标签 |
| 文档树“重命名当前文档”可点却无反应 | 当前选中的是随笔，不一定存在于文档树中。仅在树中存在目标文档且有回调时启用；折叠其它目录也检查实际目标 | 同上：两端先禁用、再选择文档重命名 |
| 点禁用工具栏按钮后，下一条命令可能替换旧选区 | 按下事件设置交互标志，禁用按钮不产生 click，标志一直不清理，之后光标变化被忽略。禁用按钮不启动交互；取消事件清理标志 | 同上：选中文字 → 点禁用重做 → 移到末尾 → 块内换行，原文字必须保留 |
| 共享“搜索笔记”入口查不到随笔与待办 | 始终转发文档专用查询。无文档筛选时改走笔记、文档、待办联合查询，按 ID 去重；有筛选时保留文档查询。保持保存冲刷和请求失效机制 | 同上：随笔、文档、待办命中，目录筛选 / 取消筛选 / 清除；`search-navigation.spec.ts` 保留搜索刷新、定位回归 |

## 未覆盖与后续风险

- 原生系统剪贴板授权、系统文件选择 / 分享、真实软键盘、Windows WebView2 与 iOS 安装版仍需真机验证。桌面尺寸 + 触摸模拟不等价于真机。
- 随笔批量只读、回收站和版本恢复、文档树迟到响应已在下方“可靠性补充”处理；部分属性关联操作仍缺少完整的逐按钮 E2E。
- Linux Playwright WebKit 的 PDF 导入事务失败是此前已记录的独立问题；本次按钮测试不能证明该问题已修复。

## 验证结果

- `npm run check` 通过（包括 70 项 Vitest 用例及原有串行测试）；ESLint 维持 145 个既有警告，0 个错误。
- `npm run build` 和 `git diff --check` 通过。
- 全量 Chromium 首轮：274 通过、5 跳过、1 失败。失败是 EPUB 流程中的正文高亮未显示，侧栏已生成高亮记录；单独连续复测 3 次通过，未修改或放宽 EPUB 断言，仍保留为偶发失败记录。
- 全量运行之后补充的两项手机“更多”菜单测试单独通过，验证了随笔 / 文档的颜色、字号、链接、图片插入和 Markdown 下载。本次新增 16 个按钮场景，其余按钮复用既有回归。
- 最终 Chromium 独立重跑新增按钮文件：16 项全部通过。
- WebKit 首轮 37 通过、4 失败；检查发现 4 项均在操作按钮前未形成选区（触控 WebKit 的 Ctrl+A 行为不同）。测试改用实际选区并断言所选文字，未修改生产逻辑或放宽格式结果断言；新增 16 项重新运行全部通过，既有 25 项随笔菜单、文档树和搜索回归也通过。
- 测试夹具另补齐手机切换文档后的就绪等待，避免侧栏自动收起时还去点击隐藏按钮。浏览器套件共享开发服务器时也应避免一个套件结束后关闭服务器、使另一套件连接失败。

## 截图反馈后的补充：全部随笔菜单

先前菜单测试验证了日期面板能打开，但没有执行跨日移动；排序用例也未覆盖“全部随笔”，因此不能据此前结果认定所有菜单动作可用。

- 移除“全部随笔”手动排序禁用条件；顺序提交后统一刷新列表，不再每写入一项就重载当日、切换当前笔记。失败显示反馈，标签筛选、非手动排序、列表 / 置顶分组边界明确提示并置灰。
- 日期面板预填原日期，不再延迟调用系统 `showPicker` 或争抢焦点；增加显式“移动”、空日期校验、保存中状态和失败重试。移动前冲刷未保存编辑，不因刷新列表切换当前笔记。
- 全部列表显示所属日期，移动成功后说明记录仍保留在全部列表；空态依据实际显示列表，不再同时显示笔记与“今天还没有笔记”。
- 新增三个触控场景：跨日期上下移动及重载持久化；跨日移动确认 / 写入失败重试；边界提示 / 非手动排序 / 取消日期修改。系统日期选择器外观与真实 iOS 的表现仍需真机复验。
- 补充验证：Chromium 按钮 / 随笔菜单 25 项通过，最终三个针对性场景重新运行通过；WebKit 26 项通过；完整静态与单元检查、生产构建通过。

## 可靠性补充（基线 e8c31c9）

- 回收站永久删除与清理增加确认，操作串行执行，显示忙碌、失败和结果；加载失败不再显示“空回收站”。
- 随笔批量只读复用主工作区处理器：冲刷当前编辑、更新列表而非整页刷新；失败保留选择并允许重试。
- 文档树连续选择使用请求序号；切换目录、禁用、卸载时使旧请求失效，读取失败给出可见提示。弹出文档树补齐备份忙碌状态。
- 版本列表丢弃迟到请求；恢复需要确认，先冲刷保存，阻止并发恢复及处理中关闭。成功直接更新目标文档，不再切换当日随笔；失败保持弹窗和重试入口。
- GitHub 自动检查与手动测试共用连接状态。按钮下方统一反馈区按进行中、操作结果、连接状态显示，避免重复或冲突；配置字段校验及 Token 风险提醒保留在字段旁。新增 JSON 备份不含 PDF/EPUB 原文件及独立阅读数据的说明。
- 新增 `e2e/reliability-actions.spec.ts`：删除/清理取消、失败重试、恢复前保存失败及快照、快速选中文档、批量只读失败重试和无页面刷新。`hook-lifecycle` 补充连接提示与操作结果互斥验证。
- 本轮不实施 PDF/EPUB 阅读数据备份协议或大编辑器拆分；真实 Windows WebView2 和手机系统确认框仍需真机验证。
- 验证：`npm run check`、生产构建、差异检查通过，维持 145 个既有 lint 警告。Chromium 相关 36 项回归通过，最终可靠性文件 5 项重新通过（含后补的真实工作区恢复/重载用例）；WebKit 针对性 7 项通过。连接提示另验证 390px 截图。测试准备改为显式选择目标文档，避免将启动恢复时序混入操作测试。
