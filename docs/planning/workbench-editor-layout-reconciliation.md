# File Workbench 编辑器需求核对与布局修正

日期：2026-11-15。依据最近布局修复、浏览器回归及用户确认。

## 已确认需求

1. 内置 Markdown 编辑器支持源码和渲染切换；两种模式均可用目录、书签、只读切换和更多工具。
2. 标题操作顺序：视图切换、目录／源码符号、书签、更多工具、固定面板左右切换；其它文件操作随后排列。不显示“磁盘文本”。
3. 更多工具提示使用统一短延迟，展开状态也应可提示。
4. 标题栏全宽。固定目录、书签、源码符号、同词等固定面板统一从标题行（若有标签则从标题与标签区域）下沿开始；正文工具栏与正文列并排占据剩余区域。数据库文档、磁盘文件的源码和渲染视图共用这一锚点，展开或收起工具栏不移动固定面板。
5. 目录、书签、源码符号、同词匹配服从同一个左右设置；默认左侧，用户最新选择持久保存。
6. 长文档在正文区域滚动，原生竖直滚动条位于正文列边缘，不被固定面板遮挡；风格与源码模式一致。
7. 书签两种模式共享，重开恢复；正文修改后仍定位对应内容。需覆盖单处和多处编辑、插入与删除。
8. 保留文件保存、草稿、冲突、只读和撤销等已有约束。
9. 先前相关要求还包括代码复制和行号按钮使用统一 SVG、图标按钮尺寸统一、Command+Q 独立退出提示；与本次布局重做分开验证。

## 当前事实与未完成项

数据库文档和磁盘文件继续使用共享源码／渲染工作区及固定面板控制器。源码和渲染标题可能位于不同滚动容器；面板通过测量当前可见标题行的底边换算锚点，不依赖工具栏展开状态，也不从隐藏的保留视图读取旧标题。标签行不再推动固定面板下移，因此数据库文档与磁盘文件的面板起点一致。固定面板使用正文列自己的滚动区域，不叠加第二套同步滚动状态。

最近修复了标题候选选取错误：此前 `querySelector` 取到的第一个标题可能属于被保留但不可见的源码／渲染视图，导致数据库源码模式固定目录仍锚在旧标题位置。现在只选取有可见布局框且未隐藏的标题，并在源码／渲染往返中重新测量。

浏览器回归覆盖数据库文档源码／渲染、磁盘 Markdown 源码／渲染；固定面板左右两侧和七种非经典风格（清雅、纸页、精简、九环、物哀、幽玄、侘寂）都检查标题／工具栏边界及面板几何。书签重启恢复和复杂多处编辑后的定位仍未完成专门认证；macOS Tauri 实测由用户执行，不以浏览器测试代替。

## 实施边界

以已验证正确的源码布局为参照，复用布局职责与已有面板组件；不替换 TipTap 或 CodeMirror 编辑引擎，不为 File Workbench 复制一份渲染器。

应将标题、正文工具栏、正文滚动视图、固定面板分别放入明确的布局区域。固定面板起点由标题区域底边决定，不能由展开工具栏的底边决定。正文滚动条由正文列的真实滚动容器提供。

清理仅服务于错误层级的宽度、负边距、定位补丁；保留其它宿主默认布局。调整共享接口前核对数据库文档和本地文件两个调用方。

## 验收矩阵

- 源码／渲染、只读／可编辑、左右固定、宽／窄窗口；非经典风格为本阶段重点。
- 固定目录、书签、源码符号、同词及可共存组合。
- 展开／收起更多工具：固定面板上沿和高度不变，工具栏不侵入面板列。
- 长文档能拖动原生竖直滚动条到末尾，正文不被面板覆盖。
- 标题全宽，模式切换保留位置，分栏宽度拖动后边界正确。
- 书签创建、重命名、删除、模式切换、重开和编辑定位。
- Chromium 与 WebKit 定向验证；记录真实通过范围，不以类型检查代替交互认证。

### 2026-11-15：可见标题锚点与非经典风格验收

- 固定面板定位只选取当前可见标题，避免源码／渲染保留视图中的隐藏标题抢先成为锚点；目录、书签等共用该定位入口。
- 固定面板锚点统一为标题行底边；数据库文档的标签行不再造成它与磁盘文件布局不一致。
- 数据库文档回归覆盖源码和渲染，并加入源码→渲染→源码往返；磁盘 Markdown 覆盖源码和渲染。分别检查标题／工具栏边界与固定目录几何。
- 固定面板左右两侧及清雅、纸页、精简、九环、物哀、幽玄、侘寂七种非经典风格均纳入数据库／磁盘源码与渲染定向回归。Chromium 4/4、WebKit 4/4 通过。
- 仍待专门认证书签重启恢复、多处编辑后的定位，以及更完整的窄窗口和左右固定组合。完整产品 E2E 与 macOS Tauri GUI 尚未由本轮覆盖；后者由用户本机验证。
