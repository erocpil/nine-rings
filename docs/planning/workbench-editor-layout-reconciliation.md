# File Workbench 编辑器需求核对与布局修正

日期：2026-11-14。依据最近 12 小时提交及同一会话中的用户确认。

## 已确认需求

1. 内置 Markdown 编辑器支持源码和渲染切换；两种模式均可用目录、书签、只读切换和更多工具。
2. 标题操作顺序：视图切换、目录／源码符号、书签、更多工具、固定面板左右切换；其它文件操作随后排列。不显示“磁盘文本”。
3. 更多工具提示使用统一短延迟，展开状态也应可提示。
4. 标题栏全宽。标题栏下方分正文列与固定面板列；正文列包含工具栏、正文和状态栏。固定面板上沿对齐正文工具栏上沿。展开或收起工具栏不移动固定面板。
5. 目录、书签、源码符号、同词匹配服从同一个左右设置；默认左侧，用户最新选择持久保存。
6. 长文档在正文区域滚动，原生竖直滚动条位于正文列边缘，不被固定面板遮挡；风格与源码模式一致。
7. 书签两种模式共享，重开恢复；正文修改后仍定位对应内容。需覆盖单处和多处编辑、插入与删除。
8. 保留文件保存、草稿、冲突、只读和撤销等已有约束。
9. 先前相关要求还包括代码复制和行号按钮使用统一 SVG、图标按钮尺寸统一、Command+Q 独立退出提示；与本次布局重做分开验证。

## 当前事实与未完成项

源码模式标题在编辑面板容器外，渲染模式标题、工具栏仍在正文滚动容器内。该结构差异是最近宽度、边距和面板定位补丁反复失效的主要原因。

已提交的布局补丁和同步滚动轨道不等同于最终结构。后者应在原生正文滚动边界正确后移除，避免两套滚动状态。

源码导航已接入共享组件；渲染导航仍由共享渲染器管理。书签使用同一宿主数据，但重启和多处编辑可靠性尚未完成浏览器认证。全局左右按钮尚有未提交改动，不能视为验收通过。

## 实施边界

以已验证正确的源码布局为参照，复用布局职责与已有面板组件；不替换 TipTap 或 CodeMirror 编辑引擎，不为 File Workbench 复制一份渲染器。

应将标题、正文工具栏、正文滚动视图、固定面板分别放入明确的布局区域。固定面板起点由标题区域底边决定，不能由展开工具栏的底边决定。正文滚动条由正文列的真实滚动容器提供。

清理仅服务于错误层级的宽度、负边距、定位补丁；保留其它宿主默认布局。调整共享接口前核对数据库文档和本地文件两个调用方。

## 验收矩阵

- 源码／渲染、只读／可编辑、左右固定、宽／窄窗口。
- 固定目录、书签、源码符号、同词及可共存组合。
- 展开／收起更多工具：固定面板上沿和高度不变，工具栏不侵入面板列。
- 长文档能拖动原生竖直滚动条到末尾，正文不被面板覆盖。
- 标题全宽，模式切换保留位置，分栏宽度拖动后边界正确。
- 书签创建、重命名、删除、模式切换、重开和编辑定位。
- Chromium 与 WebKit 定向验证；记录真实通过范围，不以类型检查代替交互认证。
