# UI / UX 渐进优化（2026-09-09）

每批独立验证、提交和推送，保留验收窗口，不改动正文存储和 PDF / EPUB 渲染。

## 第一批：查找范围与控件状态

- 列表输入框持续显示「当前列表」，只筛选标题、路径、标签和概念；全局输入框持续显示「全局」，当前文档查找持续显示「当前文档」。输入关键词后范围也不会消失。
- 全局搜索筛选采用现有 SVG 图标，不再使用容易误解为第二个搜索入口的放大镜。
- 导航及查找按钮统一展开/选中、按下、键盘焦点和禁用状态，不改变工具栏高度或文字粗细。
- 清除搜索按钮提供 28 × 28 CSS px 点击区；折叠三角高度从 20 增至 24 px，保留原有横向范围，不遮挡相邻块号。窄边栏的三角仍不是完整 24 × 24 点击区，此批不宣称全面符合目标尺寸标准。
- 清空搜索后保留输入焦点，避免手机上的延迟失焦逻辑将搜索栏收起；更新输入状态后才重新聚焦，避免再次提交旧关键词。

验证覆盖：390 / 1280 px 下的范围提示、搜索焦点、清除按钮尺寸、键盘焦点和禁用状态；全局路径/类型/概念筛选；有/无块号、普通/专注模式的书签标记与折叠操作。分别使用 Chromium 与 WebKit 执行。Linux WebKit 不等同于 iOS PWA 真机验证，仍需用户在实际设备验收。

第一批后续回归：用户反馈 iOS 专注模式引用块左侧出现多余的标题三角。针对滚动中按钮的绘制风险，标题折叠按钮改用 `top = 首行中心 - 点击区域高度 / 2` 居中，取消该按钮的 CSS transform；保持 24px 点击高度、块号与书签标记位置。增加多行标题、反复章节折叠和引用块高度变化的坐标回归。截图本身不能区分错误 DOM 坐标与 WebKit 绘制残留，最终仍需 iOS 真机复核。

第二次回归修复（用户反馈首轮仍未消除）：

- 核对第一批 7 个文件：正文查找及列表查找改动不参与常态正文布局；三角直接受到高度 20→24px、统一焦点描边及不透明度变化影响。本次将三角高度和焦点样式恢复到第一批之前，保留直接坐标居中。其他工具按钮的状态样式不回退。
- 原 gutter 只通过编辑区整体 ResizeObserver、IntersectionObserver 和事务更新几何。局部块外框变化而编辑区总高度不变时，已可见标题可保留旧坐标。
- 增加当前布局窗口内各块的 border-box 尺寸观察（含未显示块号的普通段落/引用块），下一帧重测窗口内控件；窗口移出时取消观察，卸载时断开。不扫描或观察整篇文档。
- 回归用例让引用块增加 60px、末段减少 60px，保持编辑器总高度不变且标题一直可见。只观察内容尺寸时实测失败，改为完整外框后 Chromium 通过；这一用例不依赖滚动来修复坐标。iOS 截图现象仍需真机验收，不能把自动化对齐通过等同于真机完全修复。

第三次三角回归处理：前两次真机反馈仍有多余三角，因此改为由 ProseMirror widget 提供标题内部的控件宿主，React 按钮直接挂入对应宿主。标题自身相对定位、首行行高控制居中；不再从 gutter 的 `firstLineCenter` 定位三角，标题隐藏时控件随父节点隐藏。块号和书签继续使用原来的窗口测量。宿主由编辑器管理，禁止编辑并排除 PDF 导出；未修改标题节点内容或持久化结构。未变化标题的宿主按节点身份复用，避免前方插入文字使后续全部标题宿主重建。新增正文编辑、撤销、剪贴板序列化及标题改为段落后清理控件的回归；仍需用户真机验收，不能以桌面 WebKit 对齐测试替代 iOS 结果。

## 第二批：设置和视图偏好

- 设置首页加入关键词查找，仅查询静态设置名称和说明，不查询正文、用户信息或凭据。支持多关键词、英文大小写和全角归一化。
- 搜索结果进入分类或排版面板；排版面板可按标签定位「行号」「列表 缩进」等设置；检查更新结果仅定位现有按钮，不自动发起更新。
- 「密码」显示文档/路径属性页说明，不恢复全局密码入口。不可用的平台功能不出现在结果中。
- 返回分类保留本次查询，关闭重开设置清空；查询不落盘。
- 列表本机持久化最近/全部/收藏视图、排序字段/方向、显示字段。当前会话状态优先，重启后读取本机偏好。仍不保存查询词、路径、标签、类型筛选、文档元数据或滚动位置。
- 新增独立版本化 localStorage 键，使用字段白名单与值校验；损坏时回退默认值，写入失败时提示且保留本次会话操作。不修改备份格式，不承诺跨设备同步。

验证：单元测试覆盖白名单、错误类型、损坏/不可用存储与平台结果过滤；浏览器回归覆盖手机/桌面设置定位、查询清除、密码说明，以及列表重启恢复和存储失败后继续使用。

第二批已通过 4 项单元测试、Chromium / WebKit 的设置和列表回归及第一批查找范围回归。另用生产构建验证 PWA 更新入口的查找与定位；类型检查、lint、格式检查和生产构建通过。未执行 Windows WebView2 或 iOS PWA 真机测试。

## 第三批：保存、备份与更新反馈

- 正文工具栏与块工作区使用「已存本机」，说明自动保存不等于备份；未扩大工具栏高度。
- 常规 JSON 导出仅在桌面文件写入成功或浏览器下载触发后记录时间和交付方式。取消、序列化或写入失败不生成新记录；恢复快照不冒充常规备份。记录不包含路径、文件名、正文或凭据，写入记录失败不使已完成的文件导出变成失败。
- 数据导入/导出及同步页展示最近可用的本机导出记录。浏览器明确写「已发起下载，文件是否保存需自行确认」；记录不验证文件仍然存在，不宣称代表 GitHub 或全部历史备份。
- GitHub 成功提示明确为上传备份，已有版本记录改为「上次上传备份版本」「上次读取远端版本」。未新增未经远端确认的成功时间。
- 从已有检查状态和 Service Worker 生命周期推导检查、下载并安装、就绪、未发现待安装版本及失败状态。下载与安装属于同一实际 installing 阶段，不拆出无法测量的进度，不提供虚构百分比。
- 继续使用现有失败详情和复制入口。未修改 30 分钟自动检查间隔、重试、缓存、激活或保存后刷新机制。

第三批验证：18 项单元测试通过；Chromium / WebKit 的备份导出记录持久化、键盘压缩后的块工作区布局，以及各 4 项生产版 PWA 升级/失败重试/离线回归通过。页面重开时若注册尚未返回，显示检查阶段；观察到 installing 后才显示下载并安装。类型检查、lint、项目格式检查和生产构建通过，未执行 iOS PWA 或 Windows WebView2 真机测试。

## 设计约束与参考

保持紧凑标题栏、小图形、大而不重叠的点击区域；不增加大面积毛玻璃，不靠缩小正文换取空间。
参考 [Notion 视图与筛选](https://www.notion.com/help/views-filters-and-sorts)、[W3C 最小目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) 和 [Apple 按钮指南](https://developer.apple.com/design/human-interface-guidelines/buttons)。Apple 的 pt 与网页 CSS px 不混为一谈。
