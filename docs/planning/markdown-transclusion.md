# 磁盘 Markdown 跨文件内容嵌入

本文记录设计，实施暂缓。拟支持 Nine Rings 与 File Workbench 打开的授权目录内 Markdown。

Obsidian 用 `![[文件]]`、`![[文件#标题]]` 显示来源内容，并在源文件变化后更新。首批保留这一语法和更新体验，路径解析沿用两款应用已有的相对链接规则。 [Obsidian 嵌入文档](https://obsidian.md/help/embeds)

## 语法与目标

- 独占正文顶层一行的 `![[guide.md]]` 或 `![[../guide.md#目标章节]]` 表示只读嵌入。省略扩展名时补 `.md`，含保留字符的路径段沿用百分号编码。行内、转义和代码中的写法按字面保留。
- 以宿主文档的实际父目录解析，定位限制在当前授权根。目标是一个明确的 `.md` 或 `.markdown` 普通文件。同名目录项可通过显式相对路径选择。首批只支持整篇和标题节，Obsidian 的块 ID、非 Markdown 附件和别名语法留待独立评估。
- 标题片段复用现有标题锚点及重复标题编号。未命中锚点时，仅在原始标题文本唯一匹配的情况下回退。缺失或存在歧义时在嵌入处提示。章节包含选中标题及其较深层级的内容，结束于后继同级或更高一级标题。先解析完整目标再截取章节，保留有效的链接定义、脚注和结构边界。

## 运行时边界

| 环节 | 首批设计 |
| --- | --- |
| 内容权威 | 原始 Markdown 只保存嵌入标记。渲染层为该节点挂接派生的只读视图，沿用现有文档块渲染器和清洗规则。编辑、撤销、复制和保存宿主时，以嵌入标记为单个块。 |
| 授权 | 路径先用 `localMarkdownLink` 作相对路径检查，再由可信文件宿主核对调用窗口、授权根和真实文件。绝对路径、协议、越界路径和指向根外的符号链接均失败。解析、导入、同步、备份和纯源码查看可以识别或保留标记，只在可见渲染视图发起读取。数据库文档保留原标记，后续另定数据库身份和可见性边界。 |
| 资源与导航 | 目标文档内部的链接和图片以目标文件的父目录为基准，沿用同一授权根。标题和脚注锚点按嵌入实例隔离。嵌入块提供打开来源入口，通过现有标签和导航历史。宿主目录和书签仍按宿主正文生成。 |
| 刷新 | 初次可见时读取已保存的磁盘版本，避免把另一窗口尚未保存的内容当成来源。切回窗口、标签或重新展开时，合并检查该文档当前可见的依赖，按内容修订更新，同尺寸改写也要重新核验。缓存按活动宿主、授权根、规范文件身份和内容修订隔离。读取在异步完成后再次核验权限与活动请求。切换文件、撤权和卸载后丢弃迟到结果，并释放派生资源。文件删除、移走、不可读时显示相应提示。 |
| 循环与用量 | 第一阶段只展开一跳。宿主直接引用自身时以可信宿主核验的文件身份识别。平台支持时使用实际文件标识识别别名，否则使用规范路径。被嵌入文档里的嵌入标记显示为可打开的来源引用，A → B → A 在 B 停止。首批建议每个宿主每轮加载最多 16 个不同目标、每目标 256 KiB、合计 1 MiB，同时限制输出块数。读取器在实际读取时执行字节限制，并对超限或失败项显示局部状态。 |
| 导出与迁移 | Markdown 序列化保留原标记。HTML／PDF 首批输出可读的来源引用。文件改名和移动的引用预览后续把嵌入标记接入已有扫描、修订校验及逐文件写入。 |

## 实施顺序与验收

1. 先做纯语法和往返测试。识别独立块，保持原文拼写，覆盖转义、代码、未闭合、中文标题、百分号编码以及旧客户端保留。入库结构若增加新类型，先核对 React、Flutter、同步和备份契约，再启用写入。
2. 接入两个磁盘宿主共用的有界读取端口。复用 `readSnapshot` 的授权、编码和修订核验，并将上限传到底层读取，验证不同根、符号链接别名、撤权和读取中修改。先以同一路径解析规则推出整篇与标题节的只读渲染。
3. 验证快速预览、完整编辑器只读／可编辑和源码往返，覆盖重名、跨章节脚注、失效链接、保护草稿、重复依赖合并、循环及预算。以读取次数、实际字节、可见实例数量和刷新延迟记录性能。

曾考虑直接把目标正文复制进宿主，优点是离线导出容易，代价是产生第二份正文并需要额外处理编辑、撤销和刷新冲突。按文件名在整个库中查找可以简化输入，同名文件、授权范围和索引更新都需要额外规则。首批采用明确相对路径及只读投影，后续扩展基于实际样本和测试结果。
