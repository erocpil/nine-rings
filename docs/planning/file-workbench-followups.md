## 第一批交付与边界

- PDF：共享快速预览及独立工作台全视图支持分页、页码、适宽／75%～200%缩放和文本选择；逐页渲染，显示倍率与画布像素密度分离，按屏幕DPR（最高2.5倍）绘制且画布最多1200万像素。使用独立 Worker 与本地 CMap，直接传入二进制数据以兼容 tauri 自定义协议，不将文件导入 Nine Rings PDF 库。
- PDF读取：授权根内按段读取，读取前后核验大小／修改时间，取消及撤权后丢弃迟到结果；浏览器与原生端均限制32 MiB。超过预算时显示文件信息并建议系统应用；图片不受此新预算影响。
- Markdown：快速预览和独立全视图默认渲染；上方单图标按钮切换渲染／源码，图标和悬停提示表示目标模式；一次预览内按源码字符与渲染内容边界映射位置，切换时跟随同一段内容，不再只恢复两种模式各自的旧像素位置。快速预览查找切到原文；内置编辑器解除只读后可直接编辑渲染正文，并可切换源码；切换不改写原文，原保存／草稿／未保存离开保护继续生效。带搜索定位打开时仍直接进入源码。
- 独立预览禁用数据库 nr-image 图片解析；本地相对链接暂不直接跳转，以免绕过保存确认。相对图片暂保留替代文本，不擅自扩大目录授权；远程资源仍受宿主 CSP 限制。
- 密码 PDF 暂提示使用系统应用；PDF全文查找、目录、相对图片／链接的授权解析、页位置记忆属于后续可选扩展，本批未声称已支持。

## Markdown 渲染编辑实施约束

先复用 Nine Rings 已有渲染编辑器，检查并拆出必要的编辑器宿主接口，不能为复用引入独立工作台不需要的数据库、同步或应用单例。

- 源码保真：仅打开、预览或切换模式不得重排、转义或改写原始 Markdown；明确渲染编辑对复杂语法的支持范围及不支持时的源码入口。
- 单一正文权威：渲染与源码为同一编辑会话的两种视图，不建立互相覆盖的可写副本。明确切换交接与版本核验，避免晚到解析覆盖更新。
- 编辑连续性：保留位置、选区、撤销历史、脏状态及恢复草稿；不能因切换视图清空撤销或误判为已保存。
- 磁盘安全：沿用原文件修订核验、外部修改检测、保存及离开确认；只读／无写权限文件继续只读，导出副本不等于保存原文件。
- 分批实施：先基础正文与块编辑，再按实测结果扩展特殊块；回归覆盖编辑后往返切换、撤销重做、外部冲突、保存失败、取消离开及异常恢复。


## 独立编辑器窗口：同一应用、两个工作区

目标不是再发布一个编辑器 App，而是在同一 File Workbench 应用内提供可独立移动、缩放、最小化的文件浏览窗口与编辑器窗口。浏览其他文件不必关闭当前编辑器或重新加载其会话。各 WebView 的状态不天然共享，应通过受信任的宿主接口协调，不能假定两个窗口能直接访问彼此的 React 状态。

- [x] 按授权后的规范化完整路径去重，最多32份会话；重复打开只激活原会话，不移动标签顺序。搜索定位有独立打开序号，不因普通切换标签重复跳转。
- [x] 复用原SourceView、Markdown工作区及ParkedDocument，保留未保存正文、选区、位置、撤销与折叠；仅活动标签响应编辑快捷键。

## Markdown 渲染能力分批与历史缺口

历史基线（237df662，现已补齐）：WorkbenchSourceView的锁只控制源码编辑权限；渲染分支一直装配FileBrowserPreviewMarkdown／MarkdownSplitPreview只读投影，没有传入编辑回写能力。因此当时解除只读后返回渲染仍不能修改正文；本批已经补齐该能力。之前的“编辑预览”仅表示渲染当前源码的未保存修改，不表示可在渲染结果直接输入。

### 第一批：正文渲染编辑

- [x] 将文档权威／渲染编辑与文件存储宿主分开，复用现有Nine Rings渲染编辑能力；不直接把依赖数据库或应用单例的整个编辑页面装入工作台。
- [x] 源码、渲染共用一个文件编辑会话；渲染修改能产生脏状态、撤销／重做、草稿和保存结果，保存时仍执行磁盘修订核验。
- [x] 已解除只读时渲染正文可编辑；只读、无写权限或草稿保护失败时明确保持只读。快速预览继续只读，不把它升级为另一个可写会话。
- [x] 不通过浏览／切换模式改写原文。先验证支持范围与序列化差异；无法无损处理的语法明确回到源码编辑，不能静默丢失扩展内容。
- [x] 回归源码／渲染往返定位、编辑与撤销连续性、标题／列表／引用／表格／待办、未保存预览、保存失败与外部冲突，区分“只读预览”与“渲染编辑”。

### 第二批：块号、块菜单与块模式

- [x] 渲染编辑器接入块号、当前块与折叠，以及对应的显示设置；尽量复用编号展示插件和既有块级交互，不另造编号／折叠算法。
- [x] 接块菜单、复制／剪切／移动／删除、多块选择等适用操作；文件来源不适用的数据库操作不显示。只读时只开放允许的查看与复制。
- [x] 接代码／引用／Mermaid／flow等块的放大块模式及编辑回写，继续使用同一正文、撤销和保存边界；不产生独立未协调的正文副本。
- [x] 验证块号与正文定位、折叠恢复、块模式关闭／Esc优先级、源码切换与特殊块；复制粘贴继续走已有公共动作与单元测试。本批复用同一工作区交付；不需要等待独立窗口，双栏快速预览仍只读。

两个工作流可分别推进，但独立窗口与渲染编辑都必须以同一文件会话／宿主边界为基础；实施前在共享工作台决策中确认具体接口与验收范围。


本批实现边界：首次访问某模式才加载，访问后保留其编辑实例；仅活动视图可写。两个文本引擎仍有各自原生撤销栈，保留历史不等于建立单一跨模式撤销协议。源码变化在进入渲染时投影，保留原始字符串直到实际正文编辑；仅显示属性变化不改写Markdown。独立窗口、持久侧面板及相对资源授权扩展继续属于后续任务。


后续专项：超大Markdown的渲染性能和完整原生剪贴板／实机操作验收。独立工作台尚无原生PDF打印宿主，隐藏PDF导出入口，Markdown导出改走现有文件宿主，避免调用Nine Rings专用命令。

## 实测传输进度（2026-11-15）

共享原生文件服务通过可选的请求专属 Tauri 通道回传当前授权根内路径、processedBytes、processedFiles、elapsedMs、phase。沿用系统 fs::copy、临时目录、独占发布及跨磁盘移动校验；按完整文件复制、同步和来源复核后累计字节。单个大文件内部不逐块回报，同盘移动不虚构复制字节，也不额外遍历目录预估百分比。普通通知最多每100ms一次，结束补送完整计数；撤权后不再通知。

Nine Rings 和 File Workbench 共用服务、执行器与队列展示，当前路径包含子目录。平均速度是本次调用累计已处理字节除以调用耗时。它不是整批任务平均速度，不表示目标已经发布；最终成功仍以 IPC 返回及宿主协调为准。失败保留原有需核对策略。进度消费者异常不影响写入；操作结束后忽略迟到数据，各请求单独校验计数单调和路径范围。

后续仍可评估分平台单文件内部进度（须保留 Windows 数据流及复制语义）、独立校验阶段与更多统计。此项不提供主动终止当前原生复制；停止继续只阻止后续项并等待当前结果。

命令响应同时携带最终计数，处理进度通知与 invoke 完成的先后竞争；未请求进度的旧调用仍返回路径字符串。前端兼容两种返回，通道通知不会成为任务成功的依据。

## 集中快捷键（2026-11-15）

两宿主使用共享命令表与匹配器，配置通过各自 BrowserSettingsStore 保存，File Workbench 的前缀继续隔离 Nine Rings 设置。文件操作／预览只在文件列表焦点生效，路径／过滤在当前目录栏生效；编辑器、输入框不执行文件操作。保存前验证格式、重复绑定、通用编辑／窗口保留键及 Nine Rings 已配置的应用快捷键；运行时再次读取宿主保留键，应用快捷键以后改变也不会被文件浏览命令抢走。操作仍调用原有能力检查与确认框，不提升写权限。

固定导航与选择按键不开放重绑定：Tab、方向键、Home／End、Page Up／Down、Enter、Backspace、Insert、全选及菜单键。快速预览默认空格／F3；重新录制替换该命令全部绑定。保存失败保留草稿与错误，不关闭窗口。操作系统全局注册的所有第三方快捷键无法枚举，冲突检测仅覆盖已知保留键和宿主配置。

本批验证：`npm run check` 通过；新增快捷键核心8项单测通过，定向覆盖行100%、分支92.98%。Chromium 的 File Workbench 全组43项和 Nine Rings 双栏操作13项通过；两个宿主的新增快捷键用例在 WebKit 通过，覆盖取消录制、冲突、恢复、重新加载、路径／过滤焦点和文件操作确认。两个前端生产构建通过。本批没有执行本机 Tauri GUI 或全仓库完整 E2E，不将浏览器结果等同于原生系统快捷键验收。

影响分析结论：SAFE（本批已验证范围）。入口为 `FileBrowserWorkspace`、`FileBrowserLocations`，通过 `browserShortcutAction` 处理当前列表／目录栏按键；重绑定后的文件命令仍进入 `startOperation` 与原有能力检查。可选 `BrowserWorkspaceHost.shortcutReservations` 仅 Nine Rings 宿主提供，独立宿主不依赖应用状态；读写配置异常有默认回退／保留错误，输入区不执行文件写操作。未改动原生命令、文件身份或复制发布协议。

## 手动目录大小（2026-11-15）

共享工具栏“统计当前目录大小”打开统计窗口，首次点击“开始统计”才递归调用已有授权分页服务。结果为按路径累加的逻辑文件字节及文件／子目录数量，不是磁盘实际分配，不去重硬链接，也不计入服务略过的符号链接、特殊项或无法枚举项。动态文件系统不是原子快照；结果带统计时间，可主动重新统计。

取消、窗口关闭及插件停用会废弃迟到分页，不缓存部分结果。最多100000项／128层／10000页，触限、异常、未知大小或非法分页均明确为未完成；浏览器快照遍历定期让出事件循环。会话内最多缓存64个结果，有效一分钟；文件变更通知、目录刷新、授权移除会清缓存，跨根移动同时使来源与目标根失效。不新增IPC或放宽授权。

验证：完整 `npm run check`、两个生产构建通过。核心12项单测，行覆盖100%、分支92.68%；Chromium／WebKit 验证手动扫描、缓存、刷新失效、取消和迟到结果，另验证 Nine Rings 插件入口。WebKit 的目录上传会省略点文件，统计只能包含其实际提供的快照。影响结论 SAFE（上述范围）：仅新增只读分页消费者；原文件操作、保存、权限和IPC契约不变；取消和失效关闭统计窗口并清理请求。原生大目录实机验收仍由用户执行。

## 独立编辑器窗口验收步骤（2026-11-16）

先退出旧的File Workbench进程，再运行新构建，避免单实例机制把启动请求交给旧程序。

1. 授权一个测试目录，用“打开方式 → 内置编辑器”打开.c，再打开.md：浏览列表继续可见，编辑器只有一个窗口、两个标签；重复打开同一文件只激活其标签。
2. 解锁编辑并输入，切到另一标签再返回，检查正文、选区、滚动、折叠和撤销。保存当前文件，核对磁盘仅此文件改变。
3. 编辑器打开时，浏览窗口仍可切目录、查找、预览和统计；目录写操作禁用。点击“在文件浏览中显示”应在新目录标签中定位文件；“显示编辑器窗口”可召回编辑器。
4. 修改后关闭单标签或编辑器窗口：取消保留全部内容；保存或保留草稿后继续才关闭。关闭浏览窗口应只收到托盘，不关闭编辑器；最后编辑标签关闭后可继续使用浏览窗口。
5. 在任一窗口连续Cmd+Q：先提示，再依次询问未保存文件；取消应停止退出。另用外部编辑器修改磁盘文件后保存，确认仍拒绝覆盖并可比较。最后检查恢复草稿入口能看到另一窗口生成的草稿。

剩余扩展仍包括多编辑器窗口、Finder／启动参数入口、按相关路径缩小目录写保护，以及平台实机的焦点和全屏行为。32份会话、单文本4MiB及最多5份恢复草稿沿用既有预算，不宣称可无限保留。目录、书签、源码符号等直接由现有工作区组件提供，并非另写一套解析器。


### 独立编辑器单标题栏（2026-11-16）

移除独立窗口顶部重复的文件标签行；多文件会话继续保留，以文档标题栏“打开的编辑文件”菜单切换，当前文件关闭仍走原有保存／草稿门禁。右侧依次为配色、在文件浏览中显示、关闭当前文件；关闭按钮距窗口右侧8px，标题横线继续保留正文滚动条留白。SourceView通过可选beforeCloseActions插槽同时供源码和渲染使用，旧网页内置编辑器调用不受新插槽影响。
