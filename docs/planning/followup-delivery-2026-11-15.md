# 四组后续工作的交付顺序

用户确认按以下顺序推进。优先非经典风格；原生 Tauri GUI 由用户验证。各组按可独立验证的增量提交，不将旧文档的未勾选项直接视为缺失实现。

## 1. 编辑器可靠性与验证收尾（进行中）

- [x] File Workbench 多处源码修改的书签映射，复用共享按行差异实现。
- [x] 页面重载后重新打开、书签名称恢复与跳转（Chromium / WebKit）。原生进程重启不在此认证范围。
- [x] 标签行留在正文列，避免遮挡固定目录；示例、导入实际点击回归。
- [x] 更新标题全宽、固定字号、默认左侧和触控拖动方向的过期测试契约。
- [ ] 完整 E2E 失败逐项分类、修复和最终复验；不得用定向重跑替代首次全套结果。
- [ ] 远端 CI 按提交核验（本轮尚未推送）。
- [ ] 补足窄窗口多面板组合和跨模式书签修改认证。

## 2. File Workbench 产品优化（首个增量已实现）

先文件操作进度，再快捷键设置、手动目录大小、列表展示、冲突界面、相关路径草稿保护。独立编辑器窗口和 Windows/Linux 交付各自需要接口审查及平台验证，不能与 UI 修改合并提交。

进度实现前须检查共享 runner、两宿主与 Rust 文件服务：当前 IPC 只在单项结束时返回，不能据此伪造实时字节速度。字节进度需要可信传输事件与请求身份、节流及撤权处理；取消仍须等待当前不可中断动作结果确认，不把未知写入结果标为失败可重试。

## 3. 预览扩展（待）

按 PDF 位置记忆、目录、全文查找的依赖逐步实施；本地相对资源先明确授权及修订生命周期，再接图片/链接；超大 Markdown 先测量与记录再优化。

## 4. Nine Rings 长期优化（待）

先核对现有导航历史与类型/快捷键作用域，再按实证推进编辑模型保真、增量转换和模块拆分。插件贡献点按实际产品需求开放，不因草案列出即批量放开。数据模型及跨窗口写入契约的变更单独记录决策并检查所有写入口。

第二组已加入实时耗时、停止等待状态及按完整文件统计的实测字节、当前路径和平均处理速度；集中快捷键和手动目录大小已实现；独立编辑器窗口第一阶段已接通，原生多窗口验收仍待用户执行。第一组本机默认全套首次失败、修复后原32项全部通过及独立42项全部通过分别记录，远端CI和原生GUI仍待对应环境验收。
