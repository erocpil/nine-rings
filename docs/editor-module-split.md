# 编辑器按职责拆分

## 第一批：工具栏与操作浮层（2026-09-07）

基线 `fd51696`；本批只调整模块边界，不设计新交互、不更改存储格式，也不虚拟化可编辑正文。

`NoteEditor.tsx` 从 4,800 行降至 4,013 行。减少的是主体文件承担的展示职责，而不是宣称总代码量、加载体积或渲染耗时下降。

| 模块 | 职责 | 状态与事件归属 |
|---|---|---|
| `NoteEditor.tsx` | 编辑器实例、文档会话、选区、命令实现、浮层协调、布局测量 | 保持原有 state/ref/effect 及事件处理顺序 |
| `EditorToolbarContents.tsx` | 桌面/紧凑/手机工具栏、表格菜单、更多弹层、保存状态展示 | 接收受控菜单状态和命令；不新建编辑器、不订阅另一套事务事件 |
| `EditorContextMenu.tsx` | 正文右键菜单及格式/段落/插入子菜单 | 定位、外部关闭、当前选区与命令仍由会话提供 |
| `EditorInsertDialogs.tsx` | 链接、图片 URL 对话框 | 开关、输入值和提交回调由会话控制 |

### 不变量

- `.editor-menu` 容器仍在原处，保留原 ref、指针/触摸/点击捕获处理和移动端选区恢复；新工具栏内容只返回 Fragment，不增加 DOM 包装。
- 更多弹层仍使用 `MobileActionSheet`，原锚点、间距、Portal 与事件冒泡边界不变。
- 右键菜单和链接/图片对话框的 DOM 位置、class、自动聚焦、取消和插入行为不变。
- 菜单状态仍归编辑器会话所有，不因菜单组件挂载/卸载或工具栏切换布局而重新初始化。
- 不给展示组件加 `React.memo`：TipTap `Editor` 引用不变不代表选区、活动样式或撤销栈不变。沿用父组件现有 UI 刷新信号，避免把按钮状态缓存住。
- 本轮没有移动正文折叠、视口锚点、块号测量、自动保存或只读局部渲染逻辑，没有修改 CSS。

### 验证入口

- 新增 `e2e/editor-ui-boundaries.spec.ts`：改变工具栏布局、打开/取消插入对话框后正文 DOM 不重建且撤销历史保留；切换文档后菜单/对话框的回调只修改当前文档，并验证落盘内容。
- `toolbar-responsive`、`context-menu`、`view-buttons`：全部按钮矩阵、表格选区、正文格式、链接/图片与导出。
- `pwa-layout`：触屏选区、更多面板、键盘视口、Portal 触摸与手势边界。
- `heading-fold`、`folded-tail-gutter`、`readonly-heading-fold`、`mobile-fold`：标题与文档尾部折叠安全网。

本轮也校正了回归脚本的跨浏览器前置条件：新建后等待目标空白会话就绪，再测量工具栏或派发粘贴；布局仍断言原有精确间距。右键“全选”改为检查编辑器内的 DOM Range 内容，不依赖 WebKit 会附加段落换行的 `Selection.toString()`；该旧断言在拆分前的 `fd51696` 基线上同样失败。未通过修改业务代码或放宽选中文本来掩盖差异。

最终验证：

- `npm run check`、生产构建、bundle-size 通过；Vitest 94 项通过，lint 保持 145 个既有警告、0 错误。
- Chromium 分组回归共 119 项通过：工具栏/右键菜单/按钮矩阵/新增边界 40 项，PWA 布局与完整折叠 79 项。
- WebKit 分组回归共 69 项通过：工具栏/右键菜单/按钮矩阵/新增边界 39 项、完整折叠 22 项、触屏更多弹层与选区 8 项。剪贴板授权专用的“剪切”用例只在 Chromium 验证，未计入 WebKit。
- 浏览器模拟不替代真实 iPhone 安装版和 Windows WebView2；本轮未执行真机测试，也未宣称全项目 E2E 全量通过。

## 第三批：高亮状态、应用预加载、设置组件与样式入口（2026-09-16）

基线 `04c0b04`。本轮保持功能、数据格式、编辑器生命周期与 CSS 层叠关系不变，不调整自动保存或正文虚拟化策略。

| 边界 | 本轮变化 |
| --- | --- |
| `extensions/EditorHighlights.ts` | 从编辑器提取当前行/书签跳转高亮和工具栏选区反馈；明确 `Plugin<State>`，使用 ProseMirror `Selection`，保留原插件 key、事务映射及清除规则 |
| `hooks/useEditorStartup.ts` | 从 App 提取首屏文档准备、次级界面延迟加载、最近文档空闲预热；保留取消检查、定时参数、Worker 回退与缓存策略 |
| `SettingsHotkeys.tsx` / `SettingsFields.tsx` | 提取快捷键录制和设置字段/分区展示；挂载位置与 DOM 不变；录制 ID 改为显式空值检查，移除非空断言 |
| `styles.css` / `styles/` | 全局入口改为 9 个有序 CSS 导入；只沿原连续区段切分，不重排/合并规则；职责与维护约束见 `src/styles/README.md` |

主体行数：编辑器 4,382 → 4,236；App 2,380 → 2,303；设置页 1,619 → 1,486。全局 CSS 从 13,639 行入口改为 10 行导入清单，原规则仍然存在于子文件中，并非删除或缩小样式体积。编辑器会话、导航协调和设置数据导入仍待后续拆分。

验证与基线说明：

- 拆分前先修正 `editor-ui-boundaries` 的过期随笔入口：使用有 `storagePath` 的文档及文档树导航，保留原选区、撤销、DOM 身份和写入目标断言。3 项在拆分前后均通过。
- 新增快捷键录制、Escape 关闭后取消、跨设置页保留及恢复默认持久化回归；刷新前等待实际配置落盘，不用固定延时。
- 新增 4 项插件状态单测：当前行切换、书签随事务映射/删除、工具栏选区映射/清除、不同文档状态隔离。
- PostCSS 对比原文件与递归导入后的规则树，忽略注释和空白后完全一致。主题和平台测试改为递归读取 CSS，避免拆分后测试空入口而漏检。
- 类型检查、零警告 lint、`npm test`、生产构建及 bundle-size 门禁通过；Vitest 184 项通过。
- Chromium 针对性回归 14 项通过（编辑器边界、快捷键、字号以及下面 4 项以外的设置页用例）；WebKit 同一集合加手机块选择、大文档引用编辑与字体阅读位置回归，共 21 项通过。
- 本轮新增模块及测试的 Prettier 检查通过。全局 `format:check` 仍被未改动的 `tests/unit/folder-rename.test.ts` 既有格式问题阻断，未借本轮重排该无关文件。

拆分前已存在、没有混入本轮业务修复的问题：

1. `settings-navigation` 首页用例仍预期 8 个编辑器字段，实际为 6 个。
2. 触屏设置导航及移动 Owner/Repo 用例仍从旧的“设置”入口操作，两项超时。
3. 新代码块软换行用例仍查找已迁移的旧设置字段。
4. 新增快捷键测试探索时发现 Alt+G 会被正文跳转行号捕获，未到达快捷键录制的保留键提示；本轮测试仅覆盖可正常工作的录制、取消和重置，不宣称已修复此冲突。

上述前 3 条对应 4 个既有 E2E 失败，针对性复跑明确排除它们，不将结果表述为全量 E2E 通过。未执行 iPhone PWA、macOS 或 Windows Tauri 真机验收。
