# 编辑可靠性：导航、锚点、剪贴板与保存

## 2026-09-25 本轮实现

- 导航：同一文本块内相距不超过 80 个文档位置的普通点按合并到当前历史项；跨块/远距离点按仍记录。搜索、目录等显式跳转不受这个阈值影响，继续记录，即使只移动一个字符。拖选、方向键、输入沿用已有合并规则。
- 阅读锚点：完整正文渲染器在桌面上同时观察正文尺寸。上方图片或图表加载导致高度变化时，沿用已有块/光标锚点补偿；主动滚动和 IME 组合期间不补偿，字号设置已有恢复任务优先，避免两个恢复流程竞争。手机保持现有视觉视口/原生选择策略，局部只读渲染器没有新增第二套滚动恢复。
- 剪贴板：完整列表复制严格保留子块顺序，嵌套列表后的段落/代码不再被移到嵌套列表前；多行首段、代码空行按续行缩进输出。部分代码/引用选择仍按纯文本复制，完整块保留既有结构策略。
- 富文本段落中的字面 `# ` 不再被延迟标题输入规则改写；普通输入和中文组合输入仍按原规则生成标题。
- 工具栏粘贴：富文本读取接口存在但调用失败时尝试 readText；纯文本也被拒绝则继续上报错误，不伪装为空粘贴。正常富文本读取保持 HTML 与文本双表示。

| 键盘收起再点按、原生选区、IME、视口变化 | mobile-caret-scroll.spec.ts | Chromium / WebKit |

此入口聚焦编辑核心场景，结构块选择退出/撤销用例，剪贴板选择富文本、异步读取保护、代码纯文本、列表复制和引用边界用例；不等于运行这些文件的全部功能测试。另含 deferred-heading-input.spec.ts，覆盖普通输入与中文组合输入。

纯模型测试：`npx tsx tests/clipboard-paste.test.ts` 与 `npx vitest run tests/unit/document-navigation.test.ts tests/unit/clipboard-content.test.ts`。真实 iOS/Android 输入法、Tauri 原生剪贴板及鼠标驱动仍需对应设备验收。

## 保存和多窗口审计

已存在的保护：useAutoSave 按字段维护会话内修订，串行保存；失败时恢复脏字段，新输入优先；导航 flush 失败不会离开；App 提供含当前待保存内容的紧急备份导出，加密文档需使用当前会话密钥。不能把这些会话内修订误认为跨窗口版本控制。

缺口：普通更新契约没有 expectedRevision；存储更新主要按 id/未删除条件写入，因此两个窗口之间没有原子性的旧版本拒绝。仅广播更新、保存前再次读取或比较时间戳，都不能消除“检查后写入”的竞争。

下一批应单独实施：

1. 两个存储后端统一单调 revision 与原子 compare-and-swap 更新；迁移旧数据并审计所有写入口（编辑、恢复、导入、同步）。
2. 编辑会话提交基线版本，冲突时保留本地草稿，提供比较/复制/明确重载，不能自动覆盖或自动合并富文本。
3. 广播仅用于及时发现变化；有本地脏数据时禁止自动刷新。关闭/崩溃草稿恢复要单独设计加密和清理策略。
4. 测试两个窗口同时编辑、延迟写入、删除后写入、恢复版本、加密文档与保存失败重试。

本轮仅完成该审计，不声称已解决多窗口覆盖、崩溃后的草稿持久化或跨设备增量同步。

## 本轮验证

- 剪贴板模型 30 项断言、导航/读取回退 10 项单测、延迟自动保存回归通过。
- Chromium / WebKit 验证附近点击与显式跳转、字体重排和异步高度锚点、代码/引用退出撤销、普通和中文组合标题输入；WebKit 原有导航与手机滚动回归通过，Chromium 专用侧键注入用例按平台跳过。
- Chromium 验证原生/工具栏富文本粘贴、代码纯文本、列表复制与引用边界，以及异步读取期间继续输入/切换只读/切换文档不会粘入过期内容。
- 测试夹具改用现有“新建文档”流程，不再依赖已移除的“随笔”入口。固定入口为精选核心回归集，不代表全仓库端到端测试已运行。
