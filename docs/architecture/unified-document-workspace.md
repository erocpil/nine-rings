# 统一文档工作区

更新：2026-11-20。

## 目标与当前结构

数据库文档和磁盘文件在相同格式、权限、布局及配置下，使用同一套编辑／阅读工作区。以原数据库实现为基线，磁盘适配器直接接入；不通过逐项补齐另一套渲染器维持表面一致。

- `RenderedDocumentWorkspace`（位于 `RenderedDocumentWorkspace.tsx`）是两类普通 Markdown 的公共渲染入口。它统一编号展示、schema、TipTap 会话、批量折叠、手势、目录／书签、块菜单、工具栏、选区弹层、右键菜单、状态栏及标题。
- `NoteEditor.tsx` 保留数据库专属组合层；`LocalMarkdownWorkspace` 直接导入通用渲染器，数据库引用搜索通过 `DocumentReferenceSearchContext` 注入。独立 File Workbench 不装配数据库 API／存储适配器入口。
- `DocumentSourceSurface` 是共同源码壳。两类来源注入原始文本、CodeMirror 会话及编辑回调，使用同一工具栏／状态栏和 `MarkdownSourceEditor`。
- `DocumentNavigationWorkspace` 统一源码目录、符号、书签及同词导航；渲染目录使用同一个 `DocumentOutlineList`、导航标题工具、展示插件与布局控制器。两种文本模型分别投影位置，不要求原始行号等于渲染块号。
- `useDocumentPreview`、`DocumentPreviewControls` 和 `MarkdownSplitPreview` 统一源码并排预览、同步滚动及设备偏好。磁盘 Markdown、Mermaid、Flow 不再另写预览逻辑。
- `useMarkdownViewPosition` 统一源码／渲染位置与选区交接；磁盘初次打开与跨文件切换仍使用文件会话的行锚点、滚动快照和恢复门禁。
- `DocumentTitleField` 统一标题命中、信息卡、输入框／完整标题预览及重命名反馈。数据库可即时保存标题草稿；磁盘在 Enter／失焦时执行受保护的重命名。

原本地独立的 `DocumentReadingView` 和 `MarkdownReadingView` 已删除，不再保留第二套只读会话、批量折叠、菜单动作组装和阅读恢复控制器。实验性局部只读渲染默认关闭；它仍只对具备相应能力的数据库宿主开放，不能绕过磁盘适配器。

## 分层与能力

| 层次 | 职责 | 边界 |
| --- | --- | --- |
| 来源适配 | 身份、版本、权限、读写、草稿、书签投影、资源授权、重命名 | 不实现另一套编辑器、菜单或排版规则 |
| 公共工作区 | 标题、编辑／阅读工具、折叠、选择、查找、目录、书签、块操作、状态栏 | 不自行调用文件服务，不猜测数据库身份 |
| 布局策略 | 文档／紧凑、浮层／固定、左右侧、宽度与面板比例 | 不修改正文、选区或撤销历史 |

`RenderedWorkspaceHost` 注入能力：块引用、文档导航历史、标注、标题编辑／提交、原文复制、资源处理、来源状态说明及附加文件命令。`origin` 仅用于选择各来源自己的布局偏好；不能用它决定另一套渲染或菜单实现。

磁盘不进入 `ProtectedNoteEditor`、数据库同步或全局文档位置历史。其设备会话使用 `local-file:` 命名空间，不伪造 `nr-note:` 目标。数据库专属引用／维基候选、标注存储和导航入口按能力关闭；复制、删除、缩进、样式、多块选择等通用操作直接使用公共工作区的动作集合。

## 两类源码入口的核对

源码内核本来就是共同的 `MarkdownSourceEditor`。选择数据库组合为基线不能删除磁盘入口原有的能力：

| 契约 | 数据库适配器 | 磁盘适配器 |
| --- | --- | --- |
| 文本权威 | 源码时为 CodeMirror／`SourceNavigationSession`；保存投影成 Delta | 源码时为 CodeMirror；磁盘快照为写入基线，原始字符串保留 |
| 渲染权威 | 当前 ProseMirror 文档，延迟生成不可变保存投影 | 同一 ProseMirror 文档，由文件适配器延迟生成 Markdown |
| 撤销 | 各视图自己的 ProseMirror／CodeMirror 历史 | 同样使用各自历史，源码会话继续由 `localFileSessions` 保留 |
| 首次位置恢复 | 文档阅读状态与阅读锚点 | 文件身份、行锚点、滚动快照；恢复期间不保存临时位置 |
| 保存 | 自动保存、批次确认、失败保护 | 手动保存、草稿检查点、外部修订检测及原子写入 |
| 格式与权限 | 元数据中的语言及只读查看覆盖 | 文件名检测／查看覆盖，保留 BOM 与换行约定 |
| 书签 | 文档元数据中的模型位置 | 文件行偏移投影，设备状态单独持久化 |

不合并两种文本内核的撤销栈，不承诺跨源码／渲染共享撤销；这与既有数据库行为一致。不能把磁盘恢复替换成数据库导航，也不能因为仅打开文件、切换模式、选区、布局或阅读折叠就重新序列化原文。

## 磁盘 Markdown 渲染编辑

`LocalMarkdownWorkspace` 是公共工作区的文件适配器：

1. 首次解析原文生成编辑投影，保留原始字符串和初始 ProseMirror 快照；打开、关闭、只读阅读及纯元数据更新不生成新 Markdown。
2. 实际正文编辑只登记不可变读取函数，合并 200ms 内的转换；不是每次按键都立即序列化全文。未处理读取函数仍计入未保存状态。
3. 保存、关闭检查点及切换视图先同步冲刷读取函数。转换失败时保留待处理快照，阻止依赖完整源码的操作并显示原因，不以旧字符串覆盖编辑。
4. 撤销到初始模型时恢复逐字相同的初始原文，包括原有空白和 Markdown 写法。已实际修改的正文使用既有 Markdown 序列化器，因此可能规范化列表符号、转义、脚注定义位置等；需要保留所有原始写法时使用源码模式。
5. 只读门禁仍拒绝程序化改文及原生粘贴。只读引用／代码折叠等显示事务只更新阅读状态，不回写文件；书签单独映射至设备存储。
6. 磁盘保存始终经原 `localFileService.write`，保留 UTF-8/BOM、换行、修订校验、外部修改冲突和草稿恢复。保存过程中继续输入不能把新编辑标成已保存。

### 两种磁盘编辑入口的会话规则

- `LocalFileView` 和 `WorkbenchSourceView` 使用 `remapLocalFileBookmarks` 更新源码及渲染修改后的书签。单处源码修改使用编辑范围，整篇替换和渲染回写按未修改的文本映射。删除目标时沿用偏移映射的回退位置；多个书签落在同一位置时分别保留身份。Nine Rings 可读取没有 ID 的旧记录。保留的 Workbench 渲染实例重新激活时采用源码会话最新的书签投影。
- `checkpointLocalSource` 写入或清理恢复草稿后重新读取正文与基线，包括原本干净时异步清理草稿期间发生的新编辑；保存正在进行或草稿操作失败时，检查点拒绝通过。宿主仍决定何时触发检查点、何时恢复草稿、是否保留未命名内容及如何处理磁盘冲突。原文件写入已确认后，后续编辑读取失败仍返回已确认的磁盘回执，并提示未能核验后续内容。
- `prepareLocalMarkdownView` 读取冲刷后的原文并构建目标模型，再交接选区与视口。宿主负责按需挂载、偏好存储、搜索定位和焦点；正文转换失败时当前模式保留。只切换视图不写磁盘文件。

文件是否实际允许覆盖／重命名仍由授权和服务决定。浏览器目录快照可以编辑为本机草稿并另存为，不能冒充已取得原目录写权限。

## 图片与原文保真

`DocumentResourceContext` 注入资源解析，不替换文档中存储的地址。`ResizableImage`、行内图片和只读并排预览均通过它解析授权目录内的相对图片。复制原文或保存仍包含原相对路径；进入图片查看器时才为本次查看解析图片列表。

磁盘粘贴／拖入的图片使用可随 Markdown 保存的 data URL，不生成只能在数据库中解析的 `nr-image:` 引用。数据库原有图片存储与 URL 生命周期保持不变。地址解析失败保留原地址和文本，不越过授权目录读取资源。

## 导航悬停与固定

目录、源码符号和书签复用公共悬停控制器。桌面鼠标悬停按钮 140ms 后显示预览，移入面板取消收回计时，移出 220ms 后收回；预览不改变正文宽度和固定偏好。点击按钮仍切换固定状态，固定后移出不收回；从浮层条目跳转仅关闭预览。文档与紧凑布局都提供此能力，不能因磁盘默认采用紧凑布局而禁用悬停。已固定的同类面板不重复生成浮层，手机和触摸保持点击操作。

桌面悬停宽度与固定宽度分别计算。浮层用列表实际显示的标题估算整组宽度，并以当前主题／展示插件字体补充可见项测量；源码符号浮层不再受固定面板的 35 字符测量限制。上限为 760px 与窗口可视宽度 80% 的较小值，位置仍裁切到窗口两侧 8px 留白。长标题超过上限继续沿用列表的换行／省略规则；不会把新浮层宽度保存为固定宽度。手机继续使用原尺寸规则。内部列表滚动不触发逐帧重新测量。

## 位置、折叠与标题

- 视图切换按钮保留正文焦点，防止浏览器先将只读选区滚回旧位置，再记录错误锚点。
- 源码未被操作且正文、宽高与字体未变时，往返恢复原阅读像素位置及引用／代码／表格等内部滚动；否则按文本位置映射。用户真实导航优先，程序恢复不能冒充新导航。
- 启动时恢复持久化源码视口不属于渲染往返，不能复用启动时的顶部像素快照。
- 源码卸载只冲刷源码位置，当前视图偏好由独立提交更新，避免清理函数把已进入渲染模式的偏好改回源码。
- 目录跳转仅展开遮住目标标题的祖先章节，保留目标本身的折叠状态。普通只读章节命中与同步标题锚定使用 `reading-heading-navigation`，不依赖文件路径。
- `DocumentTitleField` 只在实际标题文本范围内显示信息卡，允许移入卡片选取和复制；锁及标题右侧空白不触发卡片。
- 磁盘标题按 Esc 取消时跳过随后的失焦提交，避免正文同步聚焦早于 React 草稿复原而错误改名；源码与渲染遵守相同规则。
- 磁盘重命名先检查未保存编辑／恢复草稿，失败保留文件及输入草稿；成功迁移书签、读写规则、阅读状态、源码选区、tab 和最近打开记录，再打开新身份。不能虚构文件系统未提供的创建／访问时间。

## 验证与保留边界

- 同内容对照：相同格式、权限和配置下比较全部风格的块间距、字体与行高；菜单从同一工作区读取可用命令。
- 内容保护：原文往返无写入、完整撤销恢复原写法、待处理编辑立即保存、相对资源不进入保存内容、只读拒绝改文、外部冲突不覆盖。
- 连续性：布局切换不重建源码视图；手机与桌面模式交接保留视口、当前行／块、折叠及嵌套滚动。重命名后文件树、tab 和视图状态同步。
- 真实文件选择／续期、原生 IME、系统剪贴板授权不能只凭浏览器夹具宣称验收。每批具体测试与未执行项记录在 [E2E 清理进度](../validation/e2e-repair-progress.md)。

数据库的同步、版本历史、加密、关系元信息，以及文件系统授权、磁盘冲突与原始字节写入仍属于不同来源能力。这些差异不能通过伪造身份或将磁盘文件隐式导入数据库消除。


## 编辑器设置

Nine Rings 设置页和 File Workbench 的编辑器弹层使用 `EditorSettingsContent`，排版都由 `EditorAppearancePanel` 提供。共享内容包括当前行高亮、编号、折叠、状态栏、右键菜单和排版。Workbench 在弹层提供源码字体和四种配色，编辑器标题栏只保留设置入口，文件浏览窗口保留配色入口。

Nine Rings 的专注模式与代码块 Vim 继续由其宿主配置。Workbench 的排版与编辑选项保存在应用自己的设置存储，支持读取原有字号、字体、间距及折叠偏好。共享块显示读写使用各应用的独立存储环境。排版更改先在预览中显示，应用时保存，取消保留上一次配置。

## File Workbench 的 Markdown 编辑

WorkbenchSourceView通过LocalMarkdownWorkspace接入同一渲染工作区，包含块号、菜单、代码／引用／Flow／Mermaid块模式；快速预览仍只读。文件的raw source、磁盘基线、保存、恢复草稿和冲突确认属于宿主，保存／导出／模式切换／离开前先flush渲染序列化；待处理读者失败时不允许离开。未保存退出提示和外部修订拒绝覆盖与源码入口一致。

两个视图按需首次装配，再保留实例和各自历史；非活动投影只读且不接收命令。隐藏渲染视图在进入时按最新源码投影；隐藏源码视图不随每次渲染序列化重建文档。本文仍不承诺单一的跨模式撤销栈。位置交接使用共享useMarkdownViewPosition；测试按真正的工具栏下方可见正文边界定位，并用用户滚动事件中止启动恢复。

原始Markdown仅因实际正文编辑才规范化；折叠等仅表现属性变化通过规范化语义对照保留原始换行、列表标记及空白。文件块模式显示“未保存”而不冒充自动磁盘保存；图片嵌入能力与敏感文档标志分开，文件插图不调用数据库图片库，也不因此禁用块内查找。相对图片／本地链接授权仍沿用现有工作台限制，独立窗口不在本批范围。


文件适配器禁止从跨实例的编辑器辅助缓存恢复正文，以免覆盖明确的磁盘基线／草稿选择；重新打开后先显示磁盘版本，只有确认恢复才采用草稿。恢复到源码必须同时开启其按需挂载状态。数据库文档保持原有缓存行为。独立工作台不具备原生PDF打印宿主，按能力隐藏相关入口，Markdown导出委托文件端口；相对链接不得绕过离开保护。

## 显示偏好与宿主恢复边界

正文、显示偏好和打开清单由不同边界维护，修改一项不能顺带重置另外两项。

| 状态 | 实现入口 | 约束 |
| --- | --- | --- |
| 更多工具展开状态 | `useFocusEditorTools`、Workbench `toolbar-preferences.ts` | 源码与渲染共用 store；Workbench 启动时装配持久化适配器、跨窗口监听和卸载清理，不改变 Nine Rings 原有生命周期策略。写入失败不先改变界面。 |
| 行号、块号及折叠图标可见性 | `block-display-settings.ts`、`useRelativeNumbering`、`RenderedGutterSettings` | `nr:blockWorkspaceDisplay` 分别保存源码和渲染的折叠图标可见性，缺省均显示。渲染隐藏折叠图标时一并回收块间加号所用的控制列；插入段落走块号菜单，块号也隐藏时从标题栏打开当前块菜单。折叠状态、目录三角和块内工具继续保留。 |
| 表格插入行列 | `table-insertion.ts`、正文右键投影的表格工具栏、块级菜单 | 表格结构和光标在同一事务内更新。新行优先同列，新列优先同行，合并单元格占据该位置时选择新行列中最近的新单元格。从表格外打开块菜单时从第一列或第一行开始。 |
| 折叠图标样式与编号展示 | AppConfig、`EditorFoldIconContext`、编号插件 | 与可见性分开；沿用既有插件接管及禁用规则，不由菜单另建样式权威。 |
| Workbench 打开文件清单 | `editor_session.rs`、`editor_window.rs` | 原生修订快照拥有打开顺序、活动文件与退出确认；退出保留清单，主动关闭才移除。未命名正文由 `buffers.rs` 持久化，显示偏好不能替代草稿保存。 |

源码状态菜单和渲染状态菜单复用 `foldGutterVisibilityAction`。完整渲染通过 `EditorBlockGutter`，局部只读通过 `ReadingBlockGutter` 应用同一可见性；磁盘渲染由 `LocalMarkdownWorkspace` 接入公共渲染器，不另写菜单及图标规则。

Markdown 渲染与源码编辑工具都将行内样式放在块格式前，代码块、引用、列表连续排列。表格工具跟随表格插入入口，代码阅读显示工具相邻。只读工具优先排列查找、跳转和折叠，源码视图的软换行、高亮、微渲染随后排列。

选区工具由宿主挂载共享 `SelectionHoverToolbar`，命令回到活动编辑器。只读允许选择／复制／导航，不写正文。右键菜单保留原选区；已有下级菜单打开时父工具集保持可见且不透明。菜单链的归属与完成通知由 `editor-context-chain.ts` 协调，不能只关闭叶子弹层而遗留父级状态。

链接右键项以指针命中的链接为准。渲染复制链接属性原值，源码通过 Markdown 语法树读取目标。相对路径和片段保留，内置脚注跳转继续使用原操作。常规渲染的正文上边缘使用公共正文间距，只读工具栏不另加底部留白。

渲染编辑的行内代码输入规则按光标前的完整匹配删除定界反引号。在已有反引号对后输入空格时，空格作为普通文本保留。普通段落和表格单元格共用规则。

`document-rail.ts` 将正文外框的左右边界投影到工具栏下和状态栏上的分隔线。标题下的线默认也沿用正文边界。有固定阅读面板时，标题下方的一条线横跨正文与面板，两端使用相同的工作区内边距。固定面板的竖分隔线从标题下沿开始。块号和行号在正文外框内。源码以 CodeMirror 滚动区的实际 `clientWidth` 为准，并排预览时工具栏服务于两个窗格组成的整体。覆盖式滚动条占宽为零，占位式滚动条只由滚动区扣一次。File Workbench 窗口操作仍使用标题整行，状态栏分隔线固定在可见区域顶部。

文件名仅是定位线索；上述文件位于 `src/` 和 `native/file-workbench/src-tauri/src/`，使用仓库搜索确定当前路径。针对性验证与未解决问题见[开发交接](../development/session-handoff.md)。


## Markdown 链接

磁盘文档的目标由来源文件父目录、授权根和可选锚点确定。Nine Rings 数据库文档继续使用 `nr-note://` 稳定身份，并为导入目录中已有的相对链接提供定位。GitHub 样式标题标识、重复标题后缀及显式锚点由源码模型和渲染模型共同使用，界面显示的截断标题不用于定位。

File Workbench 的独立窗口以现有文件标签作为跳转目标，原生服务根据来源会话验证授权根和目标文件。后退／前进与正文撤销各自保存。改名／移动后的引用更新以确认的路径变化生成预览，修订校验和草稿保护沿用正常文件写入。

同一授权根内的引用更新也处理 Markdown 图片。扫描使用共享 Markdown 语法树识别图源和共用引用定义，只修改验证过的地址范围。相对图源采用与 Workbench 渲染相同的路径解析规则。
