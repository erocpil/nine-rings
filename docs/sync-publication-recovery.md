# 候选发布记录与中断恢复

2026-10-15。`publication-store.ts` / `publication-recovery.ts` 是新协议发布基础；**生产能力为 0，当前旧格式 Push 不创建这些记录，也不自动改用新发布协议**。

## 冻结计划与本机记录

独立设备数据库 `nine-rings-sync-state-v1` 保存 attempts、summaries、baselines，不改变主文档数据库 schema，不进入普通备份，也不保存 Token。summaries 只包含空间、阶段、时间和提交标识，启动不为检查状态而读取整份冻结正文。

准备计划前检查封装、实体、能力、固定远端证据、与实体摘要绑定的本机修订、备份确认和参与端确认；首版只允许**空备份命名空间**的首次候选。非空旧快照、已经开启空间和未完成计划都拒绝另建计划。当前产品没有分配能力或提供准备/启用入口；测试中的能力 1 是隔离的假设认证环境，不是发布版本承诺。

记录包含冻结快照、原始 SHA-256、控制文件、expectedParent、目标 snapshotId、本机存储代次，以及实际接受实体的哈希和必要元数据。当前只记录 present，不推断 absent 或删除；尚未实现非空远端的 include/ignore/conflict/pending-delete 计划。冻结记录（含接受数据）上限 128 MiB，持久化失败时不得开始写远端。

## 阶段与发布边界

| 阶段 | 含义 |
| --- | --- |
| PREPARED | 冻结意图已提交本机；外部对象准备器尚未获准更新引用 |
| OBJECTS_READY | 已核验候选 Git commit：单父项为 expectedParent，且仅修改快照、latest 和控制三个计划文件；字节必须与冻结记录相同 |
| PUBLISHING | 在唯一一次 PATCH 前以事务持久化；并发窗口通过记录 ID/阶段/commit 比较，只有一个能进入 |
| UNKNOWN | 响应丢失、超时或无法确认；禁止重放原 PATCH |
| REJECTED | 明确 HTTP 拒绝，接受基线不推进；需新的显式预检和计划，不自动 Pull |
| CONFIRMING | 已确认引用更新，等待本机接受记录提交 |
| COMPLETE | 冻结接受数据与完成标志在同一个本机事务中提交 |

恢复/发布确认复用文档恢复锁并检查存储代次。普通新编辑不被写回或覆盖；接受基线来自冻结计划，新编辑仍是后续待处理差异。若文档库已被恢复，旧发布不能被确认成新库的基线。本机确认失败保留 CONFIRMING，不把已发布数据回滚。

对象创建器仍需后续接入；对象可能已创建却尚未发布，记录库不自动删除它们。`force:false` 仅为快进保护，不是严格 expected-HEAD CAS，也不能防止外部强推。

## 启动检测与只读恢复

启动只检查轻量本机摘要，有未完成记录时提示进入备份设置；不会自动使用凭据连接远端。设置中的「只读核实发布」是显式 GET-only 检查，凭据由用户当前配置提供，连接必须与记录一致。

先固定目标分支头 H；H 等于候选 commit，或 `GET /compare/<commit>...<H>` 返回 ahead 且 merge_base 为候选 commit，才能证明当前 H 包含本次发布。随后再次核验候选提交中的三个文件和父提交，再确认冻结基线。采用 [GitHub Compare API](https://docs.github.com/en/rest/commits/commits#compare-two-commits) 的明确方向。

403/404/超时、分叉、落后、错误合并基点及文件不一致均保留 UNKNOWN；不能据此认定“从未发布”。H 包含后续提交时，只接受本次冻结值，不将后续远端编辑也标记为已接受。已观察到异常的记录不提供“忽略后重发”快捷入口。

当前接受账本与主文档存储没有跨库事务承诺；已实现的是“发布确认账本与 COMPLETE”原子提交，尚非完整 Pull 应用日志。正式上线仍需非空远端规划、对象上传接入、Pull 接受状态及显式切换 UI。
