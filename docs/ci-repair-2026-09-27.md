# CI 修复记录（2026-09-27）

## 已修复：前端依赖审计

`1993c87` 的 [Frontend Tests](https://github.com/erocpil/nine-rings/actions/runs/36328348725/job/108645378826) 在 Dependency audit 失败。本地执行相同审计发现，顶层 lodash-es 已是 4.18.1，但 Chevrotain 11.0.3 的三个包固定使用 4.17.21，仍触发高危代码注入漏洞。

通过 package.json 的 overrides 将 lodash-es 统一为 4.18.1，锁文件删除三个旧副本。保持 `npm audit --audit-level=high` 门槛不变，未进行 TipTap 等大版本升级。修复后审计通过，仍有 37 项中危依赖报告，需另行处理。

本地验证：完整 npm test、生产 build、bundle-size、format:check 通过；Mermaid 代码块和 Tauri CSP Chromium 回归 8/8 通过。日志保存于 `.local-tools/ci-*.log`，审计原始报告为 `.local-tools/ci-audit.json`。

## Windows Tauri 依赖错配修复（第 64 批）

用户补充日志确认 `tauri::generate_context!()` 生成对 `tauri::image::default_window_icon_from_app_icon_resource` 的调用，但当前 `tauri 2.11.6` 不提供该符号。锁文件混用了 `tauri-codegen 2.7.0` 与旧主库；2.7.0 的 [官方发布记录](https://v2.tauri.app/release/tauri-codegen/v2.7.0/) 明确引入了 Windows 图标资源生成方式。

在 Cargo.toml 将 tauri-build / tauri-codegen 固定为 2.6.3，并通过 Cargo 重新解析锁文件。显式 codegen 约束防止后续依赖更新再次引入不兼容生成器。保留 tauri 2.11.6 与前端 JS 的版本对应关系，不升级整套框架。2.6.3 的 Windows 分支仍读取 ico 并生成已有 Image 构造接口。STATIC_VCRUNTIME 仅是新 tauri-build 的弃用警告，不是本次 E0425 的原因；2.6.3 仍支持现有 CLI 传入的环境变量。

隔离 macOS 工具链 `cargo check --locked` 通过，`cargo test --locked` 通过，测试结果记录在 `.local-tools/e2e/repair-batch64/`。Windows NSIS 打包仍需推送后的原生 CI 验证，不能由 macOS 检查代替。

[Windows 原失败](https://github.com/erocpil/nine-rings/actions/runs/36327980566/job/108644326348)。`1993c87` 的 [跨平台 E2E 矩阵](https://github.com/erocpil/nine-rings/actions/runs/36328348783) 已成功，因此 `9063cef` 的 macOS Chromium 单次失败不再作为当前矩阵失败结论。
