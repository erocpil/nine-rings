# Nine Rings 文档系统设计

> 当前契约，2026-10-10。历史方案已移至[初期设计归档](archive/document-system-design-initial.md)，不作为待办。插件配套工作见[产品完善与插件推进待办](plugin-readiness-todo.md)。

## 1. 目标与不变量

所有记录使用共同的 `Note` 模型。UUID 是文档身份；标题和 `storagePath` 可以改变，不用于取代 ID。路径是应用内逻辑路径，不是操作系统文件路径。

- `projects`、`areas`、`references`、`ideas`、`archives` 五个顶层路径始终显示。
- 普通子路径由文档推导；受保护空路径由独立保护记录保留。保护记录表达保护边界，文档路径表达归属，两者各有职责。
- 文档的全部祖先路径都有树节点，目录计数包含后代；更改路径不能改变文档 ID 或正文引用目标。
- 删除路径不能移除五个顶层入口；涉及文档的删除、恢复、移动、加密遵循各自事务及保护规则。
- 数据库与备份使用扩展 Delta；活动渲染编辑器使用 ProseMirror，源码编辑器使用 CodeMirror。投影、保存和导航的权威边界见[编辑权威协议](editor-authority-and-workspace.md)。

## 2. 信息组织

路径、类型、概念和标签是可组合的查询条件，互不从属。文档引用表达文档之间的关系，不是目录的子分类。

| 信息 | 当前含义 | 边界 |
| --- | --- | --- |
| 路径 | 唯一的存放位置及生命周期组织 | 五个常驻顶层入口允许一般子路径；目录暂不实体化 |
| `docType` | 可选的 tutorial/how-to/reference/explanation | 当前固定枚举；不把其它类型扩展作为插件首期前提 |
| `concepts` | 跨路径的主题概念 | 目前按原值匹配；规范搜索键与合并操作待独立设计 |
| `tags` | 用户自由标签 | 不再属于旧独立随笔模型；不静默与概念合并 |
| `linkedDocIds` | 属性面板设置的出向文档关联 | 反向关联由查询派生，不要求两端重复写入 |
| 正文引用 | 文档、标题、块或选区的导航链接 | 使用稳定 ID 与锚点；与显式关联分开维护 |
| 插件 `properties` | 拟新增的结构化自定义属性 | 尚未提供；必须先验证类型、存储、备份与卸载保留 |

`[[` 补全、原文件名辅助定位和引用锚点已实现，见[引用锚点](document-reference-anchors.md)。概念聚合、文档和路径移动/改名不再是历史待做项。

## 3. 路径契约

`normalizeStoragePath` 当前整理首尾/片段空白，将反斜线转换为 `/`，移除空片段，拒绝 `.`、`..`、控制字符，并限制最多 32 层、每段 128 个 UTF-16 单元、总长 1024 个 UTF-16 单元。保留 `C++`、`C#`、Unicode 名称和大小写，不采用 ASCII/汉字白名单。

路径匹配按完整片段：`projects/a` 可以包含 `projects/a/b`，不应包含 `projects/ab`。创建、移动及属性更新应复用服务层路径规则，不能只校验界面输入。现有各写入入口的一致性正在按待办验收。

当前没有 NFC 路径迁移。后续引入时须先检测碰撞并提供报告，不能静默合并旧路径或改变保护边界。逻辑路径和导出文件名的约束不同，不能直接套用操作系统文件名禁用字符。

移动的事务和交互见[文档树移动设计](document-tree-move-design.md)；该专题含历史实施阶段，具体状态以当前功能及测试为准。

## 4. 存储、查询与派生数据

`schema/note.yaml` 是共享数据契约。Web 使用 IndexedDB，桌面使用 SQLite；现有字段及备份兼容不能因插件增加而丢失。

IndexedDB 可以直接存数组，也可以使用 `multiEntry` 索引。当前 tags/concepts 等字段仍有 JSON 字符串存储路径，这是现有序列化实现，不是 IndexedDB 限制。改变存储形式须升级数据库、重建索引并验证旧数据。

搜索已有 Worker 索引、排序、Perl 兼容正则和摘要接口，见[搜索契约](editor-replace.md)。SQLite 存在 FTS5 实现，但不能由此推断每个查询入口都使用 FTS。

Web 的文档树和部分纯元数据查询仍读取完整记录；桌面树通过轻量列和独立格式标记查询避免跨 IPC 传送全部正文。后续优化应减少正文读取并按数据变更失效缓存，而不是仅缓存旧结果。L0 查询仍需独立的条件解释器、稳定排序、取消和预算。

`search_text` 是派生数据。文本提取规则变更应提供重建与一致性验证，不把它作为正文权威来源。

## 5. 随记、日期与待办

旧独立随笔/待办功能已于 2026-09-27 移除；当时未向用户开放，未设计用户数据迁移。新随记是 `ideas/notes` 下的普通文档，分组是子路径，待办是正文任务列表。详见[决策记录](decisions/001-unified-document-notes.md)与[随记交互](workspace-layout.md#随记notes)。

`date` 仍是现有模型的本地日期字段，部分查询和排序依赖它；`created_at`/`updated_at` 是时间戳，不能仅因旧日记界面移除就直接删除 date。若将来废弃，需要单独评估兼容与索引。

## 6. 导入、保护与平台边界

Markdown 导入保留原始源码与原文件名，走既有解析、安全链接和受限 HTML 管线。开发队列使用鉴权的 Vite 端点、项目内受限权限文件、容量限制及成功 ACK；静态 serve.py 不提供写入接口。详见[审计修复记录](audit-remediation-2026-09-06.md)。导入使用 upsert，但来源身份、同名冲突策略、报告与部分成功仍需明确，不能宣称所有导入是整批原子操作。

正常数据接口经过 protectedAdapter；一般读取保留密文，解锁不代表普通列表接口获得明文。插件不能取得裸 adapter、SQL 或完整内部 api。加密保护、用户只读和逐插件权限是不同检查，SDK 必须同时处理，见[插件设计](plugin-system-design.md)。

Flutter 插件实现暂缓。改变共享文档格式时仍须明确旧客户端行为：保留未知数据或拒绝不安全写入，不静默丢弃；不为本轮 Web/Tauri 工作安装 Flutter 工具链。

## 7. 相关决策与待办

保留统一模型、虚拟路径、正交查询和稳定引用；暂缓目录实体化、自动合并标签/概念、开放任意文档类型和第三方动态节点。
