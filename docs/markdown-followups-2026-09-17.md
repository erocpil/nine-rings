# Markdown 后续六项：本轮范围与验收

## 1. 双向转换

新增多轮往返测试：嵌套混合列表、引用、表格转义、链接/强调、任务、多反引号行内代码、嵌套围栏及空代码块。修复任意长度代码分隔符和空代码块丢失；导出时选择比正文更长的围栏。补齐删除线解析，并保护普通富文本的字面量块前缀（如 `#`、`>`、`-`、`1.`），避免往返后变成结构。这不是完整 CommonMark/GFM 实现，HTML、脚注等仍不承诺支持。

## 2. 任务交互

任务标记使用 ProseMirror widget 按钮，不改变存储节点类型或插入可编辑的复选框文字。点击、触控、键盘空格修改当前条目的 taskChecked；支持撤销/重做，完整只读、局部只读和块选择状态不允许修改。剪贴板/源码仍以文档模型为准，不导出装饰按钮。

## 3. 历史转义修复

源码视图提供当前文档扫描。只提议列表起始处的转义任务标记，跳过围栏代码；所有候选默认不选中。用户逐项查看原文/修复结果并确认。冲刷保存成功、版本快照成功后才应用；失败保留正文。可从版本历史恢复。没有全库自动迁移，也不承诺检测所有污染形式。

## 4. 性能

源码序列化复用数据 Worker；Worker 不可用时使用兼容路径。异步结果返回时检查文档是否又被编辑，拒绝过期转换。任务装饰按 document 身份缓存，纯选区移动不重遍历全文。没有扩大编辑器常驻缓存或全面虚拟化可编辑正文。

新增手机宽度基准（Linux Chromium、Vite 开发模式、合成 IndexedDB 数据、每种规模三轮、独立运行）：

| 块数 | 打开并布局 ms | 切到源码 ms | 回到渲染 ms |
| --- | --- | --- | --- |
| 300 | 668 / 944 / 1106 | 176 / 86 / 103 | 723 / 1097 / 1088 |
| 1500 | 5914 / 4332 / 4540 | 272 / 242 / 241 | 4786 / 4530 / 4628 |

复现：`NR_EDITOR_BENCHMARK=1 NR_EDITOR_MOBILE=1 npx playwright test e2e/editor-opening-benchmark.spec.ts --workers=1`。

没有同环境修改前对照，不能据此声明总体加速。长文档挂载与排版仍有秒级长任务；本轮是移出一项主线程计算并建立切换基线，不代表大文档问题已经全部解决。字号阅读位置及块编辑另用功能回归验证，未给出真机性能数字。

## 5. 模块与类型

按边界增量提取 `editor-toolbar-commands`（选区捕获/格式命令）、`useNoteSessionBoundary`（切换保存与 checkpoint 顺序）、`useSettingsTextImport`（状态、批处理及文件读取）。保留当前编辑器与会话 ref，不创建第二个编辑器；明确命令参数及回调类型。MarkdownDocumentView 移除源码编辑的非空断言并统一编辑入口。Markdown 样式从全局末尾提取为最后一个有序导入，保持层叠顺序。

这是一批增量拆分，不代表整个 App、编辑器或设置页已全部模块化；导航协调、完整编辑器生命周期、折叠和滚动锚点仍需后续独立批次。

## 6. 质量与平台验收

校正设置页字段数、移动端右下边缘手势入口和已撤下的默认代码换行 UI 测试；保留已保存配置对新代码块的行为测试。补上 Alt+G 录制保留键提示，正文快捷键不再截获设置页输入；修正已有 folder-rename 单测格式，恢复完整格式门禁。

真机验收仍待执行：

- iPhone 安装版：触控勾选、撤销、键盘弹出、后台恢复、大文档打开和字体锚点。
- macOS Tauri：任务/源码往返、快照恢复、GitHub Pull、系统快捷键。
- Windows WebView2：以上编辑流程以及剪贴板、文件对话框、重启持久化。

当前 Linux 环境没有这些设备，浏览器模拟和构建不能作为真机已验收的证明。

### 自动化结果和保留问题

- `npm run check` 通过：类型、lint、格式、原有脚本测试、229 项 Vitest、IPC 契约；最终小范围修订另跑 Markdown 的 16 项单测及类型/lint。
- 最终构建和 bundle-size 门禁通过。
- Chromium / WebKit 各 44 项针对性回归通过：Markdown/链接、任务、转义修复、设置导航/热键、编辑器边界、字体锚点、目录导入及手机块选择。
- Worker 旧结果竞态另在两个浏览器各 1 项通过，合计 90 项针对性 E2E；两项手机宽度性能基准单列。
- 额外扩展到旧 `block-workspace.spec.ts` 时仍有失败。抽取“编辑后仍寻找 ProseMirror”“只读先选块再选全文（两个快捷键）”“工具栏右边距”4 项，在修改前 `d8b8679` 隔离工作树同样复现；其余旧块工作区失败未逐项定性。本轮没有放宽这些断言，也没有宣称全项目 E2E 全绿，留作后续独立整理。
- 测试夹具通过动态导入 store 注入数据；源码 HMR 后可能得到与界面不同的模块实例。因此最终回归从新启动的 Vite 运行，不用热更新中的夹具失败判断业务回归。
