# 文档写入、派生数据与迁移边界

> 2026-10-11。对应 A2～A7；现有管理接口和首次可信内置 SDK 分开，第三方安装仍需 R7。

## 正常写入入口

| 入口 | 协调与保护 | 身份、正文及只读含义 |
| --- | --- | --- |
| 编辑保存、普通属性 | 文档修订/保存队列 → protectedAdapter → 原始适配器；写入前后检查恢复代次 | 用户只读禁止 UI 编辑与插件写入；已接受的保存批次不因后来切换只读而丢失。不能把界面只读标记当成存储权限系统 |
| 创建、文本导入、明确 upsert | 路径规范化、Unicode 碰撞及保护锁；继承路径密码，已有独立密码不被明文替换 | 新建 UUID；设置中的重复导入不覆盖已有文档。管理 upsert 是显式替换入口，不对插件开放 |
| 移动、批量移动、目录改名 | 保护快照与原子提交；检查目的地及全部子路径，移动跨保护边界时鉴权/加密 | 保留 UUID 与引用；改名不改变保护身份，离开保护目录不会自动解密 |
| 密码管理、历史恢复 | 快照事务/原密码验证；恢复先保存当前历史，修复正文与历史的保护一致性 | 管理操作可作用于只读文档，不能据此授予 SDK 编辑权 |
| JSON 备份恢复、GitHub Pull | 恢复屏障、跨窗口锁、代次检查与 protectedAdapter；导入前等待已接受写入，校验整包 | 备份按 UUID 恢复；不得降低现有密码保护。共享旧数据中的碰撞保留原值并报告，不能自动合并 |
| 插件意图 | 宿主绑定授权、目标/视图/选区代次、取消、恢复屏障、只读和保护检查；保存修订等待实际写入 | 插件不取得 adapter、SQL 或内部 api。管理操作不借插件路径绕过权限 |

原始 IDB/SQLite 适配器是宿主内部基础设施，不是插件 API。直接服务回归覆盖路径属性更新、继承保护、加密历史/备份、恢复代次及 SDK 绕过界面的只读/保护拒绝；见对应单元与 E2E。未把全部底层写入一概改为只读拒绝，否则会丢掉切换只读前已接受的保存。

## 路径碰撞与迁移

路径规范化整理分隔符/空白并验证深度和长度，保留大小写与 Unicode 原值。NFC 只用于比较，`Café` 与 `CAFÉ` 仍是不同路径；`café` 与 `café` 报告为碰撞。检查每一级父路径，所以不同子路径也不能掩盖父目录碰撞。

现有数据使用 `api.docs.pathNormalizationReport()` 获取 `{canonicalPath, paths}`，它是宿主内部报告接口，尚未提供一键迁移页面。备份恢复不为了解决碰撞擅自丢弃旧文档。处理顺序：先备份、列出所有等价路径及保护范围；明确选择保留的拼写或新名称；通过现有目录移动服务逐项执行；核对 UUID、树计数、书签/引用和保护快照；最后重新检查报告。不得自动合并目录、解密、改变引用身份或把逻辑路径约束替换成平台文件名规则。并发改变源数据会让保护提交拒绝，必须重新审阅后操作。

## 标签、概念、自定义属性

标签是自由分类，概念是跨路径的主题聚合，自定义属性是尚未落地的结构化类型字段。三者不互相推导，也不自动去重/合并。

概念搜索键为 `trim → NFC → lowercase`，不改变持久化显示名；普通自由文本搜索沿用其现有匹配规则。宿主 `api.docs.mergeConcepts(sources, target)` 是显式管理操作，按指定原值替换并去除完全相同的结果，不自动修改其它规范等价原值。它通过保护快照与存储协调事务更新更新时间并刷新派生查询；尚未新增概念合并设置页。C1 自定义属性需另外验证共享格式、备份和旧客户端保留。

## 文本来源与失败报告

设置中的文本导入以目标路径 + 原文件名寻找已有来源，旧数据没有文件名时才按标题回退。相同内容跳过；不同内容或多个候选作为冲突逐文件报告，保留本机编辑、UUID 与历史。此规则是安全的重复执行，不是远端同步或自动冲突合并。后续若提供覆盖，应先展示具体目标和差异，再走明确的正文替换/历史入口。

目录导入逐文件提交，因此成功与失败可以并存。设置页保留完整失败清单、重复数量、跳过不支持类型数量及中断状态；已成功项再次执行不生成副本。普通 JSON 恢复仍按备份 ID 合并，不能用文件名代替其身份。

## 摘要与搜索失效

摘要不包含正文，是列表投影；不能作为 `Note` 传给编辑器。IDB v6 的索引键只含更新时间和序列化摘要；正常写入、导入、历史恢复与保护事务原子重算。旧 bundle 丢掉投影时补建，保留旧投影但改变更新时间时仅修复该 owner。投影从备份输出剔除，恢复后重新构建，不备份派生缓存。

SQLite 摘要通过一个查询快照返回，避免元数据和大小分别读取时发生撕裂。来源信息使用 SQLite JSON 提取，UTF-8 大小使用内容 BLOB 长度。它减少 IPC/前端内存与 JSON 解析，不能声称数据库完全不读取正文。

搜索提取规则版本 1：TS 是统一提取器，包含当前结构化正文并排除密文。Worker 按正文重建；IDB 升级及写入重提取；原生全文查询前检查设备本地版本，旧版本在单一事务更新派生文本及版本标记，通过原正文完全比对防止覆盖并发修改。任意失败都不标记完成，不改正文、历史或更新时间。后续规则变化要同步提升 TS/Rust 常量与 IDB 升级版本；版本表不进入备份。导入重新计算搜索字段，不能接受备份中的过时明文索引。

## 验证边界

浏览器使用隔离 context/IDB，真实文档只从本机 fixture 读取。生产摘要对照为相同记录分别读取完整 owner 和索引键，统计读取耗时与载荷，不据此承诺任何设备的帧率。只读 A/B 交替三次，同时记录实际是否启用局部模式，不能把回退到完整渲染误报为局部成功。Windows/Linux 的原生退出、进程/文件锁与真实触摸输入仍需相应真机；Rust 生命周期测试、浏览器 IPC 模拟和 CI 构建分别提供独立证据，不能相互替代。
